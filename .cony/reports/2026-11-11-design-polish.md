# 디자인 전반 다듬기: 수치·제목 구분

## 1. 결과

화면 전체의 글자 크기를 7단계로 정리했습니다. 라벨은 작고 흐리게, 수치는 크고 굵게 보여서 둘이 붙어 보이지 않습니다. 이미 확정된 디자인(먹색 버튼, 코발트 사용처, 알약 탭, 로고)과 색 값은 그대로입니다.

## 3. 팀이 내린 결정

- [ADR-040](../decisions/040-label-value-pattern.md) 라벨·값 구분을 토큰과 규칙 주석으로만 공유(공통 컴포넌트·CSS Module 없음). 되돌리기 쉬움.
- 리드 판정(작은 결정): 크게 단계의 `--fs-small`은 13 유지(스펙 표의 12는 오타로 봄), "더 작게"에도 3px 규칙 적용.
- 원칙: 라벨→값, 제목→수치는 3px 이상 벌린다(세 글자 크기 단계 모두).

## 4. 수용 기준 결과

  - 기존 테스트 기대값 변경 0
- 흐름 규칙 건너뜀: 없음.
- 지표(15:06부터): 에이전트 실행 3(pm·fe·qa, 이어서 부름 포함), 리드 토큰 2.5M / 합계 23.7M(약 11%). 시간은 구현 26분, 테스트 15분, 조율 1분. qa 되돌림 1, hook 차단 0.

## 5. 화면 확인

- qa가 본 것: 390px 라이트 기본, 360px 라이트·다크 × 기본·크게, 360px 더 작게. 가로 스크롤 0, 라벨·값 겹침 0, 가장 긴 금액(12억 9,999만원, 14억 1,699만원)도 한 줄. 표 보기와 인쇄 PDF에서 넘침 없음.
- 못 본 것: 공유·초대 화면(서버 토큰 필요), 실거래가 시트 목록(API 필요), 메모 시트 라벨. 이 세 곳은 CSS만 확인했습니다. 실기기도 보지 못했습니다.

## 6. 사용자 확인 필요와 남은 이슈

**화면 취향(제품 기본값, 제안값으로 적용됨)**

- U1: 글자 크기 제목 22, 답 26, 수치 19, 값 16, 라벨 11
- U2: 홈 카드 제목을 16으로 낮춤
- U3: 예산 묶음 합계 13 · 700. **줄 금액(16)보다 작게 보입니다.** 키울지 결정이 필요합니다.
- U4·U5: 칸 라벨·답 라벨을 11 · 600 흐린 글자로

**알려진 문제**

- 매물 카드 이름이 "84 / ㎡"처럼 두 줄로 나뉩니다. 360px, 글자 크기 크게, "초과" 배지가 함께 있을 때만 생깁니다. 원인은 이름 굵기를 700으로 올린 것입니다. 다음 단계 후보에 올렸습니다.
