# 인테리어 묶음(카테고리) 접기·펴기

## 결과

인테리어 목록의 묶음마다 제목 줄 오른쪽 끝 화살표(접힘 ∨ / 펼침 ∧)로 접고 펼 수 있다. 상태는 이 기기의 localStorage에 계획별로 기억한다.

요청 원문: "인테리어탭에 카테고리별로 비용목록들 있잖아. 카테고리 단위로 접었다 폈다할 수 있게 해줄래? 접힘/펼침상태는 로컬스토리지에 저장해주면 좋을듯"

## 태스크별 결과

1. **접기·펼치기와 기억** — 키 `loan-calculator/interior-collapsed-groups` 하나에 `{계획 id: 접힌 구분[]}`. 읽기·쓰기 실패·손상·개인 모드면 모두 펼침. 서버·계획 저장 형식 변경 없음, API 호출 0건.
2. **자동 펼침 + 조작 변경** — 접힌 묶음에 새 줄·고친 줄을 저장하면 그 묶음을 펼침(실패하면 접힌 채). 사용자 지시로 접기 조작을 "제목 칸 전체 탭"에서 "오른쪽 끝 화살표 버튼 하나"로 바꿈. 제목은 끌기 손잡이만.
3. **검증** — AC 8개 통과.

## 팀이 내린 결정

- [ADR-039](../decisions/039-group-collapse-storage.md) localStorage 키 하나에 `{계획 id: 접힌 구분[]}`. 묶음 식별자는 구분 이름(상대가 이름을 바꾸면 그 묶음은 펼침으로 돌아감).

## 수용 기준 결과

- AC-1~AC-8 통과. [위험] AC-7(계획 원문 불변·API 0건)은 로그인·로그아웃 모두 확인, 버그 되살리기로 테스트가 잡는지 확인.
- 흐름 규칙 건너뜀: 없음.

## 화면 확인

- qa 360px(터치 에뮬레이션): 화살표 48×44px 오른쪽 끝, 접힌 줄에 이름·n줄·합계·화살표 한 줄, 긴 이름은 감기고 화살표 제자리, 화살표 꾹 눌러 끌어도 묶음 안 들림, 새로고침·목록↔표 전환 뒤 유지.
- 사람 확인 필요: 실기기 꾹 눌러 끌기, VoiceOver 낭독, 사파리 개인 모드.

## 사용자 확인

- U3 조작 위치는 사용자가 정함(오른쪽 화살표만). U1(처음 모두 펼침)·U2(접힌 줄에 n줄·합계)·U5(자동 펼침)·U6(접히면 [+ 줄 추가] 숨김)·U7(목록 보기·이 기기만)은 사용자가 "이대로 둘게"로 확정.
- U4는 사용자가 뒤집음: 목록 위 오른쪽 [모두 접기]/[모두 펴기] 한 버튼(묶음 2개 이상, 모두 접혀 있으면 [모두 펴기]). 후속 PR에서 추가(AC-9).

## 규칙 제안

- 사용자가 "왜 이렇게 오래걸려?"라고 함. 서버·저장 형식을 건드리지 않는 작은 화면 기능은 스펙 검토 라운드를 건너뛰고 태스크 하나 + qa 한 번으로 가는 규칙을 제안.
- 묶음 조작 위치(U3)를 팀이 "제목 전체 탭"으로 정했다가 사용자가 뒤집음. 화면 조작 방식은 구현 전에 사용자에게 먼저 보이는 편이 낫다.
