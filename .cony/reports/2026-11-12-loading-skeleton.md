# 데이터 조회 로딩 스켈레톤

## 결과

홈·매물·예산 탭이 응답 도착 순서대로 하나씩 튀어나오던 것을, 같은 자리를 지키는 스켈레톤 뒤에서 화면마다 한 번에 드러나게 바꿨다. 서버 변경 없음.

## 태스크별 결과

1. 공통 `Skeleton` 부품 + 홈 한 번에 드러내기 (`7b665c0`): `/api/me`·`/api/listings`·`/api/interior-plans`를 모두 받은 뒤 세 카드와 계정 자리를 함께 그린다. 대출 계산 카드는 기기 값이라 처음부터 보인다. 판정은 순수 함수 `isHubRevealed`.
2. 매물·예산 탭 적용, 실거래가 시트 막대를 공통 부품으로 교체 (`899a3f2`), 연결 계획 스켈레톤에 "연결된 매물" 줄 자리 추가 (`47448df`).
3. 검증 (qa): 태스크 1 통과, 태스크 2는 AC-3 실패 1회 → 수정 후 재검증 통과.

## 팀이 내린 결정

- [ADR-041](../decisions/041-loading-skeleton.md) 직접 만든 스켈레톤(라이브러리는 gradient라 ui-refresh 금지와 충돌), 기존 상태 유니온에서 "모두 준비됨" 파생. ADR-031 조건 2(홈 섹션 독립 표시)를 로딩에 한해 개정 — **검토 권장**.
- 사용자가 속도를 지적해 스펙 검토 라운드는 생략.

## 수용 기준 결과

- AC-1~8 통과. AC-8: 의도적으로 바뀐 기대값은 홈 행 5 대신 `isHubRevealed`로 분리, 연결 계획 테스트 2개(AC-7) — 삭제·약화 없음.
- 태스크 3(검증)은 태스크 1·2 qa 기록으로 대신했다.
- 지표(18:00 이후): 에이전트 실행 3, 리드 토큰 2.6M/20.4M(13%), 스펙 9분·구현 18분·테스트 11분·조율 1분, qa 되돌림 1, hook 차단 0.

## 화면 확인

- qa 확인: 360px에서 응답이 따로 늦어도 홈 세 카드·계정 자리 위치 변화 0px. 100ms 응답이면 회색 안 보임, 1.5초면 약 300ms 뒤 보였다가 한 번에 교체. 다크 모드 구분, 동작 줄이기에서 맥박 정지. `/api/listings` 500이면 정상 드러남.
- 못 본 것: 실기기 스크린리더("불러오는 중" 한 번만 읽히는지), 라이트 모드 실기기에서 막대 대비, 계정 이전 중 화면, 실제 서버.

## 사용자 확인 필요

- U1 화면마다 한 번에 드러남(대출 계산 카드는 처음부터)
- U2 반짝임 대신 은은한 밝기 맥박, 동작 줄이기에서 멈춤
- U3 300ms 안에 끝나면 회색을 안 보임(자리는 처음부터)

## 남은 이슈

- 매물에 연결된 계획은 계획 목록이 오기 전엔 연결 여부를 몰라 약 20px 한 번 바뀔 수 있다(순서에 따라 스켈레톤 중간 또는 드러날 때). 다음 단계 후보 "마지막 모양 기억"으로 없앤다.
- `/api/listings`가 아예 응답하지 않으면 연결 계획 화면이 스켈레톤에 머문다(다음 단계 후보 "느린 한 요청만 먼저 포기").

## 규칙 제안

- 이번처럼 화면 하나 범위의 요청은 스펙 검토 라운드를 기본 생략하는 기준(서버 변경 없음 + 결정 1개 이하)을 팀 스킬에 두는 것을 제안.
