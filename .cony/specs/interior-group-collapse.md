# 우리 집 — 구분 묶음 접기·펼치기(이 기기에 기억)

> 작성 2026-11-07 · 브랜치 `cony/interior-group-collapse` · 상태: D1 결정됨(A, [ADR-039](../decisions/039-group-collapse-storage.md)), fe·qa 검토 조건 반영, 제품 기본값 U1~U7은 사용자 확인 전(답이 오기 전에는 제안 기본값으로 진행)
> 관련: ADR-026(꾹 누르기 250ms·스페이스로 들기, 엔터는 원래 동작) · ADR-036(줄 순서 `lineOrder`, 묶음 순서 = 가장 이른 줄 자리) · ADR-039(접힘 저장 키) · `.cony/log.md` 718행(PR #47 `9be6f81`, 묶음 제목 = 묶음 끌기 손잡이, 아이콘 없음) · 774행·ADR-038 U6(묶음 제목 합계 = 예산 반영 확정 줄만) · 저장 목록 간단히 보기 `CompactListingRow.tsx`(한 버튼이 짧게 누르기 = 펼치기, 꾹 누르기·스페이스 = 끌기) · 스펙 `interior-vendor-tbd-line-order.md`·`interior-budget-exclude.md`(형식)
> 검토: [fe](../reviews/20261107-1615-fe-spec-interior-group-collapse.md) · [qa](../reviews/20261107-1615-qa-spec-interior-group-collapse.md) (둘 다 조건부 찬성, 조건은 아래에 반영)

## 목표

인테리어 목록에서 구분(공정) 묶음을 통째로 접어 두면, 지금 보고 싶은 공정만 펼쳐서 긴 목록을 덜 스크롤한다. 접은 상태는 이 기기에 기억해 다음에 열어도 그대로다.

요청 원문: "인테리어탭에 카테고리별로 비용목록들 있잖아. 카테고리 단위로 접었다 폈다할 수 있게 해줄래? 접힘/펼침상태는 로컬스토리지에 저장해주면 좋을듯"

## 지금 코드에서 확인한 것

- "카테고리" = 목록 보기의 **구분 묶음**이다. `buildInteriorPlanRows`가 `item.trade.trim()`으로 줄을 묶어 `InteriorPlanRowGroup { trade, rows }`를 만든다. **묶음은 저장된 실체가 없고 구분 글자 자체가 식별자**다(끌기 id도 `group/{trade}`, `lineDrag.ts`).
- 그리는 곳: `PlanScreen` → `PlanLines`(DndContext, 묶음 `SortableContext`) → `LineGroup`(`<section aria-label={trade}>` → `GroupHeader` → 묶음별 `SortableContext` 줄 `<ul>` → `[+ {구분}에 줄 추가]`).
- **묶음 제목이 끌기 손잡이다**(PR #47). 묶음이 2개 이상이면(`canMoveGroup`) 제목이 `<button class="groupHandle">`이고 dnd-kit 속성(`aria-roledescription="순서를 바꿀 수 있는 묶음"`, `aria-describedby`)이 붙는다. 짧게 누르면 지금은 **아무 일도 없다**. 묶음이 1개면 제목은 그냥 글자다.
- 센서(`useLongPressSensors`): 마우스·터치는 250ms·5px 꾹 누르기, 키보드는 **스페이스로 들고**, 스페이스·엔터로 놓고, Esc로 취소한다. 엔터는 원래 동작으로 남겨 두었다(`KEYBOARD_CODES`).
- dnd-kit 포인터 센서는 끌기가 시작되면 그 뒤의 click을 document 캡처에서 막는다(`core.esm.js` 1504행 "Stop propagation of click events once activation constraints are met"). 그래서 **같은 버튼에 onClick을 달아도 꾹 눌러 끈 뒤에는 click이 오지 않는다.** 이 앱에서 이미 쓰는 조합이다: 줄 여는 버튼(`LineRow`, 짧게 = 시트 열기)과 저장 목록 줄(`CompactListingRow`, 짧게·엔터 = 펼치기, 꾹·스페이스 = 끌기, `aria-expanded`).
- 묶음 제목 합계(`GroupHeader` → `groupConfirmedWonOf`)는 확정 · 예산 반영 · 금액 있는 줄의 합이고, 그런 줄이 없으면 그리지 않는다(ADR-038 U6). 이번에 바꾸지 않는다.
- 묶음을 든 동안 `DragOverlay`는 제목 + 그 묶음의 모든 줄 글자를 그린다(`PlanLines.tsx` 280~291행).
- `PlanLines`는 `key={plan.id}`이고 [목록|표]를 바꾸면 다시 마운트된다. 그래서 접힘 상태는 컴포넌트 state가 아니라 바깥 저장소에 둬야 보기 전환·계획 전환 뒤에도 남는다.
- 작은 브라우저 설정은 이미 같은 모양의 저장소가 있다: `privacyModeStorage.ts`·`textSizeStorage.ts`(`createXxxStore({ storage })`, 메모리 값이 원본, `getItem`·`setItem`을 try/catch, 실패하면 기본값·이 탭에서만 유지). `AppRoutes.createStores`에서 만들고 prop으로 내려 준다. 접근 불가 storage(`getBrowserStorage`의 `INACCESSIBLE_STORAGE`)와 손상 storage를 테스트에서 넣는 길도 있다.
- 계획 id는 로그인 이전(`/import`) 때 그대로 옮겨지고, 함께 쓰는 두 기기도 같은 계획 id를 본다. 그래서 계획 id로 나눈 접힘 상태는 로그인 전후에도 이어지고, 기기마다 따로다.
- **서버·저장 형식 변경 없음이 맞다.** 계획·항목 타입, 검증, API, `loan-calculator/interior-plans` 원문 어느 것도 건드리지 않는다. 새 localStorage 키 하나만 더한다.

## 사용자 시나리오

1. (접기) 목록에서 "도배" 제목을 짧게 누르면 도배 줄들과 [+ 도배에 줄 추가]가 숨고, 제목 줄에는 "도배 · 2줄"과 오른쪽 확정 합계만 남는다. 다시 누르면 펼쳐진다.
2. (기억) 도배·주방을 접어 둔 채 앱을 닫았다 열거나, [표]를 봤다가 [목록]으로 돌아와도 두 묶음은 접혀 있다.
3. (옮기기와 같이) 접힌 "주방" 제목을 꾹 눌러 위로 옮긴다. 옮기는 동안 뜬 묶음은 제목만 보이고, 놓은 뒤에도 접혀 있다.
4. (새 줄) 오른쪽 아래 [+]로 구분 "도배" 줄을 저장하면, 접혀 있던 도배 묶음이 펼쳐져 방금 저장한 줄이 보인다.
5. (함께 쓰기) 내가 접은 묶음은 함께 쓰는 사람 휴대폰에서는 펼쳐진 그대로다. 표·인쇄·CSV·요약·홈 카드는 아무것도 바뀌지 않는다.
6. (시크릿 모드) 사파리 개인 모드처럼 저장소를 못 쓰는 브라우저에서도 접고 펴기는 되고, 새로고침하면 모두 펼쳐져 있다.

## 참고한 사례

- **WAI-ARIA APG Accordion**: 제목(heading) 안에 버튼 하나, 버튼에 `aria-expanded`(펼침 true/접힘 false)와 `aria-controls`(내용 감싸는 요소 id). 여러 패널을 동시에 펼칠 수 있어도 된다. → 마크업을 그대로 따른다(`<h3><button aria-expanded aria-controls>`). APG는 스페이스·엔터 둘 다로 여닫지만, 이 목록은 ADR-026에서 스페이스를 "들기"로 정했으므로 **엔터 = 접기, 스페이스 = 들기**로 둔다(저장 목록 줄과 같은 규칙). region 역할은 남발하지 말라는 권고가 있어 패널에 `role="region"`을 더하지 않는다(이미 `<section aria-label>`이 있다). https://www.w3.org/WAI/ARIA/apg/patterns/accordion
- **노션 토글 제목**: 제목 왼쪽 삼각형(▶/▼)으로 여닫고, 접힌 내용은 그대로 남아 있다. 전체 접기는 따로 없다. → 꺾쇠 하나로 상태를 보이고, "모두 접기"는 두지 않는 쪽(U4).
- **iOS 메모·메일 폴더 목록, 파일 앱 사이드바 섹션**: 섹션 머리를 누르면 접히고, 꺾쇠가 오른쪽(>)/아래(∨)로 돌며, 앱을 다시 열어도 접힌 상태가 기기에 남는다. 처음은 펼침이다. → 처음 = 모두 펼침(U1), 꺾쇠 방향으로 상태 표시(U3), 기기 단위 기억.
- **이 앱 저장 목록 간단히 보기**(`CompactListingRow`): 같은 버튼이 짧게·엔터 = 펼치기, 꾹·스페이스 = 끌기. 꺾쇠 `chevron-down`이 펼치면 돈다(`CompactListingSummary.module.css` `.chevron`/`.chevronOpen`). → 그 조합과 꺾쇠 모양을 그대로 쓴다. 다만 저장 목록은 펼친 줄을 들 수 없게 했는데, 묶음은 **접힌 채로도 들 수 있다**(접힌 묶음이 작아 옮기기가 오히려 쉽다).
- 토스·뱅크샐러드의 카테고리 목록 접기는 공개 도움말·검색으로 확인하지 못했다(지어내지 않음).

  - 목록 보기의 구분 묶음 접기·펼치기(묶음 1개일 때도)

  - 묶음 제목 버튼의 접근성(`aria-expanded`, `aria-controls`), 접힌 묶음 끌기와 뜬 묶음 모양

- 범위 밖:

  - "모두 접기/펴기" 버튼(U4 대안, 다음 단계 후보)
  - 표·인쇄·CSV·요약·홈 카드의 접기(U7)
  - 접기·펴기 애니메이션
  - 다른 탭(같은 기기 다른 브라우저 탭) 사이 실시간 반영(`storage` 이벤트). 다음 마운트 때 읽는다

## 데이터 모델

서버·계획 저장 형식 변경 없음. 새 localStorage 키 하나(D1: A, ADR-039).

- 키: `loan-calculator/interior-collapsed-groups`
- 원문: JSON 객체 `{ [planId: string]: string[] }`. 값 = **접힌** 묶음의 구분 글자(`group.trade`, 이미 trim된 값) 목록. 목록에 없으면 펼침(U1). 빈 배열이 된 계획은 키를 지운다.
  - 예: `{"p_abc123":["도배","주방"]}`
- 읽기(앱 시작 때 한 번, `privacyModeStorage`와 같은 모양):
  - `getItem`이 throw(개인 모드·쿠키 차단) → `{}`(모두 펼침)
  - 키 없음·JSON 아님·객체 아님 → `{}`
  - 계획 값이 문자열 배열이 아니면 그 계획만 버린다. 배열 안 문자열이 아닌 값은 버린다.
  - 계획 id가 `__proto__`·`constructor`여도 안전하도록 읽은 결과는 `Map`(또는 `Object.create(null)`)으로 만든다.
  - 어느 경우에도 throw하지 않고 화면 오류를 띄우지 않는다.
- 쓰기(접기·펼치기·자동 펼침 때만): 메모리 값을 먼저 바꾸고 알린 뒤 `setItem`을 try/catch. 실패하면 이 탭에서만 유지(안내 없음).
- **정리(이름이 바뀌거나 지워진 묶음)**: 그 계획에 쓸 때 **지금 화면에 있는 묶음의 구분만 남긴다.** 구분을 모두 다른 이름으로 바꾸면 새 이름 묶음은 펼침으로 보이고, 옛 이름은 다음 쓰기 때 빠진다. 같은 이름의 줄을 다시 만들면(아직 정리 전이면) 접힌 채 나타날 수 있으나 U5 자동 펼침이 바로 편다. 지운 계획의 값은 남겨 둔다(계획 3개 이하라 크기 걱정 없음, A3). 알려진 한계: 폴링·일시 편집으로 묶음이 잠깐 사라진 시점에 다른 묶음을 접으면 그 이름이 지워진다(접힘 한 번 다시 하기, 허용 — fe 검토).
- 모듈 위치(CONVENTIONS): 저장소 `src/lib/utils/interiorGroupCollapseStorage.ts`(`createInteriorGroupCollapseStore({ storage })`, `getSnapshot`·`subscribe`·쓰기 함수), 타입 `src/lib/types/`, 훅은 우리 집 화면 전용이라 `src/containers/Mortgage/Home/hooks/`(`useSyncExternalStore`로 그 계획의 접힌 구분 집합을 읽는다). `AppRoutes.createStores`에서 만들어 `MortgageHome` → `PlanScreen` → `PlanLines`로 내린다.

## 화면

### 묶음 제목 줄 (U2, U3)

- 제목은 **언제나 버튼**이다(묶음 1개여도). `<h3>` 안 버튼 하나, 오른쪽 확정 합계는 지금처럼 버튼 밖 형제다. 꺾쇠·"· n줄"은 버튼 안에 둔다.
  - `aria-expanded`: 펼침 true / 접힘 false
  - `aria-controls`: 그 묶음의 줄 `<ul>`과 [+ {구분}에 줄 추가]를 감싸는 요소 id(`useId`). 감싸는 요소는 접혀도 DOM에 남기고 `hidden`을 붙인다(가리키는 id가 사라지지 않게). 안의 줄은 **접히면 그리지 않는다**(묶음별 `SortableContext`도 함께 빠져 끌 대상·놓을 자리에서 빠진다).
  - 묶음 2개 이상이면 지금 끌기 속성을 그대로 더한다(`aria-roledescription`·`aria-describedby` 유지). 1개면 끌기 속성 없이 접기 버튼만.
  - **순서 저장 중(`canReorder=false`)에도 제목은 접기 버튼이다.** 끄는 것은 끌기뿐이다: 끌기 속성(`attributes`·`listeners`, disabled일 때 붙는 `aria-disabled` 포함)은 `CompactListingRow`처럼 조건부로만 펼치고, `useSortable`의 disabled는 `draggable`만 끈다.
  - 뜬 묶음(`DragOverlay`, `as="p"`)은 버튼이 아닌 별도 제목(prop 하나로 구분)을 그린다. 접힌 묶음이면 줄 글자를 빼고 제목 줄만 그린다.
  - **구분이 빈 글자(`trim()` 결과 "")인 묶음**: 저장 키는 빈 문자열 그대로 두되, 제목 버튼의 접근 가능한 이름이 비지 않게 "구분 없음"으로 읽히게 한다(`aria-label`). 보이는 글자와 `[+ 에 줄 추가]` 문구는 이번에 바꾸지 않는다(기존 동작).
- 조작(U3):
  - 짧게 누르기·클릭·**엔터** = 접기/펼치기
  - 꾹 누르기(250ms)·**스페이스** = 지금처럼 묶음 들기(묶음 2개 이상). 든 뒤 놓아도 접힘 상태는 바뀌지 않는다(포인터는 dnd-kit가 click을 막고, 키보드는 스페이스가 들기라 click이 나지 않아야 한다 — AC-2로 지킨다)
  - 묶음이 1개면 스페이스도 기본 버튼 동작(접기)이다
- 모양:
  - 제목 글자 뒤에 작은 회색 꺾쇠(`lucide-react` `chevron-down`, 이미 설치). 펼침 = 아래(∨), 접힘 = 오른쪽(>)으로 돈다. `aria-hidden`
  - 접혔을 때만 제목 뒤에 작은 흐린 글자 **"· n줄"**(그 묶음 줄 수). 확정 합계는 접혀도 펼쳐도 지금 자리 그대로(U2)
  - 접힌 묶음은 흰 면 한 장(`.group`) 안에 제목 줄만 남는다. 아래 여백이 너무 좁지 않은지 360px에서 확인
  - 제목 칸 전체가 누를 자리(지금 `groupHandle` 여백 그대로). 꺾쇠만 따로 누르는 버튼은 만들지 않는다
- 접근 가능한 이름은 구분 글자 그대로(지금과 같음). 접혔을 때 "n줄"은 이름 뒤에 읽혀도 된다. 접으면 포커스는 제목 버튼에 남고, 펼칠 때 자동 스크롤은 하지 않는다.

### 끌기와의 관계

- 접힌 묶음도 들어 옮길 수 있다. 뜬 묶음(`DragOverlay`)은 **접힌 묶음이면 제목 줄만**, 펼친 묶음이면 지금처럼 제목 + 줄 글자다(빈 자리 크기와 뜬 면 크기가 맞게). 접힘 값은 저장소에서 라이브로 읽어도 된다(든 동안 click이 없어 바뀌지 않는다).
- 묶음을 든 동안·순서 저장 중에는 끌기만 막히고 접기 상태는 바뀔 수 있다(든 동안에는 click이 없다).
- 줄 끌기는 펼친 묶음 안에서만 가능하다(접힌 묶음의 줄은 그려지지 않는다). 줄을 든 동안 다른 묶음 제목을 눌러 접는 일은 없다(포인터 하나).
- 놓은 뒤 저장 값(`lineOrderAfterGroupMove`·`lineOrderAfterMove`)은 데이터(스냅샷)로 만들므로 접힘과 상관없다. 수정 없음.

### 상태 유지·반복 사용 불편

- [목록|표] 전환, 다른 계획 갔다 오기, 새로고침, 30초 재조회 뒤에도 접힘이 그대로다(저장소가 컴포넌트 밖, 구분 글자로 찾음).
- 계획마다 따로다(계획 A의 "욕실"을 접어도 계획 B의 "욕실"은 펼침).
- 접은 묶음 아래 묶음의 줄을 열었다 닫으면 포커스는 그 줄로 돌아온다(지금과 같음).
- 저장 실패 안내는 없다(되돌리기 쉬운 화면 설정, 이 탭에서는 동작).

### 자동 펼침 (U5)

- 줄 시트 [저장]이 성공했을 때, 저장한 줄의 구분(`values.trade.trim()`)이 그 계획에서 접혀 있으면 펼치고 기억한다. 새 줄(떠 있는 [+])과 고친 줄(구분을 접힌 묶음으로 바꾼 경우) 모두 같다. 저장 성공 처리는 `MortgageHome`의 `onSave` 한 곳이다.
- 접힌 묶음 안 [+ {구분}에 줄 추가]는 접히면 숨으므로(U6) 그 경로는 생기지 않는다.

### 영향 없음 (U7)

- 표·인쇄·CSV(`PlanTableView`·`buildInteriorPlanTable`·CSV)·요약(`PlanSummary`)·홈 카드·묶음 합계 계산은 접힘과 상관없이 그대로다.

## 수용 기준

- [ ] **AC-1 접고 펴기·접근성**
  - 묶음 제목을 클릭하면 그 묶음의 줄과 [+ {구분}에 줄 추가]가 사라지고, 제목 버튼 `aria-expanded="false"`, "· n줄"과 확정 합계(있을 때)가 보인다. 다시 클릭하면 줄이 돌아오고 `aria-expanded="true"`다. `aria-controls`가 가리키는 요소가 DOM에 있다.
  - 엔터로도 같다. 묶음이 1개인 계획에서는 제목이 버튼이고 엔터·스페이스 둘 다로 접힌다(A6). 순서 저장 중에도 제목 클릭으로 접힌다.
  - 다른 묶음은 영향이 없다(여러 묶음을 동시에 접을 수 있다).
- [ ] **AC-2 끌기와 충돌 없음**(묶음 2개 이상)
  - 제목에서 스페이스 → 묶음이 들리고(끌기 알림 "…묶음을 들었습니다") `aria-expanded`는 그대로다. 화살표·스페이스로 놓으면 순서가 저장되고 접힘 상태도 그대로다. **통합 테스트 하나로 반드시 잡는다**: user-event로 "스페이스 들기 → 스페이스 놓기(포커스는 제목 버튼에 남음)" 뒤 `aria-expanded` 불변(놓는 스페이스 keyup이 click을 만들어 접힘이 바뀌는 연결 누락을 막는다).
  - 접힌 묶음을 들어 옮기면 뜬 묶음에 줄 글자가 없고, 놓은 뒤에도 접혀 있다. 펼친 묶음 안 줄 끌기·짧게 눌러 시트 열기는 지금과 같다(기존 끌기 테스트 통과).
  - **사람 확인(자동화 안 함)**: 실기기·브라우저에서 꾹 눌러 끌고 놓은 뒤 묶음이 접히거나 펼쳐지지 않는다(합성 이벤트로는 click 억제를 못 본다. 이 저장소에 Playwright 없음, 도입하지 않는다). VoiceOver로 제목에서 `aria-expanded`(접힘/펼침)가 읽히는지 한 번 본다(`aria-roledescription`이 역할 낭독을 덮을 수 있음). 확인하지 못하면 "사람 확인 필요"로 남긴다.
- [ ] **AC-3 기억·복원**
  - 계획 P에서 "도배"를 접으면 `loan-calculator/interior-collapsed-groups` 원문이 `{"{P id}":["도배"]}`다. 다시 펴면 P 키가 없다.
  - 저장소를 그대로 두고 앱을 다시 마운트하면 도배가 접혀 있다. [표] → [목록] 전환 뒤에도 접혀 있다.
  - 계획 Q의 같은 이름 묶음은 펼쳐져 있다.
- [ ] **AC-4 읽기·쓰기 실패**
  - 원문이 `"{"`·`"[]"`·`"null"`·`{"P":"도배"}`·`{"P":[1,"도배"]}`이면 앞의 넷은 모두 펼침, 마지막은 도배만 접힘이고 오류 화면이 없으며 `console.error` 스파이 호출이 0회다.
  - 접근 불가 storage(모든 호출이 throw)에서 목록이 뜨고 접기·펴기가 동작한다. 다시 마운트하면 모두 펼침이다.
  - `getItem`은 되고 `setItem`만 throw하면 이 탭에서 접힘이 유지된다. 한 계획 값이 깨진 원문(예: `{"P":"도배","Q":["주방"]}`) 위에서 다른 계획을 접으면 깨진 P는 버려진 채 정상 JSON이 써진다.
- [ ] **AC-5 이름 바뀜·사라짐**
  - 접힌 "도배" 묶음의 줄 하나뿐인 줄을 시트에서 구분 "벽지"로 바꿔 저장하면 "벽지" 묶음은 펼쳐져 있다. 저장 성공 후 화면이 새 묶음으로 다시 그려진 것을 확인한 **다음에** 다른 묶음을 하나 접으면(정리는 쓰기 때 일어난다) 원문 P 값에 "도배"가 없다.
- [ ] **AC-6 자동 펼침**(U5)
  - "도배"를 접은 뒤 떠 있는 [+]로 구분 "도배" 새 줄을 저장하면 도배 묶음이 펼쳐지고 새 줄이 보이며, 원문에서도 도배가 빠진다. 저장이 실패하면(시트가 열린 채) 접힘은 그대로다. 고친 줄이 구분을 접힌 묶음으로 바꿔 저장한 경우도 그 묶음이 펼쳐진다. (화면 통합 테스트로 확인 — `onSave` 연결 누락은 단위 테스트로 못 잡는다)
- [ ] **AC-7 계획 데이터·다른 화면 무변화** `[위험]`
  - 판정 방법: 접기·펴기 전후로 `localStorage`의 **모든 `loan-calculator/*` 키** 원문 스냅샷을 비교해 바뀐 키가 `interior-collapsed-groups` 하나뿐이다(`interior-plans`만 보면 다른 키 오염을 놓친다). 로그인 상태에서 접기·펴기 직후 api 모킹(fetch 또는 apiClient 스파이) 호출 수가 0이다.
  - 접힌 묶음이 있어도 표·CSV·요약 글자는 접기 전과 같다. 표·CSV·요약 함수가 접힘 입력을 받지 않음을 시그니처로 확인하고(별도 테스트 없음), 접은 상태에서 표 보기 텍스트를 한 번 비교한다.
- [ ] **AC-8** `pnpm lint`·`format:check`·`test`·`build` 통과. 360px에서 접힌·펼친 제목 줄(꺾쇠·"· n줄"·확정 합계가 한 줄)을 화면으로 사람이 확인한다(자동 테스트 없음).

## 가정

- A1: "카테고리" = 목록 보기의 구분(공정) 묶음이다. 표 보기의 구분 묶음 행은 해당하지 않는다(U7).
- A2: 묶음 식별자는 구분 글자(`group.trade`, trim 후)다. 저장 형식에 묶음 id가 없고, 끌기 id도 같은 값을 쓴다. 대소문자·공백 차이는 지금 묶음 규칙(trim만)을 그대로 따른다.
- A3: 지운 계획의 접힘 값은 남겨 둔다(계획 3개 이하, 구분 수십 개 이하라 수 KB 미만).
- A4: 접힘은 화면 취향이라 저장 실패를 알리지 않는다(`privacyMode`·`textSize`와 같다).
- A5: 로그인 전후·함께 쓰기 전환에도 계획 id가 그대로라 접힘이 이어진다. 로그아웃해도 이 키는 지우지 않는다(데이터가 아니라 기기 설정).
- A6: 스페이스로 들기는 ADR-026 관례라 APG의 "스페이스로 여닫기"보다 우선한다. 묶음이 1개일 때만 스페이스가 접기다.

## 결정 필요

- **D1 저장 키 나누기 — 결정됨: A** ([ADR-039](../decisions/039-group-collapse-storage.md)). 뒤집을 조건: 두 기기 접힘을 맞추고 싶다는 요청이 오면 서버 계획 필드로 옮기는 것을 다시 본다. 당시 선택지:
  - A: 키 하나 `loan-calculator/interior-collapsed-groups`에 `{ [planId]: 접힌 구분[] }`
  - B: 계획마다 키 `loan-calculator/interior-collapsed-groups/{planId}`
  - C: 계획 구분 없이 접힌 구분 이름 하나의 목록(모든 계획에 같이 적용)
  - 이유: 기존 키들(`listing-order`, `interior-plan-imports`)처럼 기능당 키 하나라 읽기·정리·테스트가 한 곳이다. B는 지운 계획 키가 흩어지고, C는 계획마다 공정 구성이 달라 한 계획에서 접은 것이 다른 계획을 접는다.

## 사용자 확인 필요

제품 기본값이다. 되돌리기 쉽고, 답이 오기 전에는 **굵은 글씨의 제안 기본값**으로 진행한다.

- **U1 처음 상태**: **모두 펼침**(지금 화면 그대로). 접은 것만 기억한다.
  - 대안: 처음엔 모두 접힘(제목·합계만 보이는 요약 목록).
- **U2 접힌 제목 줄에 보일 것**: **구분 이름 + "· n줄"(접혔을 때만) + 오른쪽 확정 합계(지금 그대로)**.
  - 대안 ①: "n줄"을 펼쳐도 늘 보이기. 대안 ②: "n줄" 없이 지금 제목 그대로. 대안 ③: "확정 n / 전체 n줄".
- **U3 접는 조작 위치**: **제목 칸 전체를 짧게 누르기(엔터) = 접기, 꾹 누르기(스페이스) = 지금처럼 묶음 옮기기. 제목 글자 뒤 작은 꺾쇠로 상태 표시**(저장 목록 간단히 보기 줄과 같은 규칙).
  - 대안: 제목 왼쪽에 꺾쇠 버튼을 따로 두고 그것만 접기(제목은 옮기기 손잡이만). 조작이 섞이지 않지만 누를 자리가 작다(44px 확보 필요).
- **U4 모두 접기/펴기**: **두지 않는다**(묶음 수가 많지 않고 노션 토글도 없음).
  - 대안: 목록 위 [모두 접기]/[모두 펴기] 한 버튼.
- **U5 접힌 묶음에 줄을 저장했을 때**: **그 묶음을 자동으로 펼친다**(방금 저장한 줄이 보이게).
  - 대안: 접힌 채 두고 "n줄"만 늘어난다.
- **U6 접힌 묶음의 [+ {구분}에 줄 추가]**: **줄과 함께 숨긴다**(떠 있는 [+]는 그대로).
  - 대안: 접혀도 보인다.
- **U7 적용 범위**: **목록 보기에만, 이 기기에만.** 표·인쇄·CSV·요약·홈 카드는 그대로이고, 함께 쓰는 사람 화면은 각자의 접힘이다.
  - 대안: 표 보기에서도 같은 묶음 접기.
