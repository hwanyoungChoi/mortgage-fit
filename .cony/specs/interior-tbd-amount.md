# 우리 집 — 견적 금액 "미정" 줄

> 작성 2026-10-27 · 브랜치 `cony/interior-tbd-amount` · 상태: **D1 결정됨(ADR-033, C)**, 제품 기본값 U1~U6은 사용자 확인 전
> 관련: 스펙 `interior-simple.md`(줄 = (항목, 견적), 예시 P·L, AC-0 규칙) · ADR-001(손상이면 전체 corrupt) · 002(만원 정수) · 007(합계는 계산) · 012(선택 필드 = 키 없음) · 027(옛 번들 위험) · 029(검증 원본 `validateInteriorPlan.ts`) · 032(저장 형식 무변경 매핑) · **033(이 기능의 저장 표현·배포 순서)** · `interior-planner.md` "앞으로 더하는 필드는 모두 선택 필드(qa D3)"

## 목표

업체한테 견적을 요청만 해 두고 금액은 아직 모를 때도 그 줄을 적어 둘 수 있게 한다. 금액이 정해지면 채우기만 하면 된다. 합계는 금액이 있는 줄만 더하고, 금액이 비어 빠진 줄이 몇 개인지 알려 준다. 이미 저장된 계획은 로그인 여부와 상관없이 하나도 잃지 않는다.

## 사용자 시나리오

1. [줄 추가]에서 구분 "조명", 업체 "빛나라조명", 세부내용 "거실 매입등"을 적고 견적 칸은 비운 채 저장하면, 목록에 "미정"으로 보인다.
2. 이 업체로 하기로 정했으면 [확정]을 켠다. 지출 예정은 그대로 800만원이고, 옆에 "미정 1건"이 붙는다.
3. 실측 뒤 견적 120만원을 받으면 그 줄 시트에서 금액을 채운다. 지출 예정이 920만원이 되고 "미정" 표시는 사라진다.
4. 표·CSV·인쇄에서는 금액 칸에 "미정"이 찍히고, "계" 줄에 "금액 미정 1건 제외"가 붙는다.

## 참고한 사례

- **스프레드시트 관례(엑셀·구글 시트)**: 금액을 모르면 칸을 비우거나 "미정"이라고 적는다. `SUM`·`SUMIF`는 빈칸과 글자를 0처럼 건너뛰고, 빠진 건수는 `COUNTBLANK`로 따로 센다.
  - 가져올 것: 지출 예정 = 금액이 있는 확정 줄의 합. 미정 줄은 더하지 않고 건수만 따로 보인다.
  - CSV 금액 칸의 "미정" 글자는 엑셀 `SUM`이 건너뛰므로, 내려받은 파일로 다시 합계를 내도 깨지지 않는다.
- **Smartsheet 견적 비교 템플릿**: 견적마다 lowest·accepted·rejected·incomplete 상태를 둔다. "아직 금액이 없는 견적(incomplete)"을 하나의 상태로 인정하는 셈이다. → 미정은 줄의 한 상태로 보이되, 따로 상태 필드를 만들지 않고 "금액 키가 없음"으로 나타낸다(ADR-012). https://www.smartsheet.com/content/construction-bid-templates-and-forms
- **국내 견적 비교 가이드**: 항목별로 비교하라고 권한다. "협의 후 결정"처럼 모호한 금액은 추가 비용 위험 신호로 본다. → 미정 줄이 합계에 조용히 묻히지 않도록, 요약·표·허브에 "미정 n건"을 꼭 보인다. https://store.hanssem.com/tips/guide/%EC%9D%B8%ED%85%8C%EB%A6%AC%EC%96%B4-%EC%97%85%EC%B2%B4-%EA%B3%A0%EB%A5%B4%EA%B8%B0/ · https://tilnote.io/pages/6adb8519053520860ae8e4c4
- **Parallel Change(Expand–Contract, Martin Fowler)와 Tolerant Reader**: 호환되지 않는 형식 변경은 단계를 나눠 배포한다. 먼저 읽는 쪽이 새 형식을 받아들이게(expand) 배포하고, 그 뒤에 새 형식을 쓰기 시작한다. → ADR-033의 2단계 배포. https://www.martinfowler.com/bliki/ParallelChange.html · https://www.thoughtworks.com/en-au/radar/techniques/api-expand-contract
- **우리 코드**:
  - 저장소 파서는 하나라도 어긋나면 전체를 corrupt로 본다(`interiorPlanStorage.ts` `parseInteriorPlans`, ADR-001).
  - 서버 응답 파서도 하나라도 어긋나면 조회 실패로 본다(`useInteriorPlanList.ts`).
  - 다른 탭이 저장하면 `storage` 이벤트로 바로 다시 읽는다(`useInteriorPlanListSource.ts:72-79`).
  - 손상 화면에는 확인 창 뒤 키를 지우는 [계획 초기화]가 있다(`CorruptPlansNotice.tsx`).

## 데이터 모델 (ADR-033)

- `InteriorQuote.amount?: number`: 키가 없으면 미정이다(ADR-012). 값이 있으면 지금처럼 만원 정수 1~999,999,999다.
  - 키 없음과 `undefined`만 미정이다. `null`·`0`·`""`·`"100"`·`1.5`·`1000000000`은 지금처럼 거부한다. `1`과 `999999999`는 통과한다.
  - 돌려주는 객체에 `amount: undefined` 키를 남기지 않는다. `exactOptionalPropertyTypes`가 꺼져 있어 타입이 막지 못하므로 `Object.hasOwn` 단언으로 지킨다.
- 바꾸는 검증은 `validateInteriorPlan.ts` `parseQuote` 한 곳이다(`parseOptional(value, "amount", isInteriorAmount)`). 서버(`server/interiorPlans/*`)·로컬 저장·로그인 이전이 이 검증을 같이 쓰므로 함께 넓어진다.
  - 서버 코드 diff와 D1 마이그레이션은 0이다(항목은 JSON `data` 컬럼에 저장). 기존 `server/**` 테스트 파일 수정도 0이다.
  - 다만 서버 동작은 바뀐다. 금액 없는 견적의 POST·PUT·import를 받는다.
- `InteriorPayment.amount`·`budget`은 그대로 필수다.
- 계산(저장하지 않음, ADR-007). **`interiorPlanRows` 한 곳**에서 "확정이고 금액이 있는가"라는 한 가지 판단으로 만들고, 요약·표·CSV·허브가 그 결과를 쓴다(따로 세지 않는다).
  - 지출 예정 = Σ(확정이고 금액이 있는 줄)
  - 미정 건수 `tbdCount` = 확정이고 금액이 없는 줄의 수(U2). 미확정 미정 줄은 세지 않는다.
  - 남은 예산 = 총 예산 − 지출 예정. 미정 줄은 더하지 않는다.
  - 타입 오류를 `?? 0`·`!`로 덮지 않는다(`interiorPlanRows.ts:79`의 `?? 0`도 위 판단으로 대체).
- 표 모델(`buildInteriorPlanTable`)의 견적 칸은 **견적 없음 / 미정 / 금액** 세 가지를 구분하는 한 타입이다(`number | undefined` 하나에 두 뜻을 싣지 않는다). "미정" 글자 상수는 `lib/constants/interiorPlanTable.ts`에 모아 `AmountCell`·CSV가 같이 쓴다.
- 문구 "금액 미정 n건 제외"는 `tbdCount`를 받는 함수 하나에서 만든다(n=0이면 빈 문자열).
- 쓰기 규칙(`interiorLineWrites.ts`):
  - 확정 토글·삭제·형제 견적 수정은 금액 없는 견적을 그대로 보존한다(1단계부터).
  - 2단계: 시트 금액이 비면 그 견적의 `amount` 키를 지운다. 채우면 키를 넣는다. `editedQuote`는 `amount`를 `memo`처럼 구조 분해로 빼고 값이 있을 때만 다시 넣는다(`{...rest}`가 기존 `amount` 키를 그대로 펼치므로 `amount: undefined`만 덮어쓰면 키가 남는다). 나머지 숨은 값은 지금처럼 그대로 돌려보낸다.

## API 계약

경로·봉투·에러는 바뀌지 않는다. 바뀌는 것은 본문 규칙 하나다.

- 항목 POST·PUT(`/api/interior-plans/{id}/items`, `/api/interior-plans/{id}/items/{itemId}`), 계획 POST(`/api/interior-plans`), 이전(`/api/interior-plans/import`)의 `quotes[].amount`를 생략할 수 있다. 응답은 생략한 그대로 돌려준다.
- GET `/api/interior-plans` 응답에서 미정 견적에는 `amount` 키가 없다.
- 400: `amount`가 `null`·소수·문자열·음수·상한 초과(1e9)면 거부한다(0은 ADR-033 개정으로 허용, 8e30cdd). 오류 모양은 변경 전과 같다.

### 원 단위 키(ADR-034, 태스크 1-4)

경로·봉투·오류 모양은 그대로다. 본문 규칙이 늘어난다.

- 견적 `quotes[].amountWon?`(원 정수 0~9,999,999,999,999)과 플랜 `budgetWon?`(원 정수 1~9,999,999,999,999)을 항목 POST·PUT, 계획 POST, `/import`, GET이 받고 그대로 돌려준다. 서버는 옛 키(`amount`·`budget`)를 새 키로 바꾸지 않는다.
- 한 견적에 `amount`·`amountWon`, 한 플랜에 `budget`·`budgetWon`이 함께 오면 400 `invalidParams`다(같은 환산값이어도).
- PATCH `/api/interior-plans/{id}`는 `budgetWon`(숫자 또는 null)을 알려진 키로 받는다. `budget`·`budgetWon` 중 하나라도 보내면 두 키를 함께 정한다(`src/lib/utils/budgetMergePatch.ts`, 로컬 저장소와 같은 함수).
  - `{ budget: n }` → `budget: n`, `budgetWon` 지움. `{ budgetWon: n }` → 반대. `{ budget: null }`·`{ budgetWon: null }` → 둘 다 지움.
  - `{ budget: n, budgetWon: null }`·`{ budget: null, budgetWon: n }`은 받는다. 두 키 모두 숫자면 400 "budget과 budgetWon을 함께 숫자로 보낼 수 없습니다".
  - 예산 키가 없으면(이름만 등) 예산 키를 건드리지 않는다.
  - `budgetWon`이 0·소수·문자열·상한 초과(1e13)면 400 "budgetWon은 1~9,999,999,999,999 정수(원) 또는 null이어야 합니다".
  - "하나 이상" 오류 문구의 키 목록에 `budgetWon`이 들어간다.
- 마이그레이션 없음(JSON `data` 컬럼).

## 화면

- **줄 시트**: 견적 칸이 선택 칸이 된다(U1).
  - 1단계: 미정 줄을 열면 견적 칸은 `""`이다(`String(undefined)`나 `Number("")`로 "undefined"·0이 들어가지 않는다). 금액 없이 저장하면 지금처럼 필수 오류다. 이 동작은 2단계에서 없어진다.
  - 2단계: 빈칸으로 저장하면 미정이다. 안내는 라벨 "견적(비우면 미정)"으로 한다("세부내용(선택)"·"비고(선택)"과 같은 관례, 공용 `AmountInput`에 props를 늘리지 않는다).
  - `0`·`-1`·`1.5`·`1,000,000,000`·`12a`는 지금처럼 오류다. `"   "`는 빈칸으로 본다.
  - 업체는 계속 필수다. 업체를 비우면 지금처럼 저장을 막는다(U3).
  - 견적 없는 줄의 확정 안내는 2단계에서 "줄을 열어 업체를 적으세요"로 바꾼다(견적이 선택이 되므로).
- **목록**:
  - 금액 자리에 "미정"을 지금 금액과 같은 위치·크기로 보이되, 기존 토큰 `--color-text-muted`로 구분한다(새 토큰 없음).
  - 확정 체크는 켤 수 있다(U2). 확정 체크의 접근 가능한 이름은 그대로 쓴다.
- **요약**:
  - 확정 미정 줄이 있으면 지출 예정·남은 예산 headline 아래 **전체 폭 한 줄**로 "금액 미정 1건 제외"를 작게 붙인다. 남은 예산도 같은 기준이다.
  - 문구는 요약 영역(`aria-label="요약"`) 안에서 정확히 한 번 보인다. 표 보기에는 표 머리·"계" 비고에 각각 한 번 더 있다(영역별로 한 번).
  - 예산 초과일 때도 문구가 붙는다. 미정 0건이면 문구가 없다.
- **표·인쇄**:
  - 견적(원) 칸에 "미정"을 넣는다. 확정한 미정 줄이면 확정(원) 칸에도 "미정"을 넣는다. 견적 없는 빈 줄은 계속 빈칸이다.
  - "계" 줄의 비고에 "금액 미정 n건 제외"를 넣는다(n ≥ 1일 때만).
  - 표 머리의 지출 예정 조각 뒤에 "(금액 미정 n건 제외)"를 붙인다(조각 하나라 가리기가 조각 단위로 맞는다).
- **CSV**:
  - 표와 같은 글자를 쓴다("미정", "금액 미정 n건 제외").
  - BOM·CRLF·수식 주입 규칙은 그대로다.
- **홈 허브**:
  - 확정 미정 줄이 있으면 "{이름} · 지출 예정 800만원 · 미정 1건"으로 보인다(U5). 확정이 미정뿐이면 "지출 예정 0만원 · 미정 1건"이다.
  - 0건이면 지금 문구 그대로다.
  - 360px에서 이름이 길어 두 줄이 되는 경우를 수동 확인한다.
- **가리기**(U6): 가리는 곳은 **허브·요약·표(머리·칸·계 비고)·목록 네 곳**이고, 목록·표 **두 보기** 모두에서 확인한다.
  - "미정"은 금액 칸이므로 금액처럼 가린다(표의 "미정"은 `MaskedValue`).
  - "미정 n건"·"금액 미정 n건 제외" 조각은 구분자(`·`)까지 **통째로 뺀다**. 허브는 "우리 집 · 지출 예정 •••가려짐"이다(•••가 둘이 되지 않는다).
  - 컨테이너 `innerHTML`과 `aria-label`에 "미정"이 없다.
- **반복 사용 불편 방지**:
  - 미정 줄은 시트를 열어 금액만 채우면 된다. 포커스는 main과 같이 시트 자체로 간다(묶음 끝 [+ {구분}에 줄 추가]만 세부내용 칸, qa 1-6 정정).
  - 저장 뒤 스크롤 위치는 유지된다.
  - "미정"이 금액과 같은 열에 있어 눈으로 훑기 쉽다.

    - 1단계 배포 기록(커밋·시각)을 `.cony/log.md`와 ADR-033에 남긴다.
- [ ] 2. **시트에서 금액 비우기(2단계 배포 = contract)** — AC-0(e) 게이트(기록 · 사용자 두 사람 확인 · 최소 24시간)를 모두 충족한 뒤에만 머지
  - [ ] 2-1. 시트·쓰기 (담당: client)
    - `interiorLineDraft`의 금액을 선택 칸으로 바꾸고 `InteriorLineValues.amount?`로 만든다.
    - `editedQuote`는 `amount`를 구조 분해로 빼고 값이 있을 때만 넣는다(비우기 → 키 삭제).
    - 라벨 "견적(비우면 미정)", 견적 없는 줄 확정 안내 "줄을 열어 업체를 적으세요"와 그 문구 단언 테스트 수정.

  - [ ] 2-2. 검증 (담당: test)

    - 2단계 전 사용자 질문(이전되지 않은 로컬 계획)의 답과 diff 가드 결과를 기록하고, 롤백 하한을 ADR-033에 적는다.

## 가정

- A1: "금액도 미정으로"는 **업체는 알고 금액만 모르는 줄**을 뜻한다. 업체까지 모르는 줄은 지금의 빈 줄(구분·비고)로 충분하다.
- A2: 서버와 정적 번들은 한 번의 Workers 배포로 함께 바뀐다(ADR-011 개정). 그래서 "새 클라이언트 + 옛 서버" 조합은 없고, 위험은 **이미 열려 있는 옛 번들 탭**뿐이다. 서버 읽기는 검증하지 않으므로(`JSON.parse(row.data)`) 서버는 금액 없는 견적으로 500을 내지 않는다.
- A3: 옛 번들 탭의 동작은 다음과 같다(코드로 확인, 옛 파서 corrupt 판정은 qa가 재현).
  - 로그아웃 상태에서 같은 브라우저의 다른 탭이 미정 견적을 저장하면, `storage` 이벤트로 즉시 다시 읽어 **이 기기 계획 전체를 손상**으로 보인다.
  - 그 화면의 [계획 초기화]를 확인 창까지 누르면 키가 지워진다. 새 탭도 `storage` 이벤트로 빈 목록이 된다. 이것이 유일한 **데이터 손실 경로**다. 손상 상태에서는 옛 탭이 덮어써서 잃게 하는 경로는 없다.
  - 잃는 것은 **로컬에만 있는 계획**이다. 로그인해 이전된 계획은 로컬 사본을 잃어도 서버에 남는다(이전은 로컬을 지우지 않는다).
  - 로그인 상태에서는 목록 조회가 실패("불러오지 못함")할 뿐 파괴 동작은 없다.
- A4: 사용자는 본인·배우자 두 사람이고 사용 기기가 적다. 24시간은 "그 사이 새로고침했을 가능성"의 대리 지표일 뿐 보장이 아니고(서비스 워커·버전 확인 없음, 휴대폰 탭은 며칠 남을 수 있음), 접속 통계도 없다. 그래서 게이트의 본체는 두 사람의 직접 확인이고 24시간은 하한이다.
- A5: 미정은 0원이 아니다. 지출 예정·남은 예산에는 더하지 않지만, 화면은 반드시 "미정 n건"을 함께 보여 0원으로 오해하지 않게 한다.

## 결정됨(ADR-033)

- **D1 미정의 저장 표현과 배포 순서 → C 채택.** `quote.amount` 선택 필드(키 없음 = 미정)를 A와 같은 표현으로 쓰되 2단계로 배포한다. 반대 의견이 없어 반론 라운드 없이 결정됐다.
  - A(한 번에 배포)는 배포 순간 열려 있던 모든 옛 탭을 손실 경로에 노출해 버렸다. B(견적 0개 줄)는 업체를 담을 곳이 없어 시나리오 1·2를 채우지 못해 버렸다.
  - 반영한 ADR 조건: 1 게이트(AC-0(e)), 2 롤백 하한(AC-0(e)), 3 검증 범위(데이터 모델·AC-0(a)), 4 계산 한 곳·표 모델·문구 함수(데이터 모델·AC-1), 5 시트(화면·AC-2·태스크 1-2/2-1), 6 가리기(화면·AC-4), 7 기준 브랜치(태스크), 8 옛 파서 기록(AC-0(h)·(e)), 9 미리보기 규칙(태스크).
  - 뒤집을 조건: 번들 버전 확인 장치가 생기면 다음 형식 완화는 한 번 배포로 할 수 있다.
- 후속 문서(스펙 밖): `interior-planner.md`의 "필수 필드는 처음부터 있는 것만" 규칙에 "필수 → 선택 완화는 2단계 배포, 저장된 선택 필드는 되돌릴 수 없다"를 덧붙인다. ADR-033에 1단계 배포 커밋·시각과 롤백 하한 확인 결과를 적는다.

## 사용자 확인 필요

**사용자 확인 전** 기본값이다. 되돌리기 쉬우며, 답이 오기 전에는 이 기본값으로 진행한다.

- U1 미정 입력 방법: **견적 칸을 비우면 미정**(스프레드시트 관례, 누를 것이 가장 적음). 라벨 "견적(비우면 미정)"으로 안내한다. 대안: 견적 칸 옆 [금액 미정] 체크박스(실수로 비우는 것을 막지만 한 번 더 누름).
  - 주의: 금액을 깜빡하면 조용히 미정 줄이 된다. 확정 줄에서 금액을 지우면 지출 예정이 줄어든다. "금액 미정 n건 제외" 표기가 이를 알린다.
- U2 미정 줄 확정: **켤 수 있다**(업체는 정했고 실측 뒤 금액이 정해지는 경우). 지출 예정에는 더하지 않고 "금액 미정 n건 제외"를 붙인다. n은 확정한 미정 줄만 센다. 대안: 금액을 채워야 확정 가능(빈 줄처럼 disabled).
- U3 업체: **계속 필수**다. 업체도 모르면 지금의 빈 줄(구분·비고)로 적는다. 대안: 업체도 비울 수 있게.
- U4 표기: 목록·표·인쇄·CSV 모두 **"미정"**, 요약·표 머리·계는 **"금액 미정 n건 제외"**. 대안: CSV는 빈칸, 문구는 "미정 n건 별도".
- U5 홈 허브: **"{이름} · 지출 예정 800만원 · 미정 1건"**(확정 미정 1건 이상일 때만). 대안: 허브는 지금 문구 그대로.
- U6 가리기: **"미정"과 "미정 n건"도 금액처럼 가린다**(가리는 중에는 해당 조각을 구분자까지 뺀다). 대안: "미정"은 금액이 아니므로 보인다.
