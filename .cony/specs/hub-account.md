# 홈으로 계정·함께 쓰기 옮기기 + 우리 집 가리기 없애기

> 작성 2026-10-27 · 개정 2026-10-27(ADR-035 반영) · 브랜치 `cony/hub-account`(main 3c0bdc2 기준) · 상태: 결정 D1~D3 **결정됨(ADR-035)** · 사용자 확인 U1~U9 대기(제안 기본값으로 진행 가능)
> 관련: ADR-035(이 스펙의 결정) · ADR-031(홈 허브, 스펙 `platform-home.md` U10·U11·AC-1·AC-7(c)) · ADR-028(함께 쓰는 목록) · ADR-029(인테리어 플래너, D4 가구 범위·수락 시 숨김) · ADR-030(표 보기, 가리기 중 내보내기 비활성 U18) · ADR-032(인테리어 단순화, 가리기 테스트 감사 규칙) · ADR-017(시트 이력)
> 순서(ADR-035 조건 7): 같은 fe가 태스크 1 → 2 → 3 순서로 한다. 금액 미정 2단계(`cony/interior-tbd-amount-2`)가 main에 머지된 뒤 그 위에서 시작한다(우리 집 가리기 대조군 파일이 겹친다. log "견적 금액 미정 태스크 2").

## 목표

함께 쓰기는 이제 매물 목록과 인테리어 계획 **둘 다**에 걸리고, 로그인도 둘 다를 위한 것이다. 그래서 계정(로그인·로그아웃)과 함께 쓰기(시작·함께 쓰는 중·나가기)를 화면 하나(홈)에 모아 어디서든 [홈] 탭 한 번으로 찾게 한다. 가리기 토글은 시작했던 자리(임장 중 저장 목록)에만 남기고 우리 집에서는 없앤다. 홈은 첫 화면이라 계산 카드 매매가의 가림만 지금처럼 유지한다.

## 사용자 시나리오

1. (로그아웃, 처음) 홈 맨 위 계정 자리에 이유 한 줄과 넓은 [카카오로 로그인]이 있다(지금 그대로). 로그인을 마치면 **홈**으로 돌아온다. 취소하면 홈에 "로그인을 취소했습니다" 한 줄이 한 번 보인다. 로그인 직후 이 기기 매물의 이전이 실패하면 홈 안내에 이유와 [다시 시도]가 보인다.
2. (로그인, 혼자) 홈 계정 자리: "카카오 계정에 저장 중 · [로그아웃]", 그 아래 [함께 쓰기]. [함께 쓰기]를 누르면 지금과 같은 시트(초대 링크 만들기 → 복사·공유하기·끊기)가 열린다. 뒤로 가기는 시트만 닫는다.
3. (로그인, 함께 쓰는 중) 홈 계정 자리 둘째 줄이 "2명이 함께 쓰는 중 · [나가기]". [나가기] → 확인 문구(매물·예산·순서·인테리어 계획이 어떻게 되는지) → 홈에 "함께 쓰기에서 나왔습니다". 매물·우리 집 카드가 곧바로 내 것만의 값으로 바뀐다.
4. (로그아웃하기) 홈에서 [로그아웃] → 계정 자리가 로그인 안내로 바뀌고 카드는 이 기기 값이 된다. 실패하면 계정 자리 아래에 이유 한 줄.
5. (저장 목록) 머리 줄에는 [가리기] [목록 공유]만 있다. 로그인·로그아웃·함께 쓰기·나가기는 없고, 함께 쓰는 중 표시도 없다(U3 사용자 확인 전 기본값. 대안: 읽기 전용 "함께 쓰는 중"을 두고 누르면 홈). [가리기]를 켜면 저장 목록의 금액·메모만 가려진다.
6. (우리 집) 계획 머리글에 [가리기]가 없다([⋯]만). 저장 목록에서 가리기를 켜 둔 채 와도 우리 집의 금액·세부내용·비고는 그대로 보이고, 표 보기의 CSV·인쇄도 된다.
7. (세션이 끝남) 저장 목록·우리 집에서 401이 나면 지금처럼 그 화면 위에 "로그인이 끝났습니다. 다시 로그인해 주세요"가 보이고, 그 줄에 [홈에서 로그인] 링크가 붙는다(누르면 홈, U4 사용자 확인 전 기본값).
8. (홈 가리기) 저장 목록에서 가리기를 켜 두면 홈 계산 카드의 매매가는 지금처럼 가려진다. 우리 집 줄(지출 예정·미정 n건)은 우리 집 화면과 같게 가려지지 않는다(U6 사용자 확인 전 기본값). 홈에는 토글이 없다.

## 참고한 사례

- **web.dev "좋은 로그아웃 경험의 조건"**: 로그아웃은 사이트 전체에서 쉽게 찾는 **일관된 한 자리**에 두고 잘 안 보이는 하위 화면에 숨기지 말라고 권한다. 로그아웃 뒤에는 로그인하지 않은 상태가 분명한 화면을 보이라고 한다. 로그아웃 전에 확인을 묻는 것도 권장 사항이다. → 계정은 하단 탭 [홈]에서 늘 같은 자리(카드 위). 로그아웃하면 그 자리가 곧바로 로그인 안내로 바뀐다. 확인 대화상자는 이번에 넣지 않는다. 지금도 없고, 로그아웃해도 데이터가 지워지지 않고 다시 로그인하면 돌아온다. 그래서 다음 단계 후보로 둔다. https://web.dev/articles/sign-out-best-practices?hl=ko
- **YNAB Together**(가계부 앱의 가구 공유): 멤버 초대·관리는 예산 화면 하나가 아니라 앱 전체 메뉴(설정 드롭다운, 예산 이름 메뉴)에 있다. 한 그룹이 계획 여러 개를 함께 쓴다. → 우리 함께 쓰기도 목록과 계획 둘에 걸리므로 앱 전체 자리(홈)에서 관리한다. 메뉴 경로는 공식 글과 제3자 안내가 서로 달라, 정확한 위치까지는 확인하지 못했다. https://www.ynab.com/introducing-ynab-together-for-your-shared-financial-journey/ · https://support.ynab.com/en_us/ynab-together-B1nS78Cki.md
- **토스**: 보안·인증 같은 계정 설정은 각 서비스 화면이 아니라 하단 '전체' 탭 한 곳에 있다(블로그로 확인, 공식 자료 아님). 일반 로그아웃 메뉴는 없다고 한다. → 계정 설정을 기능 화면에서 빼 한 곳에 모은다는 관례만 가져온다. 하단 탭은 내비게이션 전용(Apple HIG, `platform-home.md`)이라 탭을 새로 만들지 않고 홈에 둔다. https://funissu.com/toss-logout-password-input
- **카카오페이·뱅크샐러드**: 계정 자리와 금액 숨기기가 어디 있는지 공식 자료로 **확인하지 못했다**. 근거로 쓰지 않는다.
- **우리 패턴**: 홈 계정 자리 `HubAccount`(확인 중에는 `session-hint`로 자리 지키기, 오류면 없음) · 화면 위 안내 `HeaderNotices`/`HomeNotices`(있을 때만 한 줄씩, `role="status"`) · 시트는 `useOpenSheet` + 뒤 화면 `inert`(ADR-017 개정: 뒤로 가기가 시트를 닫음) · 로그인 결과는 라우트 쿼리 `?login=`으로 받아 한 번 잡은 뒤 주소에서 지움 · 나가기 성공 시 `useLeaveHousehold`가 me·목록·예산·순서·계획을 다시 조회 · 가리기는 값을 DOM에 그리지 않는 `MaskedValue`.

## 데이터 모델

**변경 없음.** 새 localStorage 키 0개, 기존 키 14개의 이름·형식·값 그대로. 테이블·컬럼 변경 없음.

- `privacy-mode`: 키·값(`"true"`/없음) 그대로. **읽는 곳이 줄어든다**: 저장 목록과 홈 계산 카드 매매가만 읽는다(우리 집·홈 우리 집 줄은 더 읽지 않는다). 쓰는 곳은 저장 목록 [가리기] 하나다. 켜 둔 값은 남아 저장 목록에 계속 적용된다.
- `session-hint`: 로그인 확인 결과로 정리되는 기존 예외(ADR-029 AC-0(g)) 그대로. 홈에서 로그아웃하면 지금 저장 목록에서 로그아웃할 때와 같은 쓰기(`removeItem session-hint`)만 생긴다.
- 라우트 타입(`src/lib/types/route.ts`)만 바뀐다(D1 A):

```ts
export type Route =
  | { name: "hub"; login?: LoginResult } // 로그인 복귀 결과. 홈이 한 번 잡은 뒤 주소에서 지운다
  | { name: "calculator" }
  | { name: "listings" } // login 삭제
  | …;
```

`parseRoute`: 홈 경로는 쿼리에서 `login`만 허용 값(`cancelled|failed|notConfigured`)일 때 읽고, 그 밖의 쿼리는 버린다(`#/?a=1` → `#/`). 허용 값 검사는 `in`/객체 인덱싱이 아니라 정확 일치(`constructor`·`__proto__` 통과 금지). `#/listings?login=failed` → `#/listings`(안내 없음, 하위 호환 안 함). `PATHS.listings`는 인자를 받지 않는다. 홈 정규 경로는 `#/` 또는 `#/?login={값}`.

## API 계약

엔드포인트·요청·응답 본문 변경 없음. 바뀌는 것은 카카오 로그인 302 응답의 `Location` 하나다(be, `server/auth/handleKakaoAuth.ts`).

| ------ | ------------------------------------------------------------------------------------- | --------------------------------------------- | -------------------------------------------------------------------------------------- | ---- |

| GET    | `/api/auth/kakao/callback` 성공(초대 쿠키 없음. 공유받기 화면에서 시작한 로그인 포함) | `{origin}/#/listings`                         | `{origin}/#/`                                                                          | -    |
| GET    | `/api/auth/kakao/callback` 성공 + 정상 초대 쿠키                                      | `{origin}/#/invite/{token}`                   | 그대로                                                                                 | -    |

| GET    | `/api/auth/kakao/callback` **초대로 시작 + 취소/실패**(초대 쿠키 있음)                | `{origin}/#/listings?login=cancelled｜failed` | `{origin}/#/?login=cancelled｜failed`(초대 토큰은 버려짐. 초대 화면으로 돌아가지 않음) | -    |

- state 불일치와 `error=access_denied`가 같이 오면 `failed`다(state를 먼저 봄).
- 모든 경우 302, `Cache-Control: no-store`. 쿠키(state·초대·세션) 처리는 한 줄도 바뀌지 않는다: 실패는 `Set-Cookie` 2개(state 삭제, 초대 삭제), 성공은 세션 쿠키 포함 3개, 이름·속성·`Max-Age`를 정확히 단언한다.
- `listingsUrl`은 `homeUrl`로 바꾸고 옛 함수는 지운다. `handleKakaoAuth.ts`의 `listingsUrl`을 설명하는 주석(20행 `?login=` 설명, 36행, 94-95행 "저장 목록으로")도 홈 기준으로 고친다.
- 홈이 새로 부르는 API(모두 기존): `POST /api/auth/logout`(204), `POST /api/household/invites`, `DELETE /api/household/invites`, `POST /api/household/leave`(404는 성공으로 본다). 저장 목록은 이 넷을 더 부르지 않는다.
- 배포(ADR-035 조건 1): 서버와 화면이 같은 Worker 배포(`wrangler.jsonc` `main` + `assets`)라 함께 바뀐다. 로그인은 페이지 전체 이동이라 복귀하면 새 번들이 열린다. **1-1(서버)과 1-2(홈의 `?login=` 처리)는 같은 PR로 배포하고 1-1 단독 배포는 금지**다. 1-1만 나가면 취소·실패 안내가 사라지고, 1-2만 나가면 서버가 아직 `#/listings`로 보낸다. 옛 번들이 `#/?login=…`을 받아도 쿼리를 버리고 홈을 보일 뿐이다(안내 한 줄만 빠짐).

## 화면

### 홈 (`#/`, `Hub/MortgageHub.tsx` + `Hub/components/HubAccount.tsx`)

계정 자리는 지금처럼 `h1` "홈" 아래, 카드 목록 위에 있다. 두 행 모두 `min-height: 36px`, 글자 크기 설정이 작아져도 `flex-wrap`으로 깨지지 않는다. 확인 중 자리표시자는 같은 컴포넌트를 숨김 상태(`isHidden`)로 그려 마크업이 같다. 상태별 모양:

| 계정 상태                                           | 첫 줄                                                                                                                | 둘째 줄(함께 쓰기)                                                      |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 확인 중                                             | 지금 그대로(`session-hint`로 예측한 모양을 숨겨 자리만, `inert`·`aria-hidden`. [로그아웃]은 포커스·클릭을 받지 않음) | 예측이 로그인이면 [함께 쓰기] 자리도 숨겨 함께 지킨다(높이 흔들림 방지) |
| 로그아웃                                            | 이유 한 줄 + 넓은 [카카오로 로그인](U2 문구)                                                                         | 없음                                                                    |
| 로그인·혼자                                         | "카카오 계정에 저장 중" · [로그아웃]                                                                                 | [함께 쓰기] (`aria-haspopup="dialog"`)                                  |
| 로그인·함께 쓰는 중                                 | "카카오 계정에 저장 중" · [로그아웃]                                                                                 | "{n}명이 함께 쓰는 중" · [나가기] (`aria-label="함께 쓰기에서 나가기"`) |
| 계정 확인 실패(`/api/me` 500 + `session-hint` 있음) | "계정 상태를 확인하지 못했습니다" · [다시 시도]                                                                      | 없음                                                                    |

- 계정 확인 실패 경계: `session-hint` 없는 500은 지금처럼 로그아웃 모양(기존 `accountQa`)이다. [다시 시도]가 다시 실패하면 같은 줄이 그대로 남고, 성공하면 줄이 사라지고 로그인(또는 로그아웃) 모양이 된다.
- [로그아웃]은 작은 버튼(지금 목록 머리와 같은 크기). 보조기기 설명(`aria-describedby`, 화면에는 없음): U8 문구. **진행 중 비활성**(요청 1건). [나가기]도 같다.
- 로그아웃 응답별: 204 → 로그아웃 모양. **401은 사실상 로그아웃 성공**이라 로그아웃 모양으로 바꾸고 세션 만료 줄을 보인다. 500·네트워크 오류 → 로그아웃 실패 줄, 로그인 상태 유지, [로그아웃]은 그대로 있고 비활성이 아니다(다시 누르면 `POST`가 한 번 더 나간다).
- 홈 안내 줄(계정 자리 바로 아래, `role="status"`, `HeaderNotices`와 같은 규칙):
  - **결과 줄(동시에 하나)**: 로그인 결과(`?login=`, 한 번 잡고 `#/`로 replace) · "로그아웃하지 못했습니다. 연결을 확인하고 다시 시도해 주세요"(아직 로그인 상태일 때만) · "함께 쓰기에서 나왔습니다" · "함께 쓰기에서 나가지 못했습니다. 연결을 확인하고 다시 시도해 주세요". 로그아웃·나가기·[다시 시도]·시트 열기를 **시작하면 이전 결과 줄을 지운다**(예: 나가기 실패 뒤 재시도 성공 시 실패 줄 제거, 로그아웃 시작 시 나가기 결과 제거). 메모리 상태라 다른 탭을 다녀오면 사라진다(지금 저장 목록과 같음).
  - **상태에서 나오는 줄(상태가 풀리면 사라짐)**: "로그인이 끝났습니다. 다시 로그인해 주세요"(`listingSource`·`planSource`·홈 함께 쓰기 401 중 **어느 하나라도** 401이면 한 줄로 합쳐 보임) · 매물 이전 실패 + [다시 시도](`accountImportProblem`, 저장 목록과 같은 재시도) · 계정 확인 실패(위 표).
  - 순서: 결과 줄 → 상태에서 나오는 줄. 로그인 결과(`?login=`)와 세션 만료는 같이 뜨지 않는다(`?login=` 복귀 직후에는 401이 없다).
  - 계정 자리는 지금 규칙(`listingSource.status`, 출처가 401을 받으면 로그아웃으로 확정)을 따른다. `planSource`만 401이어도 안내는 한 줄 보이고, 계정 자리는 구현이 정한 대로 두되 측정해 테스트로 고정한다(A9).
- 포커스(ADR-035 조건 5): [로그아웃]·[나가기] **성공**으로 버튼이 사라지면, 시트가 열린 채 401이 나서 [함께 쓰기]가 사라지면, 포커스는 결과 줄 또는 상태 줄(`role="status"`, `tabIndex=-1`)로, 줄이 없으면 계정 자리 컨테이너(`tabIndex=-1`)로 옮긴다. 실패로 버튼이 남으면 그 버튼에 둔다. 시트를 여는 쪽은 `event.currentTarget`을 `sheet.open`에 넘긴다(ref 불필요).
- 함께 쓰기 시트: 지금 `HouseholdSheet` 그대로(혼자 → 초대 링크 만들기 → 복사·공유하기·끊기, 2명 → "이미 2명이 함께 쓰고 있습니다", 열린 채 세션이 끝나면 로그인 안내 본문). 시트가 열리면 홈 화면은 `inert`, 닫으면 [함께 쓰기]로 포커스가 돌아온다(위 401 갈래는 예외). 뒤로 가기는 시트만 닫는다(ADR-017 개정). `HouseholdSheet`의 "계정 상태를 확인하는 중입니다" 갈래는 홈에서 도달 조건이 없어 옮기며 지운다.
- 카드: 매물 카드 "함께 쓰는 목록 · 매물 n개"는 그대로(U9). 계산 카드 매매가는 `privacy-mode`가 켜져 있으면 지금처럼 `MaskedValue`로 가린다(읽기만). 우리 집 줄은 가리지 않는다. 나가기 뒤 카드 값은 다시 조회한 값이다. 그 사이에는 받아 둔 값이 보인다.
- 홈은 localStorage에 쓰지 않는다. 예외는 로그아웃·로그인 확인 결과의 `session-hint`뿐이다(기존 규칙).

### 저장 목록 (`#/listings`)

- 머리 줄 오른쪽: [가리기] [목록 공유](매물이 있을 때만, 지금 그대로). 나머지 버튼·`householdGroup`·`visuallyHidden` 로그아웃 설명은 지운다.
- 머리 줄 아래 안내(`HeaderNotices`): 계정 확인 실패 + [다시 시도], 세션 만료(+ [홈에서 로그인] 링크), 이전 문제 + [다시 시도], 알림(공유받은 매물 추가·함께 쓰기 수락·이전 완료), 쓰기 실패는 남긴다. 로그인 결과와 로그아웃 실패는 지운다.
- [가리기]에 보조기기 설명 한 줄(U7): "이 기기에서 저장 목록의 금액과 메모를 가립니다". 버튼 이름 "가리기"는 그대로다(토글 규칙).

### 우리 집 (`#/home…`)

- 계획 머리글: 이름 · 연결 매물 줄 · [⋯]. [가리기] 없음.
- `privacy-mode`가 켜져 있어도 목록 줄(세부내용·업체·견적·확정 체크 이름 전체)·요약(총 예산·지출 예정·남은 예산·초과·미정 n건)·표(머리·칸·계·비고)가 모두 보이고, 표 보기 안내는 늘 "내려받기·인쇄가 안 되면 Safari·Chrome에서 열어 주세요"(항목이 있을 때), CSV·인쇄 버튼은 항목이 있으면 활성, 줄을 누르면 시트가 열린다.
- "로그인이 끝났습니다" 안내(HomeNotices)에 [홈에서 로그인] 링크가 붙는다. 그 밖의 안내는 그대로다.

### 초대 화면 (`#/invite/…`, 문구만)

- "저장 목록에서 [나가기]로 나간 뒤 이 링크를 다시 열어 주세요" → "홈에서 [나가기]로…", 저장 목록으로 가던 링크 두 곳은 홈으로. 그 밖의 흐름·문구는 그대로다(인테리어 계획 안내는 알려진 갭).

### 반복 사용 불편 방지

- 계정 일은 어느 화면에서든 [홈] 탭 한 번이다. 로그인을 마치면 시작한 홈으로 돌아온다(D1 A). 예전에는 저장 목록으로 갔다.
- 저장 목록·우리 집에서 세션이 끝나면 그 화면 안내가 이유를 알리고 [홈에서 로그인] 링크로 바로 갈 수 있다(U4). 쓰던 메모·이름을 목록 위에 남기는 지금 규칙은 그대로다.
- 나가기·로그아웃 결과는 누른 자리 바로 아래(계정 자리 밑)에 보인다. 결과를 놓치는 일을 줄이려고 성공해서 버튼이 사라져도 포커스가 결과 줄로 간다.
- 가리기는 저장 목록에서만 켜고 끈다. 우리 집에 가면 값이 그대로 보이고, 홈은 계산 카드 매매가만 가려진 채 읽는다. 화면마다 따로 가려졌다 풀렸다 하지 않는다.
- 첫 로그인 착지에는 `session-hint`가 아직 없어 확인 중 자리표시자가 로그인 안내 모양(약 2줄+링크)으로 예측되고, 확인되면 두 행으로 줄어 카드가 밀릴 수 있다(지금도 있는 한계, 로그인 후 늘 홈에 착지하므로 더 자주 보임). 리드 화면 확인 항목에 넣는다.

## 가정

- A1: "함께 쓰는 중 표시를 홈으로 옮긴다"는 **옮기기**다. 저장 목록 머리의 표시는 남기지 않는다(U3). 저장 목록에서 함께 쓰는 중임을 모르고 지우는 일이 생기면 읽기 전용 표시를 되살린다(ADR-035 뒤집을 조건).
- A2: "가리기는 목록에만"은 저장 목록 **토글**을 뜻한다. 우리 집은 토글만이 아니라 가림 자체를 없앤다. 버튼만 없애고 가림은 저장 목록 설정을 따르게 하면, 우리 집에서 가려진 값을 풀 방법이 없어진다. 가리기는 원래 임장 중 저장 목록을 옆 사람에게서 숨기려고 만들었다(log "가리기 모드"). 홈은 첫 화면이라 옆 사람에게 가장 먼저 보이므로 계산 카드 매매가의 읽기 전용 가림은 유지하고, 우리 집 줄은 우리 집 화면과 같게 가리지 않는다.
- A3: 초대 링크로 시작한 로그인의 **성공**은 지금처럼 초대 화면으로 돌아온다. 초대로 시작한 로그인의 취소·실패는 홈(`#/?login=…`)으로 간다(초대 토큰은 버려짐, 지금은 저장 목록이었음). 공유받기 화면의 [카카오로 로그인](초대 쿠키 없음)은 성공하면 홈으로 돌아온다(지금은 저장 목록). 공유받은 매물은 로그인 뒤 다시 링크를 열어 추가한다(지금도 공유 화면으로 돌아오지 않는다). 대응 AC: AC-2.
- A4: 로그인 성공에는 안내 줄이 없다(지금과 같음). 계정 자리가 "카카오 계정에 저장 중"으로 바뀌는 것이 결과 표시다. 대응 AC: AC-2(`#/`에서 안내 없음)·AC-1.
- A5: 저장 목록·우리 집의 세션 만료·이전 문제·쓰기 실패 안내는 그 화면의 데이터와 [다시 시도]에 묶여 있어 그대로 둔다. 로그인 착지가 홈이 되어 이전 실패가 숨는 회귀를 막으려고 홈에도 매물 이전 실패 + [다시 시도]를 더한다(재시도는 같은 이전 훅).
- A6: 홈의 401 안내는 `platform-home` AC-7(c)("오류 문구 없음")를 바꾼다. 카드에는 여전히 오류 문구가 없고 계정 자리 아래 한 줄만 생긴다. 홈이 [함께 쓰기]·[나가기]를 갖게 되어, 왜 로그인 안내로 바뀌었는지 알려야 한다.
- A7: 2명 상한·초대 7일·한 번 쓰기 규칙은 그대로다(ADR-028). 인테리어 계획도 매물과 같은 가구 범위다. 수락하면 받은 사람의 원래 계획은 숨겨지고, 나가면 돌아온다(ADR-029 D4 A).
- A8: 홈 안내 줄은 결과 줄 하나와 상태에서 나오는 줄(세션 만료·계정 확인 실패·이전 실패)로 나뉜다. 새 동작(로그아웃·나가기·[다시 시도]·시트 열기)을 시작하면 이전 결과 줄을 지운다. 대응 AC: AC-1.
- A9: 홈 세션 만료 줄은 `listingSource`·`planSource`·홈 함께 쓰기 중 어느 하나라도 401이면 한 줄로 보인다. 계정 자리는 지금 규칙(`listingSource.status`)을 따르며 `planSource`만 401인 경우의 모양은 구현이 측정해 테스트로 고정한다. 대응 AC: AC-1.
- A10: 로그아웃 요청이 401이면 세션이 이미 끝난 것이므로 로그아웃 성공으로 보고 세션 만료 줄을 보인다. 네트워크 오류·500이면 실패 줄을 보이고 로그인 상태를 유지한다. 대응 AC: AC-1.

제품 목표가 갈리는 항목은 없다. 아래는 쓰는 경험을 좌우하는 **제품 기본값(사용자 확인 전 기본값)**이다. 답이 오기 전에는 이 값으로 진행한다.

- **U1 홈 계정 자리 모양**: 첫 줄 "카카오 계정에 저장 중 · [로그아웃]", 둘째 줄 [함께 쓰기] 또는 "2명이 함께 쓰는 중 · [나가기]"(카드 위). 대안: 한 줄에 "카카오 계정 · 2명이 함께 쓰는 중 [나가기] [로그아웃]". 360px에서 버튼 셋이 빠듯하다.
- **U2 로그아웃 상태 이유 문구·[함께 쓰기]**: "로그인하면 저장 목록·인테리어 계획을 여러 기기에서 보고, 다른 사람과 함께 쓸 수 있어요" + 넓은 로그인 하나. 로그아웃이면 [함께 쓰기]는 보이지 않는다. 대안: [함께 쓰기]도 보이고 누르면 로그인 안내 시트(지금 저장 목록 동작).
- **U3 저장 목록에 함께 쓰는 중 표시 없음**: 로그인·로그아웃·함께 쓰기·"함께 쓰는 중"·나가기를 모두 뺀다. 대안: 읽기 전용 "함께 쓰는 중" 표시만 남긴다(누르면 홈). 저장 목록에서 고치는 것이 상대에게도 보인다는 단서가 사라지는 비용이 있다.
- **U4 다른 화면의 세션 만료**: 안내 문구 "로그인이 끝났습니다. 다시 로그인해 주세요"에 **"홈에서 로그인" 링크**를 붙인다(누르면 홈). 대안: 링크 없는 문구만 / 안내 줄에 작은 [카카오로 로그인] 직접 링크(어차피 홈으로 돌아오므로 이득이 적다).
- **U5 알림 자리**: 홈은 로그인 결과·로그아웃 실패·나가기 결과·나가기 실패·홈에서 끝난 세션·계정 확인 실패에 더해 **매물 이전 실패 + [다시 시도]**를 보인다. 저장 목록·우리 집은 이전 완료·실패, 그 화면의 세션 만료·쓰기 실패를 보인다(지금 그대로). 이전 완료 알림은 홈에 두지 않는다.
- **U6 가리기 범위**: 토글은 저장 목록에만 둔다. **우리 집은 가림이 없다**(목록·표·요약·내보내기). **홈은 계산 카드 매매가만 지금처럼 가리고**, 우리 집 줄은 가리지 않는다. 대안 ① 홈에서도 가리지 않음(노출 확대, D3 A) ② 우리 집은 버튼만 없애고 저장 목록 설정을 따름(우리 집에서 풀 방법이 없어 비추천).
- **U7 [가리기] 영향 범위 문구**: 화면에는 더 쓰지 않는다. 보조기기 설명만 "이 기기에서 저장 목록의 금액과 메모를 가립니다". 대안: 켰을 때 머리 줄 아래 작은 한 줄 "금액·메모를 가리는 중"을 보인다.
- **U8 문구**:
  - 함께 쓰기 시트(혼자): "초대 링크를 받은 사람이 카카오로 로그인해 수락하면 저장 목록과 인테리어 계획을 함께 씁니다." / "받은 사람의 원래 목록·인테리어 계획은 숨겨지고 내 목록·예산·순서·인테리어 계획을 함께 씁니다. 둘 다 보고 고치고 지울 수 있습니다. 새로 만들면 전에 만든 초대 링크는 끊깁니다."
  - 초대 결과 안내: "7일 동안 한 번 쓸 수 있습니다. 받은 사람이 카카오로 로그인해 수락하면 같은 목록과 인테리어 계획을 함께 씁니다. 이 창을 닫으면 링크를 다시 볼 수 없어요."
  - 나가기 확인: 지금 문구 그대로(인테리어 계획 문장이 이미 있다).
  - 로그아웃 설명(보조기기): "로그아웃하면 이 기기에 있던 저장 목록·인테리어 계획으로 돌아갑니다".
  - 옮긴 기능을 가리키는 기존 문구(조건 4): 초대 화면 "홈에서 [나가기]로 나간 뒤 이 링크를 다시 열어 주세요", 이전 문제 안내 "홈에서 로그아웃하면 손상된 원문을 복사할 수 있습니다" 꼴.
