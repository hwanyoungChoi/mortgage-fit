# 우리 집 — 줄마다 "예산에 반영 / 예산 외" 고르기

> 작성 2026-11-06 · 브랜치 `cony/purchase-budget-toggle` · 상태: **D1 결정됨**([ADR-038](../decisions/038-off-budget-item.md): A, 1단계 배포), 제품 기본값 U1~U9는 사용자 확인 전(답이 오기 전에는 제안 기본값으로 진행)
> 관련: ADR-038 · ADR-007(합계는 저장하지 않고 계산) · 012(선택 필드 = 키 없음) · **029 조건 2(검증은 알려진 키만 복사 = 옛 번들은 모르는 키를 버림)** · 033·036(필수 → 선택 완화만 2단계 배포) · 034(금액을 원으로 읽는 곳은 `interiorPlanRows.ts` 하나) · `.cony/log.md` 749~756행(구매 완료 = [완료] 체크, 저장 형식 변경 없이 `status: "done"`) · 스펙 `interior-vendor-tbd-line-order.md`(형식) · `interior-tbd-amount.md`("금액 미정 n건 제외" 패턴)
> 검토 원문: [fe](../reviews/20261106-1025-fe-spec-interior-budget-exclude.md) · [be](../reviews/20261106-1025-be-spec-interior-budget-exclude.md) · [qa](../reviews/20261106-1025-qa-spec-interior-budget-exclude.md) (조건 반영 완료)

## 목표

예산과 상관없는 돈(따로 모은 돈, 부모님 지원 등)으로 산 줄을 "예산 외"로 표시하면, 그 줄은 목록에 그대로 남지만 남은 예산·지출 예정·지출 완료·예산 초과 계산에서 빠진다. 기록은 한곳에 두고, 예산 숫자만 실제 예산 기준으로 맞춘다.

요청 원문(함께 쓰는 사람, 카톡): "뽀야가 만들어준거 그거 구매 완료한거 / 예산에 반영/미반영 / 선택하게 못하낭 / 걍 예산 외에서 구매한 것들도 있는딩"

## 지금 코드에서 확인한 것

- **"구매 완료"** = 목록 줄 오른쪽의 [완료] 체크(원 안 "완")다. 저장 형식은 새로 만들지 않았고 항목 `status: "done"`을 쓴다. 완료 줄 = **확정 줄이면서 항목 상태가 "done"**인 줄이다(`interiorPlanRows.ts` `isDone`, 미확정 줄의 done은 무시). [완료]를 켜면 그 견적을 확정도 하고, 확정을 끄거나 다른 견적으로 옮기면 "planned"로 풀린다(`interiorLineWrites.ts` `toggleLineDoneInput`·`withStatusAfterConfirm`). 지급(`payments[].isPaid`)은 화면에서 쓰지 않는다.
- **합계는 한 곳에서 계산한다**(`src/lib/utils/interiorPlanRows.ts` `buildInteriorPlanRows`):
  - 지출 예정 = Σ(확정 · 완료 아님 · 금액 있음)
  - 지출 완료 = Σ(완료 · 금액 있음)
  - 금액 미정 n건 = 확정이고 금액 없는 줄 수
  - 남은 예산 = 총 예산 − 지출 예정 − 지출 완료. 음수면 "예산 초과 n원"이다(`summarizeInteriorPlan`)
  - 묶음 합계 = Σ(확정 · 금액 있음, 완료 포함)(`groupConfirmedWonOf`). 묶음 합계를 다 더하면 지출 예정 + 지출 완료다(log 777행)
- **그 결과를 쓰는 곳**:
  - 요약 `PlanSummary.tsx`(남은 예산 큰 숫자, 막대, 지출 예정, 지출 완료, "금액 미정 n건 제외"). 지출 완료 행은 지금 `doneCount > 0`일 때 그린다
  - 표 머리 `interiorPlanExportText.ts`(화면·인쇄). 지출 완료 조각은 `doneCount === 0`이면 뺀다
  - 표 모델 `buildInteriorPlanTable.ts`(확정·완료 칸, "계" = 지출 예정 + 지출 완료, 계 비고). 완료 열과 계 완료 칸은 `doneCount === 0`이면 없다
  - CSV `interiorPlanTableToCsvRows.ts`
  - 홈 카드 `summarizeHub.ts` → `MortgageHub.tsx`("지출 예정 n원", 꼬리 "완료 n원 · 미정 n건"). 꼬리의 완료는 `doneTotalWon > 0`일 때만 그린다
  - 묶음 제목 합계 `GroupHeader`
- 그래서 **예산 외 판정을 `buildInteriorPlanRows` 한 곳에 넣으면** 요약·남은 예산·초과·막대·표 "계"·홈 카드가 함께 바뀐다. 표시(줄 표시, "예산 외 n원", 비고)만 따로 더한다.
- **옛 번들은 모르는 키를 버린다**: `validateInteriorItemFields`는 알려진 키만 새 객체로 돌려준다(ADR-029 조건 2). 그래서 새 선택 키를 더해도 옛 탭이 손상(corrupt)으로 읽지 않는다. ADR-033·036의 2단계 배포는 필수 → 선택 **완화**에 필요했던 것이고, 이번 변경은 새 선택 키 **추가**라 해당하지 않는다(ADR-038, 아래 "배포").
- **줄 쓰기는 항목 전체를 다시 보낸다**: 확정·완료 토글, 시트 저장, n≥2 항목의 견적 삭제는 `inputOf(item)`(id·시각만 뺀 항목 그대로)에서 시작하고, 서버 PUT은 항목 전체를 바꾼다. 검증이 새 키를 돌려주기만 하면 기존 쓰기 경로는 코드 변경 없이 새 키를 보존한다. 반대로 검증이 키를 빠뜨리면 모든 쓰기에서 조용히 사라진다(AC-2·AC-4가 지킨다).

## 사용자 시나리오

1. (예산 외로 바꾸기) 부모님이 사 주신 "주방 · 냉장고 2,500,000원" 줄을 열어 [예산에 반영] 체크를 끄고 저장하면, 목록 그 줄 금액 옆에 "예산 외"가 붙는다. 남은 예산은 2,500,000원 늘고, 요약 아래에 "예산 외 2,500,000원"이 보인다.
2. (구매 완료와 함께) 그 줄의 [완료]를 켜도 지출 완료에 더해지지 않는다. 줄은 지금처럼 회색(완료) 배경이다.
3. (되돌리기) 다시 열어 [예산에 반영]을 켜면 원래 합계로 돌아온다.
4. (함께 보기) 함께 쓰는 사람 휴대폰에서도 다음 재조회(30초 안)에 같은 남은 예산·같은 "예산 외" 표시가 보인다.
5. (내보내기) [표]·인쇄·CSV에서 그 줄 비고에 "예산 외"가 있고, "계"와 표 머리의 남은 예산은 예산 반영분만 센다.
6. (기존 계획) 이 기능을 쓰지 않은 계획은 화면·표·CSV·홈 카드가 한 글자도 바뀌지 않는다.

## 참고한 사례

- **Monarch Money "Hide transaction"**: 거래 하나의 상세 화면에서 토글로 숨기면 그 거래가 예산·현금흐름 계산에서 빠진다. 지워지지 않고 필터로 다시 찾을 수 있다. 계좌 전체를 예산에서 빼는 설정은 따로 있다. → **기록은 남기고 예산 계산에서만 빼는** 거래(줄) 단위 토글이다. 토글은 목록이 아니라 상세(우리 줄 시트)에 둔다. https://help.monarch.com/hc/en-us/articles/4405041904916 · https://help.monarch.com/hc/en-us/articles/4407859794580
- **YNAB tracking(off-budget) 계좌**: 예산 밖의 돈은 계좌 단위로 "예산 외(off-budget)"로 두고, 그 거래는 카테고리 잔액(예산)에 영향을 주지 않는다. 순자산에는 그대로 보인다. → "예산 외"라는 말과 "합계에는 빠지지만 기록은 보인다"는 모양을 가져온다. 계좌 개념이 없는 우리 앱에서는 줄 단위가 가장 가깝다. https://www.ynab.com/the-ynab-dictionary-for-budgeting

- 뱅크샐러드·토스: 거래를 예산 계산에서 빼는 설정은 공개 도움말·검색으로 확인하지 못했다(지어내지 않음). 뱅크샐러드는 예산·고정비 설정과 엑셀 내보내기만 확인했다. https://www.banksalad.com/articles/가계부어플-추천-쓰는법-돈관리
- **우리 코드의 같은 모양**:
  - "금액 미정 n건 제외"(ADR-033): 합계에서 빠진 것을 요약·표 머리·계 비고에 한 줄로 알린다. 이번 "예산 외 n원"도 같은 자리, 같은 방식이다.
  - [완료] 열(log 754행): 쓰는 줄이 있을 때만 보인다. 이번에도 예산 외 줄이 없으면 아무것도 보이지 않는다.

## 데이터 모델

### 저장 형식 (ADR-038: A)

- `InteriorItem.isOffBudget?: true`. **키 없음 = 예산에 반영**(ADR-012). 이미 저장된 모든 계획은 키가 없으므로 그대로 "반영"으로 읽는다. 읽기 호환 코드는 따로 필요 없다.
- 검증(`validateInteriorItemFields`, 로컬 읽기·서버 경계·로그인 이전 공통). **`parseOptional`은 `false`를 거부하므로 재사용하지 않고, 작은 전용 판정 함수 하나(순수)로 쓴다**:
  - `true` → 돌려주는 객체에 `isOffBudget: true`
  - `false` → **받되 키를 쓰지 않는다**(빈 문자열·빈 배열을 받아 키를 빼는 ADR-012 규칙과 같다. 저장 표현은 "키 없음" 하나)
  - 키 없음·`undefined` → 키 없음
  - `null`·`"true"`·`"false"`·`1`·`0`·`[]`·`{}`·그 밖 모두 → 항목이 올바르지 않다(로컬은 ADR-001대로 계획 전체 corrupt, 서버는 400)
  - 반환 객체의 키 위치는 `...(isOffBudget && { isOffBudget: true })` 꼴로 써서 `false`가 객체에 새지 않게 한다(AC-2의 `SELECT data`가 지킨다)
- 한 항목에 하나다. 확정 견적은 항목당 하나라서, 이 키는 "그 항목의 확정 견적 금액을 예산에 넣는가"를 뜻한다. 견적 n≥2 옛 항목도 같다(형제 줄이 같은 값을 쓰고, 시트의 "같이 씁니다" 안내에 더한다).
- 확정을 끄거나 다른 견적으로 옮겨도 이 키는 그대로 둔다. 미확정 줄은 원래 합계에 들어가지 않으므로 영향이 없고, 다시 확정하면 고른 값이 살아 있다.
- 타입: `InteriorItem`에 `isOffBudget?: true`. `InteriorItemInput`은 `Omit`이라 따라온다(서버 `parseInteriorPlanRequests.ts` 타입이 따라오는지 `pnpm build`의 worker 타입 검사로 확인). API 봉투·경로는 그대로다.

### 계산 (저장하지 않음, ADR-007)

`buildInteriorPlanRows` 한 곳에서:

- `InteriorPlanRow.isOffBudget: boolean` = `item.isOffBudget === true`. 목록 표시와 표 비고가 이 값을 쓴다. 확정 여부와 상관없이 true일 수 있다(미확정 줄 표시는 U9).
- 지출 예정 = Σ(확정 · 완료 아님 · **예산 외 아님** · 금액 있음)
- 지출 완료 = Σ(완료 · **예산 외 아님** · 금액 있음)
- 새 `offBudgetTotalWon` = Σ(확정 · **예산 외** · 금액 있음, 완료 포함). 새 `offBudgetCount` = 그 줄 수. 0이면 화면 어디에도 "예산 외 n원"을 그리지 않는다. **미확정 줄은 두 값에 들어가지 않는다.**
- `tbdCount`("금액 미정 n건 제외")는 예산 외 줄을 세지 않는다. 예산에 들어갈 돈이 아니므로 A3.
- `doneCount`는 그대로 모든 [완료] 줄을 센다. **표의 완료 열이 생기는 조건과 표 머리의 지출 완료 조각 조건(`doneCount`)을 바꾸지 않으려는 것이다.** 판정 기준은 아래 "화면 > 요약", "표·인쇄·CSV"에 값으로 적었다(A4).
- 남은 예산 = 총 예산 − 지출 예정 − 지출 완료(식 그대로). 예산 외는 위 두 값에서 이미 빠졌다. 예산 막대도 같은 값을 쓴다.
- 묶음 합계(`groupConfirmedWonOf`) = Σ(확정 · 예산 외 아님 · 금액 있음)(U6). "묶음 합계의 합 = 지출 예정 + 지출 완료" 불변식을 유지한다.
- `InteriorPlanSummary`에 `offBudgetTotalWon`·`offBudgetCount`를 더하고, `summarizeHub`는 지금 쓰는 값만 계속 쓴다.

### 쓰기

- 시트: `InteriorLineDraft.isOnBudget: boolean`(체크 상태, 새 줄 기본 `true`), `InteriorLineValues.isOnBudget: boolean`.
- `addLineInput`·`editLineInput`: 반영이면 키를 쓰지 않는다. 예산 외면 `isOffBudget: true`. **반영으로 바꿀 때는 구조 분해로 키를 지운다**(`false`를 남기지 않는다. `withMemo`와 같은 방식).
- 확정·완료 토글과 견적 삭제는 `inputOf(item)`가 키를 그대로 옮긴다. 코드 변경은 없고 테스트로만 확인한다.

### 배포 (1번, 게이트 없음, ADR-038)

- **한 번 배포로 충분하다.** 서버와 번들은 한 번의 Workers 배포로 함께 바뀐다(interior-vendor-tbd-line-order A4). 바뀌는 검증은 "새 선택 키를 받아 돌려준다"뿐이고, 기존 값의 해석을 좁히거나 넓히지 않는다.
  - 옛 번들 탭은 `isOffBudget`을 모르는 키로 버린다. 손상 판정은 없다. 그 탭은 예산 외 줄도 반영으로 계산해 보일 뿐이다.
- **남는 위험(데이터 손실이 아니라 표시가 조용히 되돌아감)**: 키가 지워져 줄이 다시 예산에 들어가는 경우다. 금액·견적은 잃지 않는다.
  - 로그인 옛 탭: 배포 전에 열어 둔 탭에서 그 항목을 쓰면(확정·완료 토글, 시트 저장) 항목 PUT 본문에 키가 없어 서버에서 지워진다.
  - 로그아웃 옛 탭: 아무 쓰기나 하면 `interior-plans` 원문을 다시 써서 그 기기 모든 항목의 키가 지워진다.
  - **함께 쓰는 중 오래된 캐시**: 한 기기가 예산 외로 바꾸는 사이 다른 기기가 오래된 캐시로 같은 항목에 [완료] 등을 누르면, 그 PUT(항목 전체 교체, 409 없음, ADR-029 조건 8)이 키를 지워 반영으로 되돌릴 수 있다. 새 위험이 아니라 기존 모든 필드와 같은 성질이다.
- **대응은 한 줄이다**: 배포 보고에 "두 분 다 우리 집 탭을 한 번 새로고침해 주세요"를 넣는다. 머지 게이트·대기·qa 증거 절차는 두지 않는다(사용자 두 명, 위험은 체크 하나 다시 끄기 수준). 테스트로 막을 수 없는 항목이라 사람 확인으로 둔다.
- 롤백: revert는 안전하다. 되돌린 번들은 키를 버리고 반영으로 계산한다. 서버 D1의 키는 그 항목을 쓰기 전까지 남아 있다.
- 마이그레이션 없음(JSON `data` 컬럼), 새 localStorage 키 없음, 새 환경변수 없음, 서버 코드 diff 0(공용 검증만 바뀐다).

## API 계약

경로·봉투·오류 모양은 그대로다. 항목을 담는 모든 경로에 선택 키 하나가 더해진다.

| Method | Path                                      | Request                                                        | Response                                                      | 에러                                |
| ------ | ----------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------- | ----------------------------------- |
| GET    | `/api/interior-plans`                     | —                                                              | 예산 외 항목에는 `isOffBudget: true`. 반영 항목에는 키가 없다 | 그대로                              |
| POST   | `/api/interior-plans/{id}/items`          | `item.isOffBudget?: true \| false`(`false` = 키 없음으로 저장) | 201 `{ item }`(키는 `true`일 때만)                            | 400: `true`·`false`·없음 외 모든 값 |
| PUT    | `/api/interior-plans/{id}/items/{itemId}` | 위와 같음. 항목 전체 교체라 키를 빼고 보내면 반영으로 바뀐다   | 200 `{ item }`                                                | 400: 위와 같음                      |
| POST   | `/api/interior-plans`                     | `items[].isOffBudget?`                                         | 201                                                           | 400: 위와 같음                      |

## 화면

### 줄 시트 (U3)

- [확정] 아래에 체크 **[예산에 반영]**을 둔다. 새 줄은 켜져 있고, 예산 외 줄을 열면 꺼져 있다. 끄고 저장하면 예산 외다.
- 칸 순서: 구분 → 세부내용 → 업체 → 견적 → 일정 → 비고 → 확정 → **예산에 반영**.
- 확정 여부와 상관없이 언제나 보이고 바꿀 수 있다(U2). 미확정 줄에서는 합계에 영향이 없다.
- 체크 아래 설명 한 줄: "끄면 남은 예산·지출 합계에서 빠지고 따로 '예산 외'로 보입니다".
- 체크만 바꿔도 "고친 것"이다([저장] 활성, 닫을 때 확인. `isSameLineDraft`가 draft 키 전체를 비교하므로 `isOnBudget`을 draft에 더하면 따라온다). 견적 n≥2 옛 항목 안내(`ItemSheet.tsx` 329행 근처)는 "구분·일정·비고·확정·예산 반영을 같이 씁니다"로 바꾼다.

### 목록 줄 (U4, U9)

- 예산 외 줄은 금액 옆(또는 둘째 줄 끝)에 작은 흐린 글자 **"예산 외"**를 붙인다. 색만으로 구분하지 않고 글자로 보인다.
- **미확정 줄에도 붙인다(제안 기본값, U9)**: `row.isOffBudget`만으로 그린다. 미리 표시해 둔 줄이 목록에서 보이고 시트 설명과 같다. 이때 미확정 줄의 "예산 외"는 요약의 "예산 외 n원"에 들어가지 않는다(합계는 확정 줄만).
- 줄 배경(확정 = 옅은 코발트, 완료 = 회색)과 [확]·[완] 체크는 그대로다.
- 접근 가능한 이름 끝에 "예산 외"를 더한다(예: "욕실 하루바스 타일 덧방 (2) 예산 외 열기").
- 360px에서 금액과 "예산 외"가 줄바꿈 없이 들어가는지 확인한다. 안 들어가면 둘째 줄 끝으로 보낸다.

### 요약 (U5, U8)

- 남은 예산·막대·지출 예정·지출 완료는 예산 반영분만 센다.
- **지출 완료 행은 홈 카드 꼬리와 같게 `doneTotalWon > 0`일 때만 그린다(U8).** 예산 외 줄만 [완료]인 계획에서 요약에 "지출 완료 0원"이 보이지 않는다(홈과 같다). 이 조건 변경으로 "완료이지만 금액 미정"만 있는 계획의 요약에서도 "지출 완료 0원" 행이 사라지므로, 기존 골든·화면에 그런 fixture가 있으면 qa가 먼저 알린다(그 경우 U8을 사용자에게 다시 묻는다).
- 예산 외 확정 줄이 하나 이상(`offBudgetCount > 0`)이면 요약 아래(지출 완료·총 예산 줄 옆, "금액 미정 n건 제외"와 같은 작은 글자 크기)에 **"예산 외 n원"** 한 줄을 둔다. 막대에는 그리지 않는다.
- **총 예산이 없는 상태(`budgetWon` null, `renderRemaining`의 별도 분기)에서도 `offBudgetCount > 0`이면 같은 한 줄을 그린다.**
- 홈 카드는 모양 그대로다("지출 예정 n원 · 완료 n원 · 미정 n건"). 값만 예산 반영분으로 바뀐다.

### 묶음 제목 합계 (U6)

- 예산 반영 확정 줄만 더한다. 그런 줄이 없는 묶음은 지금처럼 합계를 그리지 않는다.

### 표·인쇄·CSV (U7)

- 줄: 확정·완료 칸은 **금액 그대로**다(사실상 확정·구매한 줄이다). 비고에 "예산 외" 조각을 더한다(`rowNoteOf`, 항목 메모 뒤 " · "로 잇는다). 미확정 줄도 `row.isOffBudget`이면 비고에 "예산 외"가 붙는다(U9와 같은 기준).
- 계: 확정 칸 = 지출 예정 + 지출 완료, 완료 칸 = 지출 완료(둘 다 예산 반영분). 계 비고에 **"예산 외 n원 제외"**를 더한다. **"금액 미정 n건 제외"가 있으면 그 뒤에 " · "로 잇는다**(순서: 금액 미정 먼저, 예산 외 나중. 예: `금액 미정 1건 제외 · 예산 외 2,500,000원 제외`).
  - 그래서 엑셀에서 확정 열을 직접 SUM하면 "계"보다 예산 외만큼 크다. 계 비고가 그 차이를 설명한다(U7 대안 B는 이 차이를 없앤다).
- **예산 외 줄만 [완료]인 계획**: 완료 열은 `doneCount > 0`이라 그대로 생기고, "계" 완료 칸은 **0**(빈칸이 아니다)이다. 표 머리(화면·인쇄)의 "지출 완료 0원" 조각도 `doneCount` 조건 그대로 보인다. 표는 줄의 완료 칸 금액을 그대로 보여 주므로 완료 열이 있는 것이 맞고, 요약만 U8에 따라 행을 생략한다.
- 표 머리(화면·인쇄): 지출 완료 뒤에 "예산 외 n원" 조각(`offBudgetCount > 0`일 때만).
- 문구 상수 `INTERIOR_PLAN_OFF_BUDGET_LABEL = "예산 외"`와 `offBudgetExclusionNote(won)`는 `lib/constants/interiorPlanTable.ts`·`interiorPlanRows.ts`에 둔다(`tbdExclusionNote` 옆). 목록·요약·표·CSV가 같은 글자를 쓴다.

### 반복 사용 불편 방지

- 줄을 열지 않아도 목록에서 예산 외인지 보인다("예산 외" 글자).
- 체크 하나만 바꿔 저장해도 줄 위치·스크롤·다른 칸은 그대로다.
- 저장 실패 안내는 지금 시트 저장 실패와 같은 자리다.

## 가정

- A1: "구매 완료한 것"은 [완료] 체크 줄을 뜻하지만, 같은 돈이 확정 단계(지출 예정)에서도 남은 예산을 깎는다. 그래서 예산 외는 확정 줄 전체(지출 예정·지출 완료 둘 다)에 적용한다(U2).
- A2: 예산 외인지는 "어떤 돈으로 사는가"라 항목(줄)의 성질이다. 견적을 바꿔 확정해도 그대로 둔다.
- A3: 금액 미정 + 확정 + 예산 외인 줄은 예산 계산에 들어갈 일이 없으므로 "금액 미정 n건 제외"에 세지 않는다.
- A4: 예산 외 줄만 [완료]인 계획에서 요약은 지출 완료 행을 생략하고(U8), 표는 완료 열이 있어 계 완료 칸 0·표 머리 "지출 완료 0원"이 나온다. 완료 열 조건(`doneCount`)을 그대로 두기 위해 받아들인다.
- A5: 서버와 번들은 한 번의 배포로 함께 바뀐다. 옛 탭·오래된 캐시 위험은 키가 지워져 반영으로 돌아가는 것뿐이고, 새로고침 요청 한 줄로 충분하다(사용자 두 명).
- A6: 홈 카드·묶음 합계·표 "계"의 값은 예산 반영분이다. "예산"이라는 말이 붙은 숫자는 모두 같은 기준이다.

- **U4 목록 표시**: **금액 옆 작은 흐린 글자 "예산 외"**. 줄 배경 색은 그대로다.

- **U5 합계 표시**: **남은 예산·지출 예정·지출 완료·예산 막대에서 빼고, 요약 아래 "예산 외 n원" 한 줄을 따로 보인다**(예산 외 확정 줄이 있을 때만, 총 예산이 없어도). 홈 카드는 모양 그대로다.

  - 대안: 예산 외 줄도 더한다(묶음에 실제로 쓴 돈 전체).
- **U7 표·인쇄·CSV(엑셀)**: **줄의 확정·완료 칸은 금액 그대로 + 비고 "예산 외", "계"는 예산 반영분만 + 계 비고 "예산 외 n원 제외", 표 머리에 "예산 외 n원"**. 엑셀에서 확정 열을 직접 SUM하면 계보다 예산 외만큼 크다.

- **U8 요약 "지출 완료" 행 노출 조건**(fe 검토 조건): **홈 카드 꼬리와 같게 `doneTotalWon > 0`일 때만 그린다.** 예산 외 줄만 완료인 계획에서 요약에 "지출 완료 0원"이 안 보인다. 표의 완료 열·표 머리는 줄에 금액이 보이므로 지금처럼 `doneCount` 기준이다.

- **U9 미확정 줄의 "예산 외" 글자**(fe 추천): **확정 여부와 상관없이 `isOffBudget`이면 목록 줄(과 표 비고)에 "예산 외"를 붙인다.** 시트 설명과 같고 미리 표시해 둔 줄이 보인다. 요약의 "예산 외 n원"에는 확정 줄만 들어간다.
  - 대안: 확정 줄에만 붙인다(글자가 보이면 합계에서 빠진 줄이라는 뜻이 되어 요약과 항상 맞는다).
