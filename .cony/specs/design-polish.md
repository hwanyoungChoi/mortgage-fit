# 디자인 전반 다듬기: 수치와 제목이 구분되어 보이게

> 작성 2026-11-11 · 브랜치 `cony/design-polish` · 상태: 검토 반영(fe·qa 조건부 찬성, D1 결정됨)
> 관련: 스펙 `ui-refresh.md`(토큰·컴포넌트 규칙의 출발점) · `.cony/log.md` 2026-10-31 "창피하지 않게", 2026-11-01 묶음 제목만 키움, 2026-11-03 화면 다듬기(11-04 확정), 2026-11-05 떠 있는 알약 탭(확정), 2026-11-07 다크 모드·해·달 토글 · `src/index.css`(토큰) · `src/lib/constants/textSize.ts`(기본 글자 크기 = `smaller`) · ADR-040(라벨·값 패턴 공유 = 토큰 + 주석)

## 요청(원문)

- "디자인좀 개선하자 전반적으로 / 세련되게.. / 명확하게 수치 타이틀 이런거 구분되어 보이게도 해주공 흑"

## 목표

화면을 한눈에 봤을 때 **제목(무엇인지)**과 **수치(얼마인지)**가 크기·굵기·색으로 바로 갈라져 보이게 한다. 글자 크기를 정해진 몇 단계로 묶고 간격 리듬을 맞춰, 같은 화면에서 들쭉날쭉한 1px 차이를 없앤다. 기능·계산·문구·저장 형식은 그대로다.

**구분 규칙(이 스펙의 핵심)**: 라벨(또는 제목)과 그 옆·아래 값 사이는 항상 2단계 이상 갈린다. 즉 **크기 차 3px 이상**이거나, 크기·굵기·색이 모두 다르다. 새 스케일에서 인접한 역할이 1px씩 붙지 않게 숫자를 정했다(아래 표).

## 뒤집지 않는 것(사용자가 이미 확정)

먹색 버튼·고른 칸, 코발트는 돈 데이터에만(남은 예산·예상 한도 숫자, 예산 막대, 확정 표시), 홈 기능 한 장 면, 새 로고, 떠 있는 알약 탭(아이콘 없음, 선택 탭 회색 알약 + 먹색 800)과 [+] 자리, 목록·표 알약, 해·달 토글, Pretendard, 묶음 오른쪽 끝 접기 화살표, 예산 확정·완료 한 글자 원. 색 토큰 값은 바꾸지 않는다(새 색 없음).

## 사용자 시나리오

1. 홈을 열면 각 기능 줄에서 "매물 3개", "지출 예정 1,240만원" 같은 숫자가 기능 이름보다 먼저 눈에 들어온다.
2. 계산 결과에서 매매가·LTV 금액·대출 가능액을 훑을 때 왼쪽 회색 라벨과 오른쪽 굵은 금액이 갈라져, 금액 열만 세로로 읽어 내려갈 수 있다. 답(필요한 자기자금)은 화면에서 가장 크다.
3. 매물 카드를 펼치면 수치 줄이 문장처럼 이어지지 않고 "라벨 · 금액" 표로 읽힌다.
4. 예산 목록에서 묶음 이름(도배·주방)이 머리글로, 그 오른쪽 합계는 줄 금액 열의 일부로 읽힌다.
5. 어느 시트를 열어도 제목·칸 라벨·칸 안 값의 층이 같다.
6. 다크 모드, 360px 폰, 글자 크기 3단계 어디서도 위 구분이 유지되고 깨지지 않는다.

## 진단: 지금 코드에서 구분이 약한 곳

기본 글자 크기는 `smaller`다(`DEFAULT_TEXT_SIZE`). 아래 px은 이 기본 크기에서 계산한 값이다(`--fs-body` 13 · `--fs-small` 11 · `--fs-tiny` 11 · `--fs-base` 14 · `--fs-section` 16 · `--fs-figure` 17 · `--fs-answer` 24 · `--fs-title` 20).

### 공통(토큰)

- **G1 글자 크기가 실제로 9단계, 그중 여럿이 1px 차이.** 토큰 8개에 더해 `calc(var(--fs-body) ± 1px)` 12곳, `calc(var(--fs-figure) + 2px)` 1곳이 있어 화면에 11·12·13·14·16·17·19·20·24px이 섞인다. 12/13/14px처럼 1px 차이는 위계로 읽히지 않고 "어긋남"으로 읽힌다.
- **G2 `--fs-small`과 `--fs-tiny`가 기본 크기에서 같다(11/11, 더 작게 10/10).** 배지·내역·초과 건수(`tiny` 8곳)와 보조 줄(`small`)의 구분이 이미 없다.
- **G3 값에 크기를 안 정한 곳은 `--fs-base`(14)를 물려받아 라벨(`--fs-body` 13)과 1px 차이·같은 굵기다.** `ResultRow` 기본 줄의 값, 실거래가 줄의 단지 이름·금액(`TradeResults .rowTitle`·`.rowAmount`).
- **G4 구역 제목 굵기가 600/700 섞여 있다.** 계산 결과 조건(`ResultCard .condition` 600)·추가 비용 제목(600)·시트 제목(600)·매물 이름(600) vs 예산 묶음 제목(700)·홈 카드 제목(700).
- **G5 카드 안쪽 여백(기본 16px·크게 20px)을 `calc(var(--space-4) + var(--space-1))`로 25개 파일 39곳에서 각자 계산한다.** 머리글 아래 첫 면까지 간격도 화면마다 다르다(계산·매물 머리글 `margin-bottom: --space-1` + 페이지 gap, 홈·예산은 gap만).
- **G6 가로 라벨/값 쌍(`dt`/`dd`) 모양이 5곳에 따로 정의돼 있고 서로 다르다**(`SummaryBar .figure`, `ListingCard .figure`, `SharedListingRow .figure`, `PlanSummary .detail`, `ResultCard .row`). 계산 하단 요약 줄만 "라벨 muted + 값 크게 700"이 제대로 돼 있다.

### 홈

- **H1 카드 제목과 내 현황 숫자가 같은 크기·굵기·색.** `HubCard .title` = `--fs-figure` 700 잉크(17px, 대출 계산 카드는 +2px로 19px), `HubSummaryPair` 숫자 = `--fs-figure` 700 잉크(17px). "매물 모으기"와 "3개"가 같은 무게라 제목 줄이 두 개처럼 보인다.
- H2 현황 라벨(`HubSummaryPair .label`)과 소개 문구(`HubCard .description`)가 같은 `--fs-body` muted — 둘 다 보조라 괜찮다. 숫자만 올라서면 된다.

### 계산

- **C1 결과 카드 기본 줄: 라벨 13px 400 muted, 값 14px 400 잉크.** 매매가·LTV 금액·대출 가능액 값이 라벨처럼 보인다(굵기 차이 없음).
- **C2 추가 비용 제목(`--fs-section` 600)과 합계(`--fs-section` 700)가 같은 크기**, 결과 카드 조건 제목(16px 600)과 강조 줄 값(17px 700)이 1px 차이.
- **C3 입력칸 라벨이 잉크 12px 600**(`AmountInput`·`ChoiceGroup`·`SaveSheet`·`TradesSheet`·`ExtraCosts .groupTitle` 모두 `calc(--fs-body − 1px)`). 칸 안 금액(18px 600 잉크)과 같은 색이라 라벨과 입력값의 층이 약하다.
- C4 하단 요약 줄(라벨 muted 13 + 값 17px 700, 예상 한도 코발트)은 이미 맞다. **이 모양을 가로 쌍의 기준으로 삼는다.**

### 매물

- **L1 펼친 카드 수치(`ListingCard .figure`): 라벨·값이 같은 13px, 값 400.** 매매가·대출·LTV가 문장처럼 이어 읽힌다. 공유 화면 `SharedListingRow .figure`도 같다.
- **L2 예산 줄(`BudgetBar`) 라벨이 잉크 13px**("예산")이라 금액(16px 700)과 같은 색 — 라벨이 muted가 아니다.
- L3 간단히 보기 줄(`CompactListingSummary`): 이름 14px 500, 금액 14px 600 — 크기 같고 굵기 한 단계 차이뿐.
- L4 자기자금(답, `--fs-answer`) 라벨이 잉크 600이라 카드 이름(16px 600)과 같은 무게로 두 번째 제목처럼 보인다.

### 예산

- **B1 묶음 제목(`.groupTitle`)과 확정 합계(`.groupTotal`)가 같은 `--fs-section` 700 잉크.** 11-01에 사용자가 "제목을 크게"를 골랐을 때 합계도 함께 커졌다. 제목과 금액이 한 덩어리로 읽힌다.
- B2 요약 상세(`PlanSummary .detail`): 라벨·값이 같은 13px, 값 400(지출 예정만 600).
- B3 요약 머리 숫자(라벨 11px 600 muted + 숫자 24px 700 코발트)는 이미 맞다. **세로 쌍의 기준.**
- B4 줄 본문(13px 500)과 금액(14px 600)은 크기 1px 차이 — 금액 토큰으로 정리하면 된다.

### 시트

- S1 시트 제목 16px 600, 카드 제목들과 굵기가 다르다(G4).
- S2 시트 칸 라벨이 잉크 12px 600(C3과 같음, `SheetForm .label`).
- S3 실거래가 시트 줄 이름·금액이 같은 14px(G3), 금액만 700.

## 참고한 사례

- **Apple HIG Typography(텍스트 스타일)**: Large Title·Title 1~3·Headline·Body·Callout·Subheadline·Footnote·Caption처럼 **이름 붙은 고정 단계**만 쓰고 그 사이 1px 조정은 하지 않는다. 사용자 글자 크기(Dynamic Type)는 단계 전체를 함께 키운다. → 역할 이름 7단계로 묶고, 글자 크기 설정 3단계가 단계 전체를 같이 바꾼다(지금 구조 유지). https://developer.apple.com/design/human-interface-guidelines/typography
- **Apple 주식·지갑 앱**: 작은 회색 라벨 + 큰 굵은 숫자(세로 쌍), 목록은 이름 왼쪽·숫자 오른쪽 tabular. → 세로 쌍(P2)·목록 줄(P4).
- **토스 TDS**: `Text`·`Paragraph`의 `typography`가 t1~t7·st1~st13 같은 **이름 토큰**만 받는다(화면이 px을 직접 쓰지 않음). 단계별 px 표는 공개 문서에서 확인하지 못했다(지어내지 않음). → 컴포넌트 CSS에 `font-size: Npx`·`calc(--fs ± px)` 금지. https://tossmini-docs.toss.im/tds-mobile/components/paragraph/
- **토스·뱅크샐러드 자산·거래 목록(앱 화면 관찰, 공개 문서 없음)**: 항목 이름은 보통 굵기, 금액은 오른쪽 굵게, 날짜·분류는 작은 회색 둘째 줄. 금액을 라벨보다 크게 두는 것이 기본. → 가로 쌍(P1)·목록 줄(P4).
- **Material 3 type scale**: display·headline·title·body·label처럼 **쓰임새 이름**으로 단계를 정한다. → 새 토큰은 역할 이름(`--fs-value`), 기존 이름은 유지.
- **design-taste-frontend(이 컴퓨터 스킬)**: 제목 위 작은 라벨(eyebrow)·대문자 자간 라벨 금지, 숫자는 tabular. → 세로 쌍의 라벨은 "제목 위 장식"이 아니라 숫자의 이름이라 해당하지 않는다. 대문자 자간 라벨은 만들지 않는다.

## 화면

### 타입 스케일(제품 기본값 · 사용자 확인 전, U1)

역할 7단계. 이름은 지금 토큰을 살리고 `--fs-value` 하나만 더한다. 굵기는 4개(400·500·600·700)만, 예외는 확정된 탭 라벨 800.

**인접 단계 간격 규칙**: 라벨 → 값(`--fs-body` → `--fs-value`), 구역 제목 → 수치(`--fs-section` → `--fs-figure`), 구역 제목 → 제목 줄 합계(`--fs-section` → `--fs-body`), 수치 → 화면 제목(`--fs-figure` → `--fs-title`)은 3개 글자 크기 설정 모두에서 **3px 이상** 차이. 나머지(`--fs-small` → `--fs-body` 2px)는 굵기·색이 함께 갈린다.

| 역할      | 토큰                 | 기본(`smaller`) 지금 → 제안 | 크게(`:root`) | 더 작게 | 굵기·모양                    | 쓰는 곳                                                     |
| --------- | -------------------- | --------------------------- | ------------- | ------- | ---------------------------- | ----------------------------------------------------------- |
| 화면 제목 | `--fs-title`         | 20 → **22**                 | 24 → 26       | 18 → 19 | 700, -0.02em                 | 화면 h1(홈·계산·매물·예산 계획 이름)                        |
| 답        | `--fs-answer`        | 24 → **26**                 | 30            | 21 → 22 | 700, tabular, -0.02em, lh1.2 | 화면마다 하나: 계산 자기자금, 예산 남은 예산, 매물 자기자금 |
| 수치      | `--fs-figure`        | 17 → **19**                 | 20 → 22       | 15 → 17 | 700, tabular, -0.01em        | 카드의 주요 숫자: 계산 요약 줄·강조 줄, 홈 내 현황 숫자     |
| 구역 제목 | `--fs-section`       | 16 (그대로)                 | 18            | 14      | **700**                      | 카드·묶음·시트 제목, 매물 이름                              |
| 값        | **`--fs-value`(새)** | (body+1 = 14) → **16**      | 18            | 15      | 600, tabular                 | 가로 쌍의 값, 목록 줄 금액                                  |
| 본문      | `--fs-body`          | 13 (그대로)                 | 15            | 12      | 400(목록 줄 이름 500)        | 문장, 가로 쌍의 라벨, 목록 줄 이름, 제목 줄 합계(700)       |
| 라벨·보조 | `--fs-small`         | 11 (그대로)                 | 12            | 10      | 400 / 라벨 600, muted        | 칸 라벨, 세로 쌍 라벨, 기준일·내역·배지·일정                |
| (없앰)    | `--fs-tiny`          | 11                          | 12            | 10      | —                            | 쓰던 8곳은 `--fs-small`로(값이 같아 보이는 변화 없음)       |

- 바뀐 것: 화면 제목 +2, 답 +2, 수치 +2, 값(새) 16. **본문·구역 제목·라벨·보조는 그대로**라서 360px에서 줄바꿈이 늘 위험은 화면 제목(22)과 값(16)·수치(19) 자리로 좁혀진다.
- `calc(var(--fs-*) ± Npx)`와 `font-size: Npx`는 컴포넌트 CSS에 두지 않는다. `calc(--fs-body − 1px)`(칸 라벨)는 `--fs-small`, `calc(--fs-body + 1px)`(목록 금액)는 `--fs-value`, 이름은 `--fs-body`, `calc(--fs-figure + 2px)`(대출 계산 카드 제목)는 U2에 따른다.
- `--fs-input`(16, iOS 확대 방지)과 `--fs-base`는 그대로. 값에 크기를 안 정해 `--fs-base`를 물려받던 곳(G3)은 역할 토큰을 명시한다.
- 줄바꿈: 가로 쌍의 값은 `white-space: nowrap`(금액은 `keep-all`)이고, 공간이 모자라면 **라벨이 줄바꿈**한다. 라벨 박스와 값 박스는 겹치지 않는다.

### 공통 패턴

규칙 주석은 `src/index.css` 한 곳에 둔다(ADR-040: 토큰 + 주석, 공통 모듈·컴포넌트 없음).

- **P1 가로 쌍**(라벨 왼쪽·값 오른쪽, `dt`/`dd`): 라벨 `--fs-body` 400 muted, 값 `--fs-value` 600 잉크 tabular 오른쪽 정렬, 기준선 맞춤. 라벨→값 3px 이상. 강조 줄 값은 `--fs-figure` 700. 기준 = 지금 계산 하단 요약 줄. 적용: 계산 결과 카드 기본·강조 줄, 하단 요약 줄, 매물 펼친 카드 수치, 공유 매물 줄, 예산 요약 상세, 매물 화면 예산 줄(`BudgetBar` 라벨 → muted). 자기자금 내역(`ListingCard .breakdown`)은 하위 내역이라 라벨·값 모두 `--fs-small` muted 그대로.
- **P2 세로 쌍**(라벨 위·숫자 아래): 라벨 `--fs-small` 600 muted, 숫자 `--fs-figure` 또는 `--fs-answer` 700 tabular, 사이 2px. 기준 = 지금 예산 요약 머리. 적용: 예산 요약 머리, 홈 내 현황, 계산·매물의 답 줄(라벨은 U5).
- **P3 제목 + 같은 줄 합계**: 제목 `--fs-section` 700 잉크, 합계 `--fs-body` 700 잉크 tabular, 기준선 맞춤. 합계는 제목보다 3px 작다(U3). 적용: 예산 묶음 제목 줄, 계산 추가 비용 제목 줄.
- **P4 목록 줄**: 이름 `--fs-body` 500 잉크(둘째 줄 `--fs-small` muted), 금액 `--fs-value` 오른쪽 tabular(3px 큰 크기), "미정"은 같은 자리 muted. 금액 굵기: 예산 줄 600, 실거래가 줄·매물 간단히 보기 700(지금처럼). 한 줄 말줄임 줄(매물 간단히 보기)은 이름만 말줄임, 금액은 줄지 않는다.

### 반복 사용 불편 점검

- 360px·글자 크기 3단계에서 답 금액("8억 1,875만원")이 숫자 중간에서 끊기지 않고(지금 `keep-all` 규칙 유지), 머리글 제목과 버튼이 한 줄을 지킨다.
- 새로 값 토큰을 받는 자리마다 `tabular-nums`를 함께 둬서, 목록을 내려 볼 때 금액 자릿수가 세로로 맞는다.
- 다크 모드에서 muted 라벨이 늘어나므로 muted가 놓이는 면(바탕·카드·채운 칸·옅은 코발트 확정 줄·회색 완료 줄) 모두에서 4.5:1을 다시 잰다.
- 큰 글자에서 라벨("필요한 자기자금", "지출 예정")이 길면 라벨이 줄바꿈하고 값은 한 줄로 남는다. 겹침 없음.

- A1: "수치"는 금액·비율·개수, "타이틀"은 화면 제목·카드/묶음/시트 제목·라벨을 뜻한다. 요청의 핵심은 둘이 같은 크기·굵기·색으로 붙어 보이는 곳(H1·B1·C1·L1)을 없애는 것이다.
- A2: 기준 화면은 기본 글자 크기(`smaller`)다. 크게·더 작게는 표의 값을 따른다.
- A3: 본문 크기(`--fs-body`)·구역 제목·라벨·보조 크기는 바꾸지 않는다. 기본을 한 단계 작은 크기로 둔 것은 한 화면에 더 많이 보이게 하려는 것으로 읽는다. 그래서 위 단계 사이를 벌리는 일은 값·수치·답·화면 제목을 올려서 한다.
- A4: 색 토큰은 바꾸지 않으므로 대비는 "새로 muted가 놓이는 면"만 다시 재면 된다. 지금 index.css 주석의 최저값(5.6:1)이 이미 4.5:1을 넘는다.
- A5: 테스트는 역할·이름으로 찾으므로 CSS만 바꾸면 테스트 수정이 거의 없다(ui-refresh AC-4와 같은 기준). fe는 이 가정을 확인하지 못했다고 적었으니 태스크 1-1에서 `git grep`으로 클래스 선택자 사용을 먼저 본다.

## 결정 필요

- **D1 공통 패턴(P1~P6)을 코드로 어떻게 공유할까 — 결정됨: A (ADR-040).** 토큰 + 규칙 주석만 두고 각 `*.module.css`가 규칙대로 쓴다. 어긋남은 AC-1 grep과 AC-2~5 화면 확인으로 잡는다. 같은 CSS 묶음이 세 곳 이상 복붙되거나 토큰만으로 일관성이 또 무너지면 B로 올린다.

## 사용자 확인 필요

제품 기본값(화면 취향)이다. 답이 오기 전에는 **굵은 글씨 제안값**으로 진행한다. 되돌리기 쉽다(토큰·CSS 몇 줄).

- **U1 글자 크기 단계**: 위 표의 숫자(기본 크기에서 화면 제목 20→**22**, 답 24→**26**, 수치 17→**19**, 새 값 토큰 **16**, 본문 13·구역 제목 16·라벨 11 그대로, `--fs-tiny` 없앰). 라벨→값·제목→수치는 3px 이상 벌린다.
  - 대안: 화면 제목은 20 그대로(360px 줄바꿈 위험을 줄임, 수치 19와의 차가 1px로 좁아짐).
- **U2 홈 카드 제목**: **제목을 구역 제목 크기(16px 700)로 낮추고 내 현황 숫자(19px 700)가 카드에서 가장 크게.** 대출 계산 카드도 같은 제목 크기, "가장 큰 카드"는 지금처럼 위아래 여백으로만 구분.
  - 대안: 제목 크기는 그대로 두고 숫자를 `--fs-answer`로 키운다(카드가 높아짐).
- **U3 예산 묶음 합계**: **제목(16px 700)은 그대로 크게, 합계는 3px 작은 13px 700**(제목 줄 오른쪽 끝, 줄 금액 열과 같은 x). 11-01 "제목을 크게" 선택은 그대로 지킨다. 줄 금액(16px 600)보다 합계 글자가 작아 보일 수 있다.
  - 대안: 합계도 제목과 같은 16px 700으로 두고 색만 muted(크기 차 없이 색으로 구분).
- **U4 칸 라벨 색**: **입력칸·고르는 칸 위 라벨을 잉크 12px 600 → 흐린 글자(11px 600 muted)**. 칸 안 금액이 더 앞에 선다(토스 입력칸 관례). ui-refresh 규칙 3("라벨 14px 600")의 색이 바뀐다.
- **U5 답 라벨**: **계산 "필요한 자기자금"·매물 자기자금 라벨을 잉크 600 → 흐린 11px 600**(숫자만 잉크로 가장 크게). 계산 답 줄의 위아래 잉크 선 두 줄은 그대로.
  - 대안: 답 라벨만 잉크 유지(합계 줄 제목처럼).
