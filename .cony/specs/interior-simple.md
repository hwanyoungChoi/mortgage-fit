## 목표

인테리어를 **공정(구분)별로 업체 견적을 줄줄이 적고, 하겠다고 정한 줄에만 [확정]을 켜면 그 합이 지출 예정액**이 되게 한다. 시작일·상태·지급·공간 같은 관리 항목 없이 엑셀 표 한 장처럼 쓰고, 그 표를 그대로 CSV·인쇄(PDF)로 뽑는다. 이미 저장된 계획은 로그인 여부와 상관없이 하나도 잃지 않는다.

## 사용자 시나리오

1. (줄 쌓기) [우리 집] → 계획 → [줄 추가] → 구분 "도배" · 업체 "육문수" · 세부내용 "실크 전체" · 견적 180 → 저장. "도배" 묶음 끝의 [+ 도배에 줄 추가]로 "동네도배 · 합지 · 150"을 붙인다. 구분은 칩 없이 직접 치되, 이 계획의 기존 구분이 입력창 제안으로 뜬다.
2. (확정) 줄 오른쪽 [확정] 체크를 누르면 바로 저장되고, 요약의 **지출 예정**·**남은 예산**이 바뀐다. 한 구분에 여러 줄을 확정할 수 있다(욕실: 하루바스 철거·방수 (1) ✓, 하루바스 타일 덧방 (2) ✓).
3. (고치기·지우기) 줄을 누르면 줄 시트(구분·업체·세부내용·견적·비고·확정·[삭제]).
4. (뽑기) 보기 [목록 | 표] → [표] → 구분·업체·세부내용·견적(원)·확정(원)·비고 + 맨 아래 "계" → [CSV 내려받기] 또는 [인쇄·PDF].
5. (홈) 홈 허브 [우리 집] 카드에 "우리 집 · 지출 예정 800만원".
6. (옛 계획) 어제 옛 화면에서 공간·여러 견적·지급·날짜까지 적어 둔 계획을 열면, 견적 하나하나가 줄로 보이고 확정했던 견적에 체크가 있다. 숨은 값(지급·날짜·상태·연락처·공간·항목 예산)은 화면에 없지만 저장소에는 그대로 남는다.
7. (함께·이전) 남편 휴대폰에서 확정한 줄이 아내 화면에 30초 안에 보인다. 로그아웃 상태에서 만든 계획은 로그인하면 지금처럼 계정으로 옮겨진다. 매물 카드 [인테리어 계획]과 "추가 비용 인테리어 n줄 가져오기"도 그대로 된다.

## 참고한 사례

- **스프레드시트 체크박스 + 합계(구글 시트·엑셀 관례)**: 한 줄 = 한 견적, 체크 열을 두고 체크된 줄만 `SUMIF`로 더한다. → 확정은 **줄마다 독립된 불리언**이고 지출 예정 = 확정 줄 금액 합. 합계·남은 예산은 저장하지 않고 계산한다(ADR-007).
- **Smartsheet 견적 비교 템플릿(Bid Comparison)**: 견적마다 lowest·accepted·rejected·incomplete 표시를 달고, 견적 합계를 예산과 비교한다. → 견적별 "확정(accepted)" 표시를 그대로 가져오고, 상태 4종 같은 추가 분류는 사용자가 뺐으므로 넣지 않는다. https://www.smartsheet.com/content/construction-bid-templates-and-forms
- **국내 인테리어 견적서·비교 양식**: 공정별로 줄을 나눠 품명·금액을 적고 맨 아래 합계를 둔다. 비교할 때는 총액보다 공정별로, 철거·전기 포함 여부와 자재 등급 같은 조건을 비고에 적는다(검색 요약으로 확인, 개별 양식 원문은 보지 않음). → "구분(공정) · 업체 · 세부내용 · 금액 · 비고 + 계" 모양, 세부내용 = 업체가 견적한 범위, 비고 = 포함·제외 조건 메모. https://k-calc.com/tool/estimate/interior · https://glasswallet.com/calculate/interior-cost/estimate-checklist
- **House Project Budget(iOS, 이전 스펙)**: 비교 견적이 여러 개여도 합계에는 확정 견적만 쓴다. → 표 "계"에는 **확정 합만** 쓰고, 비교 견적을 다 더한 "견적 합계"는 뜻이 없어 넣지 않는다(U6).
- **HTML `<datalist>`(입력 제안)**: 새 라이브러리 없이 "이 계획의 기존 구분"을 제안해 철자 차이("도배"/"도배 공사")로 묶음이 갈라지는 것을 줄인다.
- **우리 코드 패턴**: ADR-029 C(플랜 행 + 항목 행 JSON, 공용 검증 `validateInteriorPlan.ts`가 알려진 키만 복사), ADR-030(표 보기·CSV·인쇄 부품), ADR-027(옛 번들이 모르는 필드는 쓰기 때 지워진다는 교훈).

## 데이터 모델 (D1 A — 저장 형식 무변경)

저장 형식은 **한 글자도 바꾸지 않는다.** `src/lib/types/interiorPlan.ts`의 `InteriorPlan`·`InteriorItem`(`InteriorProcessSource` 타입 삭제 외), `validateInteriorPlan.ts`, 로컬 키 `loan-calculator/interior-plans`·`loan-calculator/interior-plan-imports`, `migrations/`, `server/` 모두 그대로다. `src/lib/constants/interiorPlan.ts`는 **삭제만** 한다(`+` 줄 0, `INTERIOR_ITEM_STATUSES`와 모든 `*_MAX_*` 값 불변. 이 파일은 `validateInteriorPlan.ts`가 import해 서버 번들·worker 타입 검사의 전이 의존이다). 새 화면은 그 위의 **읽기·쓰기 매핑**만 바꾼다.

### 줄 ↔ 저장 값 매핑

| 화면(줄) | 저장 값                                  | 비고                                                                   |
| -------- | ---------------------------------------- | ---------------------------------------------------------------------- |
| 구분     | `item.trade` (1~30자)                    | trim한 문자열이 정확히 같은 줄끼리 한 묶음(대소문자 구분, 정규화 없음) |
| 업체     | `quote.vendor` (1~30자)                  |                                                                        |
| 세부내용 | `quote.memo` (≤200자)                    | 이전 스펙 A12와 같은 자리                                              |
| 견적     | `quote.amount` (만원 정수 1~999,999,999) | 화면은 만원, 표·CSV·인쇄는 원(× 10,000)                                |
| 확정     | `item.confirmedQuoteId === quote.id`     |                                                                        |
| 비고     | `item.memo` (≤500자)                     | 이전 스펙 A12와 같은 자리                                              |

- **줄 = (항목, 견적) 한 쌍.** 새 화면이 만드는 항목은 언제나 견적 1개다: `{ spaceId: plan.spaces[0].id, trade, quotes: [{ id, vendor, amount, memo? }], confirmedQuoteId?, status: "planned", memo? }`. 이 값은 지금 검증을 그대로 통과하므로 옛 번들·서버·로그인 이전이 모두 그대로 읽는다.
- **옛 항목(견적 n개)** 은 견적마다 한 줄로 펼친다(견적 배열 순서). 항목 메모(비고)는 그 항목의 모든 줄에 보인다. 견적 0개 항목은 업체·견적이 빈 한 줄이다(U9).
- **줄 찾기·key**: 줄은 인덱스가 아니라 `item.id` + `quote.id`로 찾고 React key는 `item.id:quote.id`다. 쓰기 직전 최신 캐시에서 그 견적이 없으면(다른 기기가 지움) 쓰지 않고 이유 한 줄을 보인다.
- **묶음 순서·줄 순서**: 항목 목록 순서(로컬 배열 순서 = 서버 `ORDER BY created_at, id`)대로 펼친 줄에서, 묶음은 **그 구분의 가장 이른 줄 순**, 묶음 안은 그 순서 그대로(U5). 줄을 지우면 묶음 순서가 바뀔 수 있다(도배A·욕실B·도배C에서 A를 지우면 [욕실: B][도배: C]). 묶음 제목은 그 묶음 첫 줄의 표기.
- **숨은 값**: `spaceId`·`budget`·`payments`·`status`·`startDate`·`endDate`·`quote.contact`는 새 화면이 보이지 않는다(견적 0개 항목의 `budget`만 비고에 읽기 전용으로, U9). 쓸 때는 **열어 둔 항목의 값을 그대로 돌려보낸다**(PUT은 항목 전체 교체라, 빠뜨리면 그 값이 지워진다). 확정을 켜고 꺼도 `status`는 바꾸지 않는다(A4). 업체 이름을 바꿔도 `quote.contact`는 남는다(A11).
- **합성 비고는 저장하지 않는다**: 견적 0개 줄의 "예산 n만원"은 표시용이다. 줄 시트의 비고 칸 초기값은 `item.memo`뿐이고, 저장 입력의 `memo`에 합성 문구가 들어가지 않는다.
- 계산(저장하지 않음): 지출 예정 = Σ(확정 줄 견적) · 남은 예산 = 총 예산 − 지출 예정(총 예산 없으면 없음, 음수면 "예산 초과"). 정확히 0이면 "남은 예산 0만원"(초과 아님).

### 쓰기 규칙 (순수 함수, `src/lib/utils/`)

모든 쓰기 입력은 `const { id, createdAt, updatedAt, ...input } = item`에서 시작해 **바꾼 칸만 덮은** 값이다. 비운 선택 칸(세부내용·비고·확정)은 빈 문자열이 아니라 **키 삭제**다.

| 동작      | 대상                            | 저장 쓰기 (바꾸는 키)                                                                                                                            |
| --------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 줄 추가   | —                               | `addItem(위 새 항목)`                                                                                                                            |
| 줄 수정   | 견적 1개 항목                   | `updateItem`: `trade`·`memo`·`quotes[0]`의 `vendor`·`amount`·`memo`·`confirmedQuoteId`                                                           |
| 줄 수정   | 견적 0개 항목(업체·견적을 채움) | `updateItem`: 숨은 값 유지 + `quotes: [새 견적]`(새 줄 확정은 꺼진 채)                                                                           |
| 줄 수정   | 견적 n≥2 항목                   | `updateItem` **제자리**(D2 a): 구분·비고는 형제 줄과 공유                                                                                        |
| 확정 토글 | 어떤 줄이든                     | `updateItem`: `confirmedQuoteId`만(켜기 = 그 견적 id, 끄기 = 키 삭제). n≥2 항목에서 다른 견적이 확정돼 있으면 확정이 이 견적으로 옮겨 간다(D2 a) |
| 줄 삭제   | 견적 0~1개 항목                 | `removeItem`(그 항목의 숨은 지급·날짜도 같이 지워진다, A6)                                                                                       |
| 줄 삭제   | 견적 n≥2 항목                   | `updateItem`: `quotes`에서 그 견적만 뺀다. 확정 견적이었으면 `confirmedQuoteId` 키도 뺀다(검증이 `quotes` 밖의 확정 id를 거부한다)               |

- 함수 시그니처는 줄이 항목 전체를 들고 있게 `(item: InteriorItem, quoteId: string | null, 변경)` 꼴로 확정한다(1-1).
- 상한: 줄 추가는 **항목 100개**(`INTERIOR_ITEM_MAX_COUNT`, 줄 수가 아님) 그대로. 옛 항목의 견적이 펼쳐져 100줄을 넘게 보일 수는 있다.

## 화면

- **플랜 화면(`#/home/{planId}`)**: 머리글 [가리기] [⋯(이름·총 예산·매물 연결 해제·삭제, 지금 그대로)] → 요약 → 보기 `[목록 | 표]` → (목록) [줄 추가] + 공정별 목록 / (표) 지금의 표 보기.
  - 요약: 크게 **남은 예산**(없으면 [총 예산 입력], 음수면 "예산 초과 n만원")·**지출 예정**, 작게 총 예산(U6).

## 지울 테스트 감사 규칙 (1-2c 작업, 1-4 검증)

지우는 단위는 "주제가 코드에서 사라진 `it`/`describe` 하나"이고, 같은 변경에서 그 코드와 함께 지운다. 주제가 사라지지 않았으면 지우지 않고 새 줄 모델로 **옮긴다**.

1. `git diff --name-status <mb> HEAD -- '*.test.*' 'src/test/*'`의 삭제(D)는 모두 위 "화면에서 빼는 것"과 일대일 대응하는 표로 적는다(대응 못 하는 D는 실패). 지워도 되는 것: `interiorItemDraft.test.ts`·`sortInteriorTrades.test.ts` 전체, `interiorSpaces.test.ts`의 `createDefaultSpaces`·`countSpaceItems` 블록(태스크 2), `summarizeInteriorPlan.test.ts`의 todos·upcoming·paid·expected·groups·overBudget·`now` 블록, `MortgageHome.test.tsx`의 공간·공정 순서·항목 시트·할 일·옛 요약 블록, 표·CSV 테스트의 공간 라벨·견적 합계·대표 견적·옛 비고 조각.
2. 수정(M) 파일마다 제거된 `expect(`·`it(` 줄(`git diff -U0 | grep '^-.*\(expect(\|it(\|it\.each\)'`)을 **R**(주제 삭제) / **T**(새 테스트로 이동, 새 테스트 이름 병기) / **X**(설명 없음)로 분류한다. **X 0개여야 통과.**
3. 다음 키워드가 든 제거 줄은 반드시 T: `toBe(seed`, `setItem`, `removeItem`, `clear`, `writes()`, `household`, `가구`, `import`, `corrupt`, `unavailable`, `INTERIOR_ITEM_MAX_COUNT`, `999999999`, `1000000000`, `privacy`, `가리기`, `conflict`. 상한·경계·가리기·충돌·401·404·표 병합·계 테스트는 T다. "견적 중 항목을 [확정]하면 상태가 확정으로 바뀐다"는 의도된 **반전**(A4)이라 지우지 않고 "planned/quoting/inProgress 모두 확정을 켜고 꺼도 `status` 그대로"로 바꿔 쓰고 감사 기록에 "반전"으로 남긴다. `?view=trade|space` 테스트는 "목록으로 간다"로 바꿔 쓴다.
4. 기대값 완화 금지(`toBe`→`toContain`/`toMatch`, `toEqual`→`objectContaining`, `toHaveLength(n)`→`toBeGreaterThan`, 호출 횟수 0 단언 삭제, `.skip`·`.todo`·`.only`, `waitFor` 시간 늘리기, 스냅샷 갱신): `git diff <mb> HEAD | grep -E '^\+.*(\.skip|\.todo|\.only|objectContaining|toContain\()'` 결과를 설명한다.
5. 파일별 `it` 수 전후 표: 줄어든 만큼이 R·반전과 맞아야 한다.
6. 죽은 코드: 지울 이름 전부(`ItemGroups`·`ItemRow`·`QuoteRow`·`PaymentRow`·`SpacesSheet`·`ProcessSheet`·`PlanTodos`·`ListView`·`INTERIOR_TRADES`·`INTERIOR_PROCESS_*`·`InteriorProcessSource`·`INTERIOR_ITEM_STATUS_LABELS`·`INTERIOR_PAYMENT_LABEL_PRESETS`·`countSpaceItems`·`INTERIOR_NO_SPACE_LABEL`·`createDefaultSpaces`·`interiorItemDraft`·`sortInteriorTrades`·`paymentTodos`·`quoteTodos`·`upcomingTotal`)을 `rg`로 `src server`에서 찾아 0건, `INTERIOR_ITEM_STATUSES`·길이/개수 상한은 남아 있음을 확인(lint는 미사용 export를 못 잡는다).

## 가정

- A1: 미리보기의 180·370은 만원이다. 입력·저장은 만원 정수(ADR-002), 표·CSV·인쇄만 원.
- A2: 이 기능은 2026-10-26~27에 배포돼 옛 계획이 많지 않고 옛 다견적 항목은 드물다(그래서 D2 a로 끝낸다). 그래도 AC-0은 예외 없이 지킨다(보이는 것이 줄어도 저장 값은 보존). 배포된 옛 계획 수는 확인하지 못했다(원격 DB 미조회).
- A3: 구분 묶음은 trim한 문자열이 정확히 같을 때만 같다("도배"와 "도배 공사"는 다른 묶음, 대소문자 구분, 유니코드 정규화 없음).
- A4: 확정을 켜고 꺼도 `status`는 바꾸지 않는다(새 화면이 읽지 않는 값이라 그대로 두는 것이 가장 단순하고 안전). 옛 "확정하면 상태가 확정" 테스트는 의도된 반전이다. 새 줄은 `status: "planned"`, `spaceId: plan.spaces[0].id`(옛 계획은 "전체", 새 계획은 유일한 공간).
- A5: 열려 있던 옛 번들 탭·다른 기기의 옛 번들은 새로고침 전까지 옛 화면을 보이고, 새 줄을 공간 `spaces[0]`("전체")의 항목으로 보인다. 새 화면이 쓰는 값은 전부 옛 검증을 통과하고 모르는 키가 없으므로, 옛 번들이 다시 써도 지워지는 값이 없다. 옛 번들이 그 사이 고친 숨은 값(예: 지급함 체크)은 **목록이 최신일 때** 새 화면의 다음 PUT이 그대로 돌려보내 보존된다(폴링 주기만큼 낡을 수 있고, 항목 단위 마지막 저장 우선은 지금과 같음).
- A6: 줄 = 항목이라, 견적 0~1개 항목의 줄을 지우면 그 항목의 숨은 지급·날짜도 함께 지워진다. 사용자가 그 줄을 지우겠다고 한 것이므로 보존 대상이 아니지만, 지급이 있으면 확인 문구가 "지급 n건도 함께 지워집니다"를 알린다. 견적 n≥2 항목은 그 견적만 빠지고 나머지는 남는다.
- A7: 같은 항목 동시 편집 경고(ADR-029 조건 8)는 줄 시트에 그대로 쓴다. 확정 토글도 렌더된 항목의 `updatedAt`으로 쓰므로 낡았으면 `conflict`가 나고(숨은 값을 낡은 채로 덮지 않기 위해), 시트용 문구가 아닌 별도 한 줄로 알린다. 그 밖의 경우 항목 단위 마지막 저장 우선(지금 규칙)이다.
- A8: 가리기 때 구분·업체는 보이고 견적·확정 금액·세부내용·비고는 가린다(지금 표 규칙과 같음).
- A9: 이전 스펙 U14(세부내용·비고 조합)와 U15(줄 순서)는 이 스펙의 매핑·U5로 바뀌고, U16(병합)·U17(CSV 첫 줄)·U18(가리기)·U19(진입)·U20(파일 이름·금액 표기)·U21(안내)은 그대로다.
- A10: 가리기 중에는 기존 줄의 시트가 열리지 않는다(옛 화면이 연락처·메모를 플랜 화면에 두지 않은 규칙과 같다). 체크 토글과 [줄 추가]는 허용하고 요약만 가린다.
- A11: 업체 이름을 바꿔도 숨은 `quote.contact`는 그대로 남아 새 업체 이름에 옛 연락처가 붙을 수 있다. 보존 규칙(AC-0)을 우선해 유지하고 위험으로만 기록한다.

## 결정됨 (ADR-032)

- **D1 데이터 모델: A 저장 형식 그대로, 줄 = (항목, 견적) 매핑.** 서버·마이그레이션·검증 변경 0, 새 키 없음이라 옛 번들·서버의 "알려진 키만 복사"에 지워질 값이 없다. 남는 위험은 숨은 값을 PUT에서 빠뜨리는 클라이언트 버그뿐이고 AC-0(c)·(d)로 막는다. B(새 필드)는 옛 번들 탭이 모든 계획의 새 값을 한꺼번에 지우고 테스트로 못 막아 반대, C(새 저장 모델)는 같은 데이터에 두 번째 저장 경로와 가구 범위 재구현이라 반대(pm·be·fe·qa 모두 A 찬성).
- **D2 옛 여러 견적 항목의 줄: a 제자리 수정.** 쓰기 1번이라 부분 실패 상태가 없다. 같은 항목 안 확정은 하나이고 구분·비고는 형제 줄과 공유하며, 안내(시트 하단 · 확정 풀림 한 줄)로 알린다. b(떼어 내기)는 이번 범위에서 뺀다 — 셋 모두 "옛 다견적 항목이 실제로 있을 때만"을 조건으로 걸었고 이중 계산·100개 상한·줄 점프가 새 복잡도다(c 일괄 쪼개기는 AC-0(d)를 깨서 반대). 뒤집을 조건과 b 착수 조건은 "다음 단계 후보".
- 구현 필수 조건 1~9(ADR-032 "결정")는 위 데이터 모델·화면·AC-0~AC-6·감사 규칙·태스크에 반영했다. 남은 결정 필요 항목: 없음.
