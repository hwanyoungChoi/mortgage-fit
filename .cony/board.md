## 백로그

- **옛 여러 견적 항목 떼어 내기(D2 b, 구 태스크 2)**: 옛 다견적 항목에서 "다른 견적 확정이 풀린다"는 불편이 실제로 나오면 재검토(ADR-032 뒤집을 조건). 착수 시 필수 조건:
- be 4: 떼어 내는 경우는 "확정을 켜는데 같은 항목의 다른 견적이 확정돼 있을 때"와 "구분·비고를 바꿀 때"뿐, 확정을 끄는 쓰기와 다른 확정이 없는 항목에서 켜는 쓰기는 제자리 PUT 1번.
- be 5: 항목 100개면 `addItem`이 `limit`/400이라 쓰기 0건 + 상한 문구, 제자리 수정으로의 폴백 만들지 않음(AC: 항목 100개 + 견적 2개 항목에서 쪼개기 → 쓰기 0건·문구·값 불변).
- be 6: 새 항목 = `{ spaceId, trade, quotes: [그 견적(contact 포함, 같은 id)], confirmedQuoteId?, status, memo }`, `budget`·`payments`·`startDate`·`endDate`는 원래 항목에 남기고 복사하지 않음, 원래 항목은 그 견적과 (확정이었으면) `confirmedQuoteId`만 뺀다. 줄 key `item.id:quote.id`.
- be 7: 만들기 성공 뒤 빼기가 실패하면(네트워크·404·500·로컬 `unavailable`) 목록을 무효화해 두 줄을 보이고 안내, 404면 새 항목만 남는 것이 정상, 만들기 응답이 모호하면 재시도하지 말고 무효화 후 현재 목록 표시. 실패 주입 테스트는 서버(500)·로컬(setItem 예외) 둘 다.
- be 8: 빼기 PUT의 입력은 만들기 직전이 아니라 **빼기 직전** 캐시/저장소의 항목으로 만든다(서버는 항목 단위 마지막 저장 우선).
- qa 이중 계산: 확정된 견적을 떼어 낼 때 만들기 성공 + 빼기 실패면 같은 견적이 두 항목에서 둘 다 확정돼 지출 예정에 두 번 들어간다. 새 항목은 확정을 끈 채 만들고 빼기 뒤에 켜는 3단계로 하거나, 같은 `quote.id`가 두 항목에 있으면 한 번만 세는 규칙을 정하고, 확정/미확정 견적 각각의 실패 주입 테스트로 고정.
- qa 위치 이동: 떼어 낸 줄은 새 `createdAt`이라 묶음 끝으로 간다(L에서 욕실나라 체크 뒤 순서: 하루바스 철거·방수, 하루바스 타일 덧방, 욕실나라) — 기대 순서를 AC로. 부분 실패 테스트에 중복 key 경고(`console.error`) 없음 단언.
- 기대 결과(L에서 욕실나라 체크): ① `addItem({ spaceId: s1, trade: "욕실", quotes: [q2], confirmedQuoteId: q2, status: "inProgress", memo: "폐기물 포함" })` ② X에서 q2만 뺀 `updateItem` → 하루바스·욕실나라 둘 다 체크, 지출 예정 770.
- 줄 순서 바꾸기(묶음·줄 끌어 옮기기)
- 구분 이름 한 번에 바꾸기(묶음 제목 편집 → 그 묶음 항목 전부 PUT)
- 구분별 확정 소계를 묶음 제목 옆에
- 업체·견적 없이 "견적 받기 전" 줄 허용(U3 대안)
- 부가세 포함/별도 열, 공급가액·부가세·합계 줄(국내 견적서 관례)
- 숨은 값(지급·날짜·상태·공간) 정리 도구 또는 옛 항목 보기 전용 시트
- 옛 계획의 공간 이름을 세부내용 앞 `[욕실1]`로 보이기(U10 대안)
- 계획당 100개 상한 올리기(상수만; 서버 크기 상한 `interior-planner` "크기 상한" 재계산 필요, "엑셀 한 장" 기대보다 낮다는 피드백이 오면)
- xlsx 직접 생성
