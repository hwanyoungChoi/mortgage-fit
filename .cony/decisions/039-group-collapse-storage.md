# ADR-039 묶음 접힘 상태: localStorage 키 하나에 `{계획 id: 접힌 구분[]}`

- 상태: 채택
- 맥락: 사용자가 인테리어 목록을 카테고리(묶음) 단위로 접고 펴고, 상태를 로컬스토리지에 기억하길 요청했다. 저장 키를 어떻게 나눌지와 묶음 식별자를 정해야 한다.
- 선택지: A 키 하나에 `{계획 id: 접힌 구분[]}` / B 계획마다 키 하나 / C 계획 구분 없이 구분 이름 목록 하나
- 의견: fe(찬성 — 기능당 키 하나 관례, 묶음 식별자가 이미 구분 글자) / qa(찬성 — 원문 한 줄 비교로 판정 끝, planId `__proto__` 대비 Object.create(null) 또는 Map)
- 검토 원문: [fe](../reviews/20261107-1615-fe-spec-interior-group-collapse.md) · [qa](../reviews/20261107-1615-qa-spec-interior-group-collapse.md)
- 결정: A. 서버·계획 저장 형식은 바꾸지 않는다. 읽기 실패·손상·개인 모드면 모두 펼침.
- 이유: 가장 단순하고 기존 관례와 같다. 기기별 보기 상태라 함께 쓰기 동기화가 필요 없다.
- 조건(스펙 반영): 순서 저장 중에도 제목은 접기 버튼(끌기만 끔), 끌기 중 DragOverlay는 접힌 묶음의 줄을 빼고 그림, 빈 구분 이름의 버튼 이름 처리, AC-7 판정 방법(전 키 스냅샷 비교·API 호출 0건), 스페이스 들기→놓기 뒤 `aria-expanded` 불변 테스트, setItem만 실패·손상 원문 위 쓰기, 포인터 꾹 누르기 뒤 click 억제·VoiceOver 낭독은 사람 확인.
- 뒤집을 조건: 두 기기에서 접힘 상태를 맞추고 싶다는 요청이 오면 계획 필드(서버)로 옮기는 것을 다시 본다.
- 남는 위험: 함께 쓰는 상대가 구분 이름을 바꾸면 그 묶음은 펼침으로 돌아간다(오류 없음).
