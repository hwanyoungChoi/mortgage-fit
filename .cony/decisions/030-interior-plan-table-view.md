# ADR-030 인테리어 계획 표 보기를 세 번째 보기(`?view=table`)로 둔다

- 상태: 채택
- 맥락: 사용자 요청(2026-10-27) "계획을 스샷처럼 하나의 표로 뽑아 CSV·인쇄로 내보내기"(태스크 5). 표를 어디에 보일지가 라우팅·인쇄 레이아웃·테스트를 좌우한다(스펙 D6).
- 선택지: A 시트(`HomeSheet`에 표 추가) / B 플랜 화면의 세 번째 보기 `#/home/{planId}?view=table` / C 전용 라우트 `#/home/{planId}/table`
- 의견: pm(B 추천, 기존 `view` 주소 규칙에 값 하나라 새로고침·뒤로 가기 유지가 그대로) / fe(B 찬성, `parseRoute`·`paths`·보기 전환 `replace`가 이미 있음. A는 `Sheet`가 480px·90dvh 내부 스크롤·히스토리 밖이라 인쇄·뒤로 가기에 약하고, C는 분기만 늘고 이득 없음) / qa(B 찬성, 테스트 용이성 B ≈ C > A, 인쇄는 "인쇄 영역만 보이게" 조건)
- 검토 원문: [fe](../reviews/20261027-1359-fe-spec-interior-plan-export.md) · [qa](../reviews/20261027-1359-qa-spec-interior-plan-export.md)
- 결정: B
- 이유: 이미 있는 `view` 쿼리 규칙(AC-3)을 값 하나로 넓히는 것이 가장 단순하고(CLAUDE.md 작업 원칙), 새로고침·뒤로 가기·주소 공유가 그대로 되며, `parseRoute` 왕복 테스트 한 줄로 고정할 수 있다. 표는 같은 데이터의 다른 보기라 공간별·공종별과 같은 자리에 두는 것이 화면 모델과도 맞다. 조건: `HomeView`에 `"table"`을 더하면서 `ItemGroups`·`ItemRow`는 `Exclude<HomeView, "table">`로 좁히고, `parseRoute`는 허용 값 목록(`isOneOf`)으로 바꾼다. 인쇄는 표 머리와 표만 남도록 하고 리드가 인쇄 미리보기로 확인한다. 데스크톱에서도 `.page`가 480px라 표는 가로 스크롤 영역 안에 둔다.
- 뒤집을 조건: 표가 가로로 넓어져(열 추가·열 고르기) 480px 칸 안 가로 스크롤이 쓰기 어렵다는 피드백이 오면 C(전용 넓은 화면)를 다시 본다. 진입 위치(보기 전환 세 번째 칸)는 제품 기본값 U19로 사용자 확인 전이다.
