# ADR-036 업체 미정(`quote.vendor` 선택) + 우리 집 줄 순서(플랜 필드 `lineOrder`)

- 상태: 채택
- 맥락: 사용자가 "업체도 비우고 입력 시 미정으로", "집 목록처럼 눌러서 드래그로 위치 바꾸기"를 요청했다. 업체는 공용 검증 `parseQuote`가 필수로 보므로 선택으로 바꾸면 옛 번들 탭이 계획 전체를 손상으로 본다(ADR-033 조건 2: 필수 → 선택 완화는 2단계 배포). 줄 순서는 지금 "구분의 가장 이른 줄 → 항목 순 → 견적 순"으로 계산만 하고 저장할 곳이 없다. 스펙: [interior-vendor-tbd-line-order](../specs/interior-vendor-tbd-line-order.md)
- 선택지:
  - D1 줄 순서 저장: A 플랜 필드 `lineOrder?: string[]`(줄 key 배열, ADR-026 매물 순서와 같은 모양) / B 항목·견적마다 정렬 키(fractional index) / C 저장 목록처럼 별도 저장소
  - D2 PATCH 본문 한도: A PATCH만 128KB / B `WRITE_MAX_BYTES` 전체 상향 / C `lineOrder` 상한을 약 230개로
- 의견: pm(D1 A, D2 A) / be(D1 A, D2 A 조건부: POST는 `lineOrder` 버림, 상수는 PATCH만, `parseLineOrder` 시그니처, 출력이 항상 검증 통과) / fe(조건부: `lineOrderAfterMove` 입력 규칙, pending 순서는 PlanScreen·계획 id에 묶음, 안내 슬롯 하나, 공용화는 상수·센서까지, 업체 칸 판별 유니온) / qa(조건부: 예시 보강, 변경 전 골든 먼저, 병합 경계, 빈 배열 정책 통일, 옛 파서 재현 절차 고정, 버그 목록 ⑧~⑱, 2단계 게이트 증거 필수)
- 검토 원문: [be](../reviews/20261028-0843-be-spec-interior-vendor-tbd-line-order.md) · [fe](../reviews/20261028-0843-fe-spec-interior-vendor-tbd-line-order.md) · [qa](../reviews/20261028-0843-qa-spec-interior-vendor-tbd-line-order.md)
- 결정: D1 A, D2 A. 반대 없음, 반론 라운드 생략. 조건:
  1. **2단계 배포(ADR-033 조건 2)**: 1단계 = 업체 없는 견적 읽기·표시·보존(서버도 받음) + 줄 끌어 옮기기. 2단계 = 시트에서 업체 비우기. 2단계 머지 게이트는 **사용자 확인만**(두 분 기기의 우리 집 탭 새로고침·계정으로 옮기지 않은 로컬 전용 계획 여부), 시간 대기 없음(메모리 규칙). 롤백 하한은 1단계 커밋으로 올라간다. qa 기록에 게이트 증거(1단계 SHA·`merge-base --is-ancestor`, 배포 시각·운영 스모크, 사용자 확인 원문, 2단계 diff에서 공용 검증·타입·`server/**` 0줄)가 없으면 2단계 판정은 실패(qa C10).
  2. **빈 배열 하나의 정책(be 3, qa C4)**: `parseLineOrder`는 비어 있지 않은 유효 배열만 돌려준다. 저장된 값·공용 필드의 `[]`는 키 없음으로 읽고, PATCH `lineOrder: []`는 로컬·서버 모두 `null`과 같이 키 삭제로 받는다(400 경로를 만들지 않는다). key 정규식은 `isInteriorId`의 패턴에서 만들고 새 리터럴로 복제하지 않는다.
  3. **서버(be 1·2)**: 계획 POST는 `lineOrder`를 버린다(항목 id를 서버가 만들어 맞지 않는다). `/import`는 보존. `PLAN_PATCH_MAX_BYTES = 128 * 1024`를 `WRITE_MAX_BYTES` 옆에 두고 PATCH 경로에만 쓴다(근거 주석). 하네스: 64자 id 두 개 key 500개 PATCH 200·왕복 일치, 128KB 경계 200/+1바이트 413(행 무변경), 항목 PUT·계획 POST는 16KB+1에서 계속 413, POST의 `lineOrder`는 `SELECT data`에 없음.
  4. **순서 계산 한 곳(fe 1, be 4, qa C3)**: 읽기는 `buildInteriorPlanRows` 한 곳(목록·표·CSV·인쇄가 같은 결과). 쓰기 값은 순수 함수 `lineOrderAfterMove` — 옮긴 묶음은 "든 순간 스냅샷의 이동 결과 중 아직 있는 key + 새 key", 다른 묶음은 놓는 순간의 현재 값. 든 줄이 지워졌거나 구분이 바뀌었으면·제자리·다른 묶음이면 null(쓰지 않음). 출력은 항상 `parseLineOrder` 통과(중복 없음, ≤ 현재 줄 수 ≤ 500, 지워진 key 걷힘)를 500줄 계획과 옛 `item.id:` key 섞인 입력으로 테스트. 병합 경계는 qa C3 목록 전부를 단위 테스트로.
  5. **화면 상태(fe 2·3·4)**: 놓는 순간 고정 해제와 pending 설정을 같은 이벤트에서, pending 해제는 저장이 끝난 뒤. pending 순서는 `PlanScreen`에 두고 계획 id와 묶는다(표 보기도 같은 줄을 쓴다). 실패 문구는 `Record<사유, string | null>`(401은 세션 만료 안내로). 순서 실패와 확정 저장 결과는 같은 안내 줄 하나를 쓴다.
  6. **공용화 범위(fe 5)**: `LONG_PRESS`·`KEYBOARD_CODES`·`SCREEN_READER_INSTRUCTIONS`와 센서 설정만 전역으로 올린다. 알림 문장은 각자 둔다(줄은 "묶음 안 k번째"라 구조가 다르다). 옮긴 뒤 저장 목록 끌기를 리드가 브라우저에서 다시 확인한다.
  7. **테스트 분담(qa C1·R1, fe 6)**: jsdom에서 rect 스텁으로 키보드 끌기가 되는지 먼저 짧게 확인하고, 되면 키보드·알림·Esc를 자동 테스트로, 안 되면 순수 함수 + `onDragEnd` 접착 테스트로 줄이고 꾹 누르기·키보드 이동·놓은 뒤 시트 안 열림·DragOverlay는 리드 브라우저 확인으로 넘긴다(어느 쪽인지 qa 기록에 적는다). 표시 AC는 grep이 아니라 표면별 렌더 출력으로(qa C6). AC-0 "변경 전과 같다"는 f5ad2b0 결과를 리터럴 골든으로 먼저 커밋(qa C2). 읽기만으로 쓰기 0은 원문 `===`와 `setItem`·`removeItem` 0회(qa C7). 옛 파서 재현은 qa C8 절차. 일부러 넣는 버그는 스펙 목록 + qa C9 ⑧~⑱.
  8. **업체 미정 표시(fe 7)**: "업체 있음/없음"은 `vendorOf` 한 함수. 표 모델 업체 칸은 판별 유니온(이름 / 미정 / 견적 없음)이고 표·인쇄·CSV가 같은 변환 함수를 쓴다(업체 이름 "미정"·"tbd"와 충돌하지 않게 센티넬 문자열 금지). 목록의 흐린 "업체 미정"은 새 클래스(`tbdAmount` 재사용 금지), 대비 4.5:1.
  9. **2단계 `editedQuote`(pm, fe 4)**: `vendor`도 `amount`처럼 구조 분해로 빼고 값이 있을 때만 넣는다(지우면 키 삭제).
- 이유: 업체 미정은 요청을 채우는 표현이 선택 필드뿐이고, 옛 탭 손상을 피하는 검증된 방법이 ADR-033의 2단계다. 줄 순서는 사용자 두 명·계획당 최대 500줄이라 부모에 key 배열(ADR-026, Trello/Jira 같은 정렬 키보다 단순)이 요구를 다 채우는 가장 단순한 형태이고, 공용 검증이 모르는 키를 버려 옛 번들에 손상 위험이 없다. 128KB는 최악 66KB에 여유를 두는 가장 좁은 변경이다.
- 뒤집을 조건: 동시 끌기로 순서가 되돌아가는 일이 잦으면 per-row 정렬 키(D1 B). 줄이 500을 넘는 요구가 생기면 한도 재검토.
- 롤백: 1단계는 revert로 되돌려도 저장된 `lineOrder`는 옛 번들이 버릴 뿐이다. 2단계 뒤에는 1단계 커밋보다 앞으로 되돌리지 않는다(업체 없는 견적을 손상으로 읽는다).
- 검토 권장: 없음.
- 제품 기본값(사용자 확인 전): 스펙 U1~U7.
