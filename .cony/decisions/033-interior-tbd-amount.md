# ADR-033 견적 금액 "미정": `quote.amount` 선택 필드 + 2단계 배포(expand–contract)

- 상태: 채택
- 맥락: 사용자가 [우리 집] 줄의 견적 금액을 "미정"으로 둘 수 있기를 원한다(업체는 알고 금액만 모르는 줄). 지금 공용 검증 `parseQuote`는 금액을 필수로 요구하고, 로컬 `parseInteriorPlans`는 플랜 하나라도 어긋나면 전체를 손상으로 본다(ADR-001). 금액 없는 견적이 저장되면 배포 전부터 열려 있던 옛 번들 탭이 그 기기 계획 전체를 손상으로 보고, 손상 화면 [계획 초기화]를 누르면 로컬 계획이 지워진다(qa가 옛 파서로 재현: `amount` 키 없음 → corrupt). ADR-032 갱신. 스펙: [interior-tbd-amount](../specs/interior-tbd-amount.md)
- 선택지: A `quote.amount` 선택 필드로 바꾸고 한 번에 배포 / B 저장 형식 그대로 미정 = 견적 0개 줄 / C A와 같은 형식, 2단계 배포(1단계 읽기·표시·보존 → 2단계 금액 비우기 화면)
- 의견: pm(C) / be(C 조건부: 24시간 대신 사용자 확인 게이트, 롤백 하한 구체화) / fe(C 조건부: 시트 `String(amount)`·`editedQuote` 함정, 기준 브랜치) / qa(C 조건부: 표에서 빈 줄과 미정 구분, 1단계 시트 AC, 옛 파서 재현 기록)
- 검토 원문: [be](../reviews/20261027-1905-be-spec-interior-tbd-amount.md) · [fe](../reviews/20261027-1905-fe-spec-interior-tbd-amount.md) · [qa](../reviews/20261027-1905-qa-spec-interior-tbd-amount.md)
- 결정: C. 반대가 없어 반론 라운드 생략. A는 배포 순간 열린 옛 탭 전부를 손실 경로에 노출하고, B는 업체를 담을 곳이 없어 요구를 못 채운다. 조건:
  1. **2단계 게이트(be 1, fe 9)**: 1단계 배포 커밋·시각을 log에 남기고, **사용자 두 사람이 각 기기의 우리 집 탭을 닫거나 새로고침했다고 확인한 뒤** 2단계를 머지한다. 확인이 늦으면 최소 24시간 대기. 2단계 전에 "로그인 없이 만들어 아직 계정으로 옮기지 않은 로컬 계획이 있는지" 묻는다. main에 필수 체크가 없어 기계가 막지 못하는 절차 게이트임을 명시.
  2. **롤백 하한(be 2·10)**: 2단계에 문제가 있으면 revert PR로 1단계 상태에 맞추고 1단계 이전 번들로 되돌리지 않는다(1단계 이전 번들은 미정 데이터를 손상으로 읽는다). 필수 → 선택 완화는 앞으로도 2단계 배포.
  3. **검증 범위(be 근거 1·조건 6·7, qa C5)**: 바뀌는 검증은 `parseQuote` 한 곳(키 없음·undefined만 미정, `null`·0·문자열·소수·상한 초과는 거부, 1·999,999,999 통과). 서버·마이그레이션 코드 diff 0, 기존 `server/**` 테스트 수정 0, 새 D1 하네스 파일로 `/import`·항목 POST·PUT·계획 POST 200과 GET `toStrictEqual` 왕복, 거부 값 400. `validateInteriorPlan.test.ts` 373행 반전·`it` 이름을 지급 전용으로, 결과에 `amount` 키 없음(`Object.hasOwn`) 단언.
  4. **계산 한 곳(be R5, fe 7, qa C6)**: 지출 예정·미정 건수(확정한 미정 줄만)·남은 예산은 `interiorPlanRows` 한 곳에서, 요약·표·CSV·허브가 그 결과를 쓴다. 표 모델은 "견적 없음 / 미정 / 금액"을 구분한다. 문구는 n을 받는 함수 하나. `?? 0`·`!`로 타입 오류를 덮지 않는다. 미정 줄 어디에도 "0만원"·"0원"이 나오지 않는다.
  5. **시트(fe 1·3, be 4, qa C2)**: 1단계에서 미정 줄을 열면 견적 칸은 `""`(`interiorLineDraft.ts`의 `String(quote.amount)` 수정, `String(`·템플릿 사용처 grep), 금액 없이 저장하면 지금처럼 필수 오류. 2단계 `editedQuote`는 `amount`를 구조 분해로 빼고 값이 있을 때만 넣는다(비우기 → 키 삭제). 2단계에서 견적 없는 줄 확정 안내는 "업체를 적으세요"로.
  6. **가리기(fe 4·5, qa C4)**: 가리기 중에는 미정 조각을 구분자까지 통째로 빼고, `innerHTML`·`aria-label`에 "미정"이 없음을 허브·요약·표·목록 네 곳과 목록/표 두 보기에서 확인. 요약 문구 "금액 미정 n건 제외"는 요약 영역 안에서 한 번, 남은 예산·지출 예정 아래 전체 폭 한 줄.
  7. **기준 브랜치(fe 8)**: 구현은 세부내용·업체 자리 바꾸기와 홈 로그인이 머지된 main 위에서 시작.
  8. **옛 파서 기록(qa)**: 1단계 완료 때 1단계 직전 커밋 파서로 P⁺ → corrupt, 2단계 때 1단계 커밋 파서로 → ok를 한 번씩 기록(영구 사본 테스트는 두지 않음). 태스크 2 diff에서 `validateInteriorPlan.ts`·`types/interiorPlan.ts`·`server/**` 0줄을 PR에 첨부. 두 탭 수동 확인은 같은 origin·같은 포트에서.
  9. **미리보기(be 8)**: PR 미리보기가 운영 D1을 쓰는지 확인되기 전에는 실계정으로 미리보기에 쓰지 않는다.
- 이유: 사용자 목표를 채우는 표현은 A·C뿐이고, C가 A보다 더 드는 비용은 배포 한 번과 확인뿐이며 1단계에서 읽기 경로를 운영에서 먼저 확인할 수 있다.
- 뒤집을 조건: 번들 버전 확인 장치(qa D3)가 생기면 다음 형식 완화는 한 번 배포로.
- 롤백: 조건 2.
- 검토 권장: 없음.
- 제품 기본값(사용자 확인 전): 스펙 U1~U6. U1(빈칸 = 미정)은 금액을 깜빡하면 조용히 미정이 된다는 점을 확인 때 알린다(fe R3).
