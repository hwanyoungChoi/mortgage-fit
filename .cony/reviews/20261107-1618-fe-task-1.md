## 화면에서 확인할 항목 (qa)

진입: 로그아웃 또는 로그인 상태에서 [인테리어] → 묶음 2개 이상인 계획(`#/home/{planId}`) → [목록].

1. 360px 폭: 펼친 제목 줄(구분 + ∨ 꺾쇠 + 오른쪽 확정 합계)과 접힌 제목 줄(구분 + "· n줄" + > 꺾쇠 + 확정 합계)이 한 줄인지. 긴 구분 이름일 때 줄바꿈 모양. 접힌 카드 위·아래 여백이 비슷한지(`.collapsedGroup`).
2. 짧게 누르기: 제목 칸 아무 데나 탭/클릭 → 접힘(줄과 [+ 구분에 줄 추가] 사라짐) → 다시 → 펼침.
3. 꾹 누르기(250ms, 실기기·터치 에뮬레이션): 제목을 꾹 눌러 묶음을 옮기고 놓은 뒤 접힘/펼침이 바뀌지 않는지(dnd-kit click 억제, 자동 테스트로 못 봄). 접힌 묶음을 꾹 눌러 옮길 때 뜬 면에 제목 줄만 보이고 빈 자리 크기와 맞는지.
4. 키보드: Tab으로 제목 → 엔터 = 접기/펴기, 스페이스 = 들기 → 화살표 → 스페이스 = 놓기 후 접힘 그대로. 묶음 1개 계획에서는 스페이스·엔터 둘 다 접기.
5. 순서 저장 중: 묶음/줄을 옮겨 놓은 직후(로그인 상태면 네트워크 느리게) 저장이 끝나기 전에 제목을 눌러 접힘이 되는지.
6. 새로고침 후 유지: 두 묶음을 접고 새로고침 → 그대로 접힘. [표] → [목록] 왕복, 다른 계획 갔다 오기 뒤에도 그대로. 다른 계획의 같은 이름 묶음은 펼침.
7. 사파리 개인 모드(또는 저장소 차단): 접고 펴기 동작, 새로고침하면 모두 펼침.
8. VoiceOver: 제목에서 "접힘/펼침"(`aria-expanded`)이 읽히는지(`aria-roledescription`이 역할 낭독을 덮을 수 있음).

## 사실 / 추론

- 사실: user-event v14에서 스페이스 keydown을 dnd-kit 키보드 센서가 `preventDefault`해 keyup 때 click이 나지 않음(테스트 통과로 확인, 들기·놓기 모두).
- 추론: 실제 브라우저도 같은 동작으로 봄(`CompactListingRow`가 같은 구조로 이미 쓰임). Firefox 등에서 keydown을 막아도 keyup 스페이스 click이 나는지는 확인 못 함 → 화면 확인 4번.
- 사실: 접근 가능한 이름 계산(dom-accessibility-api)이 span 안 앞 공백을 버려 처음엔 "도배· 2줄"이 됐다. 공백을 span 밖 텍스트로 옮겨 "도배 · 2줄"로 고침.
- 결정 메모(스펙 범위 안): `useSortable`의 `disabled: !canMoveGroup`은 기존대로 둠(draggable·droppable 둘 다 끔 — 들 수 있는 묶음이 없을 때라 놓을 자리도 필요 없음). 버튼은 끌기 속성만 조건부로 빠지고 click은 항상 동작.
- 빈 구분 묶음은 `aria-label="구분 없음"`이라 접혀도 "n줄"은 이름에 안 붙음(접힘은 `aria-expanded`로 전달). 스펙 허용 범위.
