## 결함

### D1. 정규 경로가 아닌 로그인 결과 주소는 `?login=`이 주소에 남아 다시 열면 안내가 또 뜬다 — 담당 fe, 심각도 낮음

- 재현: `#/?login=failed&a=1`(또는 `#/?login=failed&login=cancelled`, `#/?a=1&login=failed`)로 연다. 안내는 한 번 보이지만 주소가 `#/`가 아니라 `#/?login=failed`에 남는다. 같은 주소로 다시 열면(새로고침) 안내가 또 뜬다. 정규 주소 `#/?login=failed`는 정상이다(`#/`, 다시 열면 0개).

  ```
  REPRO #/?login=failed&a=1 → 주소 #/?login=failed → 다시 열면 안내 1개
  REPRO #/?login=failed&login=cancelled → 주소 #/?login=failed → 다시 열면 안내 1개
  REPRO #/?a=1&login=failed → 주소 #/?login=failed → 다시 열면 안내 1개
  REPRO #/?login=failed → 주소 #/ → 다시 열면 안내 0개
  ```

- 원인 추정: 자식 effect가 부모 effect보다 먼저 돈다. `src/containers/Mortgage/Hub/MortgageHub.tsx:106-108`(`window.location.replace(PATHS.hub)`)이 먼저 `#/`로 바꾼다. 그다음 부모 `src/hooks/useHashRoute.ts:22-24`(23행 replace)의 정규화 effect가 옛 해시 기준(`hash !== canonicalPath`)으로 `#/?login=failed`로 다시 replace한다. 그 뒤 route의 `login` 값이 같아 홈 effect(`[login]`)가 다시 돌지 않는다.
- 영향: 서버는 정규 주소만 보내므로(`homeUrl`) 실제 로그인 복귀에서는 생기지 않는다. 손으로 만든 주소나 쿼리가 붙은 공유에서만 생긴다. 스펙 AC-2의 "`#/?login=failed&a=1` → login 유지"와 "한 번 잡고 `#/`로 replace(새로고침 재표시 없음)"가 함께 성립하지 않는다.
- 확인한 고치는 방향(검증용 임시 변이 D1fix, 되돌림): `useHashRoute`가 replace 직전에 `window.location.hash === hash`일 때만 정규화한다. 이렇게 하면 qa `it.fails` 2개만 빨개지고 나머지 2626개는 통과한다. 방법은 fe가 정한다.
- 테스트: `src/containers/Mortgage/Hub/MortgageHub.hubAccountQa.test.tsx` "[결함 D1] …" `it.fails.each` 2개. 고치면 `it.each`로 바꾼다.
