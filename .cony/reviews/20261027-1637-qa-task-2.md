## fe 확인 요청 판정

### 1. `MortgageHub.test.tsx`에 더한 `await waitFor(() => expect(hub.querySelector('[aria-busy="true"]')).toBeNull())` — 약화 아님

- 이 줄 앞뒤 단언(링크 순서·href·이름·소개 문구 accessible description)은 그대로다(`git show 78dc3bf -- …MortgageHub.test.tsx`는 +2줄, 주석 1 + 대기 1)
- 필요성: 이 줄을 빼고 현재 코드로 돌리면 AC-5 첫 테스트가 실패한다(변이 W1). `/api/me` 응답 전에는 매물·우리 집 요약 줄이 "불러오는 중"인데, 이는 AC-7 행 4가 요구한 동작이다. 태스크 1 시점의 "첫 렌더부터 소개 문구"는 스펙이 의도해서 바꾼 동작
- 거짓 통과 여부: 요약 줄이 계속 로딩이면(W2, `aria-busy` 늘 true) 이 대기에서 실패하고, 로딩이 끝난 뒤 소개 문구가 아닌 값이 나와도(W3, 매물 0개 → error) 뒤 단언에서 실패한다. 대기는 끝 상태를 바꾸지 않고 기다리기만 한다
- 같은 파일 둘째 테스트(순번·단계 판정식)는 로딩 중에 단언한다. "불러오는 중"은 `/준비 중/`에 걸리지 않아 통과한다. 약화는 아니지만, 요약이 그려진 뒤의 판정식은 이번 `MortgageHub.summary.test.tsx`에서 따로 보지 않으므로 필요하면 후속으로 더한다(결함 아님)

### 2. 401·재조회 실패 해석 — 구현이 맞고 스펙 AC-7(c)의 401 문구를 고쳐야 한다(리드·pm 결정 사항)

- 재조회 실패(`isRefreshFailed`, 받아 둔 목록 있음): 받아 둔 값을 유지하고 오류 문구가 없다. 스펙과 맞다(테스트 "받아 둔 목록이 있는데 재조회가 500")
- 받아 둔 목록 없이 실패: error. 스펙과 맞다(행 6·7, "받아 둔 목록 없이 첫 조회가 실패")
- 401: 구현은 `useEndSession`이 `me`를 `{ user: null }`로 바꾸고 서버 목록 캐시를 지워 출처가 loggedOut이 되고, 홈은 이 기기 값을 보인다. 오류 문구는 없다. 스펙 AC-7(c) 문장 "401 만료 … 받아 둔 값을 유지"를 글자 그대로 읽으면 어긋난다. 그래도 구현이 맞다고 판정한다. 이유:
  1. 같은 스펙의 상태 규칙 "로그아웃: 이 기기 데이터"와 "저장 목록·우리 집 화면이 보이는 것과 같은 수·값"에 맞다. 두 화면도 401 뒤에는 로컬을 보인다(`useInteriorPlanSource.test.tsx` "계획 GET 401" 기존 테스트)
  2. 서버 값을 홈에만 남기면 `useEndSession`이 일부러 캐시를 지우는 이유(같은 탭에서 다음 계정이 이전 값을 보지 않게)를 홈이 우회한다. 홈만 따로 들고 있으려면 숨은 상태가 하나 더 생긴다
  3. 이 문구는 qa 검토 C5의 제안에서 왔고, 본래 뜻은 "일시 실패에 오류 문구를 띄우지 않는다"였다. 그 부분은 지켜진다
- 테스트는 구현 동작으로 고정했다: "재조회가 401 → 로그아웃 상태가 되어 이 기기 값, 오류 문구 없음, 서버 값은 남지 않음"(session-hint 제거, "저장한 매물 5개"·기기 계획 줄, "저장한 매물 2개"·"서버 계획"·"불러오지 못했습니다" 없음)
- 스펙 문구 제안: AC-7(c)와 "상태" 목록의 해당 줄을 "재조회 실패(`isRefreshFailed`)는 받아 둔 값을 유지하고 오류 문구를 쓰지 않는다. 받아 둔 값이 없으면 error. 세션 만료(401)는 로그아웃 상태가 되어 이 기기 값을 보인다(저장 목록·우리 집과 같음). 오류 문구 없음"으로
