## 1. 골든 대상 (AC-0(a))

골든은 f5ad2b0 코드로 한 번 만들었다(임시 생성 스크립트는 지웠고 커밋하지 않았다). 다시 만들지 않는다. 바뀌면 그것이 곧 데이터 회귀다.
JSON에는 undefined가 없어 "키 없음"과 "값이 undefined인 키"가 같아지므로, 값이 undefined인 자리는 `{ "$undefined": true }`로 적는다(`toGoldenJson`, 단사 변환). 그래서 `vendor: undefined`가 남는 버그도 `toStrictEqual`에서 걸린다.

## 2. AC-4 jsdom 끌기 스파이크 결과: **자동 가능**

- 헬퍼: `src/test/dndKitJsdom.ts`의 `stubRowRects()`. `HTMLElement.prototype.getBoundingClientRect`를 바꿔 문서의 `li`를 문서 순서대로 세로로 쌓고(줄 높이 60px, top 100부터, 묶음 `ul`이 여럿이어도 한 줄로 이어짐), `li` 밖 요소(`DragOverlay`)는 든 줄(`aria-pressed="true"`)의 자리를 준다. 되돌리는 함수를 돌려준다.
- 키 입력: 키보드 센서가 든 다음 틱에 keydown 리스너를 붙이므로(`setTimeout`), 키마다 `act` 안에서 `fireEvent.keyDown` 후 한 틱 흘린다(테스트 안 `press`).
- 저장 목록 `CompactListingList`에서 확인(커밋한 특성 테스트, `src/containers/Mortgage/Listings/components/CompactListingList.test.tsx`):
  - 스페이스 → 아래 화살표 → 스페이스: `onReorder` 1회 `["b","a","c"]`. 화살표 두 번 + 엔터, 위 화살표, Esc 취소(0회), 제자리 놓기(0회), 엔터는 펼치기(펼친 줄은 들지 않음), `canReorder` false, 든 동안 목록이 바뀌어도 든 순간 목록으로 놓기.
  - 알림 문장 4종, 안내 문장(`aria-describedby`), `aria-roledescription`.
  - 마우스·터치 꾹 누르기: 249ms 안 듦 / 250ms 듦, 250ms 전 6px 이동이면 안 듦 / 4px이면 듦, 꾹 눌러 둘째 줄 위에서 떼면 `onReorder` 1회, 250ms 전에 떼면 0회. 가짜 타이머(`vi.useFakeTimers`)로 돈다.
- 일부러 넣은 버그(확인 뒤 되돌림), 모두 실패함: 시작 키 Enter로(5개), `arrayMove` 인자 뒤집기(1), 제자리에서도 `onReorder`(1), `sortableKeyboardCoordinates` 빼기(4), 든 동안 목록 고정 빼기(1), 안내 문장 바꾸기(1), `LONG_PRESS` delay 200(2)/300(1)/tolerance 8(1)/3(1), 터치 delay 100(1), 마우스를 distance 제약으로(2).
- 스텁 없이 돌리면: 키보드 이동 테스트 5개 실패(rect가 전부 0이면 다음 자리를 못 찾고, 제자리 놓기도 다른 줄 위로 판정돼 `onReorder`가 불린다).
- `Element.animate`: jsdom에 없다. 그러나 이 스텁에서는 `DragOverlay`가 든 줄과 같은 자리라 dnd-kit이 첫·끝 keyframe이 같다고 보고 놓기 애니메이션을 건너뛰어, 폴리필 없이 돈다. 우리 집 화면에서 뜬 줄이 다른 자리에 그려지면 `animate is not a function`이 날 수 있다(그때 폴리필 또는 `dropAnimation={null}`).
- 묶음 2개: 임시 스파이크(커밋 안 함, 지움)에서 한 `DndContext` 안 `SortableContext` 2개(`[r1,r2]`, `[r3,r4,r5]`)로 같은 헬퍼를 써서 r2↑→r1, r3↓↓→r5, r5↑↑↑→r2, **r2↓→r3(다른 묶음의 줄이 over)** 를 확인했다. "다른 묶음 위에 놓기 → 쓰기 0"은 over가 다른 묶음 줄로 실제로 들어오므로 제품 로직(`lineOrderAfterMove` null)으로 자동 검증할 수 있다.
- 주의 1(알림): 들기 직후 같은 `act` 안에서 "제자리 위(over = 자신)" 알림 `'…' 매물을 1번째 자리로 옮겼습니다.`가 이어 나와, 알림 영역의 지금 글자만 보면 들기 알림이 안 보인다. 테스트는 `MutationObserver`의 `oldValue`로 알림 이력을 모아 `[들었습니다 → 1번째 자리로 → 2번째 자리로 → 놓았습니다]`를 단언한다. 우리 집 알림 테스트도 이력 방식을 써야 한다. 실제 스크린리더에서 들기 알림이 들리는지는 브라우저 확인 항목이다.
- 주의 2(click): `fireEvent.mouseUp`·`touchEnd`는 브라우저처럼 click을 만들지 않는다. "놓은 뒤 시트가 열리지 않는다"는 jsdom에서 판정할 수 없다.
- 주의 3(inert): jsdom은 `inert`를 이벤트 차단에 반영하지 않는다. "시트가 열린 동안 들 수 없다"는 `inert` 속성 단언까지만 자동이다.

## 3. 우리 집 줄 끌기 자동/수동 분담 (태스크 1-3·1-4)

스파이크가 되므로 ADR-036 조건 7의 "되면" 쪽이다: 키보드·알림·Esc를 자동 테스트로 둔다. 거기에 더해 마우스·터치 꾹 누르기의 시간·거리 경계도 자동으로 둔다.
"자동" 칸은 저장 목록과 묶음 2개 스파이크에서 확인한 방식에 근거한 분담이다. 우리 집 화면(아직 끌기 없음)에서 실제로 되는지는 태스크 1-4에서 확인하고, 안 되는 항목은 그때 수동으로 옮겨 기록한다.

## 자동 테스트로 검증할 수 없어 화면에서 직접 확인할 항목

- 꾹 눌러 든 뒤 놓았을 때 줄 시트·펼치기가 열리지 않는지(우리 집·저장 목록)
- iOS Safari·Android Chrome 꾹 눌러 끌기, 끄는 중 화면 끝 자동 스크롤, 360px에서 든 줄 모양, 끄는 중 텍스트 선택·확대경
- 실제 스크린리더에서 들기 알림이 들리는지(jsdom에서는 같은 틱의 over 알림에 덮인다)
- 시트가 열린 동안 목록이 실제로 들리지 않는지(inert)
