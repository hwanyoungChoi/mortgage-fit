## 근거

1. AC 대부분이 원문 문자열·aria 속성·DOM 존재로 판정 가능하다. AC-3(원문 `{"P":["도배"]}`, 펴면 P 키 삭제), AC-4(원문 5종 입력과 기대 결과)는 값이 구체적이라 단위 테스트로 바로 쓴다. 저장소가 `getSnapshot`·`subscribe`로 분리돼 순수 함수에 가깝고 테스트하기 쉬운 구조다.
2. [위험] AC-7은 판정 방법을 스펙에 적어야 한다(아래 조건 1).
3. D1 A(키 하나)는 테스트 면에서도 낫다. 원문 한 줄을 비교하면 되고, B는 키 열거가 필요하다. 찬성. 단 planId를 객체 키로 쓰므로 `__proto__`·`constructor` 같은 id는 결과 객체를 `Object.create(null)`이나 `Map`으로 만들면 막힌다. 계획 id는 서버 발급이라 위험은 낮고, 있어도 읽기 관용 쪽 한 줄이다.

## 조건

1. **AC-7 판정 방법 명시**
   - 원문 불변: 접기·펴기 전후로 `localStorage`의 모든 `loan-calculator/*` 키 스냅샷을 뜬다. 바뀐 키는 `interior-collapsed-groups` 하나뿐이어야 한다. "interior-plans 원문 불변"만 보면 다른 키 오염을 놓친다.
   - API 0건: 기존 테스트의 api 모킹(fetch 또는 apiClient 스파이)의 호출 수 0을 접기·펴기 직후 단언한다.
   - "골든 diff 0"은 표·CSV·요약 함수가 접힘 입력을 받지 않으면 구조적으로 보장된다. 시그니처 확인 한 번이면 되고 별도 테스트는 줄인다. 접은 상태에서 표 보기 텍스트 한 번 비교하면 충분하다.
2. **AC-2 스페이스 키 놓기 뒤 click**: 스페이스로 들었다 스페이스로 놓을 때 포커스가 제목 버튼에 남아 있으면, 놓는 스페이스의 keyup이 click을 만들어 접힘이 바뀔 수 있다. 가장 위험한 연결 누락이다. user-event는 keyup 스페이스에 click을 내므로 jsdom 통합 테스트로 "들기 → 놓기 후 `aria-expanded` 불변"을 잡을 수 있다. 이 하나는 꼭 쓴다. 포인터 꾹 누르기 뒤 click 억제는 합성 이벤트로 못 보므로 스펙대로 실브라우저 확인으로 둔다. 이 저장소에는 Playwright가 없다(`package.json`, `e2e/` 없음). 도입은 결정 필요이며, 없으면 "화면 확인 못 함 / 사람 확인 필요"로 적는다.
3. **AC-4 보강(각 한 줄)**
   - `getItem`은 성공하고 `setItem`만 throw하는 경우: 이 탭에서 접힘이 유지된다. 지금은 "모든 호출 throw"만 있다.
   - 손상 원문 위에 쓰기: 한 계획 값이 깨진 채 다른 계획을 접으면 깨진 계획이 버려진 채로 정상 JSON이 써진다.
   - "콘솔 오류 없음"은 `console.error` 스파이로 판정한다고 적는다.
4. **AC-5 모호함**: "다른 묶음을 하나 접으면 P 값에 도배가 없다"는 정리 시점이 쓰기 때라는 전제다. 시트 저장 직후 재조회 전에 접으면 화면 묶음이 낡은 상태일 수 있다. 저장 성공 후 렌더가 반영된 뒤 접는 순서로 시나리오를 못 박는다.
5. **AC-6 자동 펼침 연결**: 저장 성공 시점과 `onSave` 연결 누락(이벤트 미전달)은 단위 테스트로 못 잡는다. 화면 통합 테스트 하나로 "접힘 → [+] 저장 → 펼침", "저장 실패 → 접힘 유지"를 확인한다. 고친 줄 경로(구분을 접힌 묶음으로 변경)도 한 케이스 더 둔다.

## 범위 과잉·빠진 AC

- 과잉은 없다. 범위 밖 목록(모두 접기, 애니메이션, storage 이벤트)이 잘 잘려 있다.
- 빠진 AC: 묶음 1개일 때 스페이스 = 접기(A6)는 AC-1에 "1개 계획에서도 접힌다"만 있고 스페이스는 없다. 엔터만 써도 되고, 스페이스를 쓰면 AC-1에 명시한다.
- 빠진 AC(경미): 계획 간 분리는 AC-3 마지막 줄로 충분하다. 30초 재조회 유지는 저장소가 컴포넌트 밖이라 재마운트 테스트로 대체된다. 별도 테스트 불필요.
- 360px 한 줄 배치(꺾쇠·"· n줄"·합계)는 자동 테스트 대신 화면 확인 항목이다. Playwright가 없으니 사람 확인으로 넘긴다.

## 리스크

- 합성 이벤트로 못 보는 포인터 click 억제가 유일한 사각지대다. 사람 확인 한 번으로 막는다.
- 버그 되살리기(변이 확인)는 이 스펙에서 AC-7(다른 키 오염)과 AC-2(스페이스 놓기 뒤 접힘 변경) 두 곳만 한다. 나머지는 가볍게 간다.
