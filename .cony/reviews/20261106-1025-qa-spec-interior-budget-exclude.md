# interior-budget-exclude 스펙 — qa 검토

2026-11-06

## 판정: 조건부 찬성

## 근거

1. 예시 E를 직접 계산했다. 지출 예정 1.8M, 완료 3.7M, 예산 외 2.5M, 남은 4.5M(R5 반영이면 2.0M). 총 예산 7M이면 반영 시 8.0M 사용이라 초과 1,000,000, 예산 외면 남은 1,500,000. CSV 계 확정 칸 5.5M, 완료 칸 3.7M. 모두 맞고, 반영/예외를 가르는 값이다. AC-1~4·6은 판정 가능한 문장이다.
2. 저장 형식 AC-2(true/false/키 없음/null/"true"/1)와 AC-4(토글·삭제 후 키 보존, 다시 켜면 키 없음)가 데이터 손실 위험을 이미 충분히 덮는다. 테스트를 더 늘릴 필요는 없다.
3. D1 A(항목 `isOffBudget?: true`)에 찬성한다. 확정이 항목당 하나라 B보다 단순하고, C는 추측성이다. `false`를 받아 키를 빼는 규칙은 ADR-012와 같다. 되돌리기 어려운 이름이라 확정 전에 `isOffBudget`으로 고정해도 무방하다.

## 조건 (스펙 보완, 테스트 추가 아님)

- C1 미확정 + 예산 외 줄의 목록 표시가 정해져 있지 않다. 계산은 합계 제외인데 `row.isOffBudget`은 true이므로 "예산 외" 글자가 붙는지 AC-5에 한 줄로 못 박는다. 붙으면 요약에 안 잡히는 "예산 외" 줄이 생긴다.
- C2 예산 외 줄만 [완료]인 계획(A4)의 표 "계" 완료 칸이 0인지 빈칸인지, 표 머리의 "지출 완료 0원" 노출을 AC-6에 값 하나로 적는다. `doneCount`를 조건으로 쓰는 곳이라 연결이 빠지기 쉽다.
- C3 AC-3의 "금액 미정 + 확정 + 예산 외" 경계는 E에 해당 줄이 없다. 별도 fixture 한 줄로 만들고, 계 비고에서 "금액 미정 n건 제외"와 "예산 외 n원 제외"를 " · "로 잇는 순서(어느 쪽이 앞인지)도 P⁺ 기반으로 값 하나를 정한다.
- C4 AC-5의 "예산 외 글자가 화면 어디에도 없다"는 시트 안내문("...'예산 외'로 보입니다")과 겹친다. 시트가 닫힌 상태의 목록·요약 기준이라고 한정한다.
- C5 AC-2 입력 목록에 `0`, `"false"`, `[]`, `{}`를 더해 "그 밖"을 정의한다. 값 판단 순수 함수라 한 줄이면 된다.
- C6 AC-4의 "[확정] 끄기" 뒤 `status`가 planned로 풀려도 키가 남는지를 같은 케이스에서 확인한다. 이미 문장은 있고 확인할 방법만 고정하면 된다.

## 리스크

- 옛 탭이 키를 지우는 문제는 스펙이 인지하고 있고 표시 문제로만 남는다. 테스트로 막을 수 없는 항목이라 "사람 확인 필요"(배포 보고 한 줄)로 두는 것이 맞다.
- 범위 과잉은 크지 않다. 다만 AC-7의 세 출처 × 상대 기기 재조회 전부를 e2e로 만들면 비용이 크다. 계산이 한 곳이므로 출처별로는 "R5 저장 → 요약 값" 하나와, `/import` 뒤 GET 계산 동일 하나만 두면 충분하다.
- 빠진 AC는 C1·C2·C3 외에는 없다. 되돌려 켜기(시나리오 3)는 AC-4의 "다시 켜면 키 없음"과 AC-3 값으로 덮인다.
- 화면 확인(360px 줄바꿈)은 AC-8대로 Playwright로 보거나 "화면 확인 필요"로 둔다.
